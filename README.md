## 产品设计规模（可核对）

- **12 个页面 ＋ 4 个一级导航分区**（总 PRD 第三章；验收标准 A1 即「12 个页面全部可正常访问，无控制台报错」）
- **6 个运行模式**与迁移条件（总 PRD §5.1）
- **14 条 MVP 验收标准**（总 PRD §11.2，A1–A14）
- **领域实体**：总 PRD 第七章定义 **33 个**（E01–E33），数据模型拆解补充至 **50 个**（E01–E50），与 [`src/app/core/models.ts`](src/app/core/models.ts) 的 **50 个 interface** 一一对应
- **异常分级 L0–L3**、**审批分级 L1–L3**、功能 **F1–F9**
- 一条硬规则：**护栏引擎是运行模式的唯一写入方**（[模块 C §0.2](docs/prd/04-拆解-模块C-护栏引擎与电池健康.md)）——避免多入口写状态导致页面之间口径撕裂

## 原型怎么打开

直接**双击** `prototype/index.html`。实测全文件 **0 处外链**（无 `<script src>`、无外链样式表、无网络请求），所有状态在前端内存里，不需要起服务器。

- hash 路由；未完成引导时强制跳 `onboarding`；未知路由有 404 兜底
- 顶部**原型状态切换条**：5 种页面状态（正常 / 加载 / 空 / 数据源失效 / 权限不足）× 6 种运行模式 × 3 种角色 × 数据新鲜度 × 引导开关
- 键盘快捷键：`g` 后接 `t p d i h b r c s` 跳页、`?` 帮助、`Esc` 关浮层
- 覆盖的关键链路：冷启动影子期（不产生实际动作）、异常接管闭环、护栏修改与审批、季度复核向导、安装商视图

## Angular 实现现状（如实说明）

这**不是**一个完成的前端系统，而是**可运行的工程骨架 ＋ 完整数据层**：

- ✅ **数据层**：`src/app/core/models.ts`（50 个 interface）、`store.ts`（Signal 状态中枢）、3 份模拟数据（电价曲线 / 家庭画像 / 运营台账，合计约 2,500 行）
- ✅ **设计系统**：`src/app/shared/` 13 个 standalone UI 组件、4 类图表组件（chart / sparkline / gauge / bar-list）、内联 SVG 图标集、设计 token
- ⚠️ **页面**：15 条路由中**只有「今日管家」完成实现**（`src/app/features/today/`）；其余 14 条为「建设中」占位
- ⚠️ **测试**：0 个单元测试

即：**产品设计与可交互验证在 PRD 与 `prototype/index.html`；Angular 侧用于验证数据模型与组件抽象的可行性。**

## 数据与隐私
