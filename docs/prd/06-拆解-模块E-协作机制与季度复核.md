## 0 · 范围、宿主与口径
### 0.1 覆盖范围
本模块把总 PRD 第五章（运行状态机）与第八章（人机协作机制）从"立场"落成"可开发、可测试、可验收"的规格，包含四件事：运行状态机、权限分级矩阵、五个协作触点、季度复核向导。

**不属于本模块**：调度算法与收益口径（第六章）、异常分级判定标准（§4.7）、市场策略包内容（§4.10）、责任边界的法律结论（第九章）。本模块只定义"人在什么时刻、以什么方式介入，以及介入如何被记录"。
### 0.2 宿主页面与跨页职责
| 内容 | 主承载页面 | 跨页呈现 |

- 颜色仅作辅助编码，**任何状态都必须同时有文字**（§3.2）；全文不得出现 emoji。

## 1 · 运行状态机规格
### 1.1 状态定义（E29 `RunModeState`）
```
RunModeState {
  mode: 'shadow' | 'advisory' | 'auto' | 'conservative' | 'safe' | 'manual-hold'
  since: string                 // 进入时间
  reason: string | null         // 降级 / 接管原因（人话，可展示）
  resumeCondition: string | null// 恢复条件（人话，可展示）
  heldBy: string | null         // 接管人（角色 + 显示名）
  nextPlannedMode: string | null// 预计恢复的目标模式
  enteredFrom: string           // 上一模式（用于恢复路径校验）
  triggerRef: string | null     // 触发证据引用（Incident / PendingApproval / 数据源）
}
```
界面可见仅 `mode`、`since`、`reason`、`resumeCondition`；`heldBy` 只在人工接管与安全模式下显示。
### 1.2 六模式的进入与离开条件
| 模式 | 进入条件 | 离开条件 | 硬约束 |
|---|---|---|---|
| **影子期 Shadow** | 首次开通完成 T1 三问（含"以后再说"）后自动进入；撤销授权后重新开通也回到此模式 | 到期（默认 14 天，可配 14–28 天）生成小结；或用户主动提前结束 | 零调度动作；**不得自动跳到 Advisory / Auto**；到期后 30 天无动作则每 30 天温和提醒一次，上限 3 次 |
| **建议模式 Advisory** | 由 Shadow 经用户选择进入；由 Auto 经用户主动降级进入；由 Conservative 经用户选择进入 | 用户开启自动执行 → Auto；系统触发降级 → Conservative / Safe；用户停止管家 → 已退出 | 每份计划需用户确认；用户不响应时**不执行** |
| **自动模式 Auto** | 用户明确开启"帮我自动执行"（L2，必须留痕），可自 Shadow 或 Advisory 进入 | 用户降级 → Advisory；护栏触发 → Conservative；安全事件 → Safe；人工介入 → Manual Hold；用户停用 → 已退出 | 仅在已批准偏好与红线内执行；计划默认自动生效，用户在次日 00:00 前可无障碍撤销；不得因"多日未打开 App"自行扩大自主范围 |
| **保守模式 Conservative** | 四类触发之一：触碰备电预留边缘 / 需超额动用循环预算 / 电价数据源失效 / 循环预算过半；或由 Safe、Manual Hold 恢复；或市场级全局熔断 | 触发原因消除 **且** 用户明确确认恢复（L2）→ Auto；用户选择只接受建议 → Advisory；触发更高级事件 → Safe | **不得自动回到 Auto**；必须显示原因与恢复条件（人话，可点开依据）；仅执行"光伏优先 + 备电优先"，无新增套利循环 |
| **安全模式 Safe** | 停电 / 电池告警 / SOC 异常跳变 / 其他安全事件；Conservative 期间再次触发更高级事件 | 触发条件消除 + 数据源恢复 + **人工确认**（用户或售后在事故简报点"确认恢复"）→ Conservative | 停止一切优化，交回设备安全默认；**绝不直接回 Auto，绝不由 Agent 自行解除**；确认按钮只在事故简报页，不在状态条上（防误触） |
| **人工接管 Manual Hold** | 用户、安装商或沃太售后在事故简报上点"我来处理" | 接管人标记"处置完成" → Agent 生成恢复汇报 → 用户查看或 24 小时后默认进入 Conservative | Agent 完全静默（不执行、不推优化类通知、不生成新计划）；被冻结计划标记 `held`，恢复后不得自动补做 |
### 1.3 界面标识：颜色语义、文案与位置
**颜色语义（五个语义位，不得扩展）**

| 语义 | 令牌 | 示例值 | 含义 | 约束 |
|---|---|---|---|---|
| 未生效 | `mode-shadow` | 中性灰 #7A7A7A | 管家没有在动你的电池 | 属中性色阶 |
| 等你决定 | `mode-advisory` | 中性蓝 #4A5C6A | 管家在等你点头 | 属中性色阶，**不占用强调色额度** |
| 自主工作 | `mode-auto` | 强调色 #2450D8 | 管家在边界内自主执行 | 全产品仅此一个强调色 |
| 能力受限 | `mode-conservative` | 琥珀 #B26A00 | 能做的变少了 | 琥珀仅用于语义告警 |
| 已停止优化 | `mode-safe` / `mode-manual-hold` | 红 #C0392B | 管家停止动作 / 有人在处理 | 红色仅用于语义告警，不得装饰 |

实现要求：状态条使用 **12% 透明度语义底 + 1px 实线边框 + 深色正文**，不用大面积饱和色块；对比度不低于 4.5:1；`mode-safe` 与 `mode-manual-hold` 同为红色，**必须靠文案前缀与 1.5px 线宽矢量图标区分**（非 emoji）。

**各模式文案与位置（引号内为可直接使用的界面文案）**

| 模式 | 主文案 | 副文案（动态） | 位置 |
|---|---|---|---|
| Shadow | "我在学习，只看不做" | "影子期还有 9 天，X 月 X 日结束；到时候你再决定要不要交给我" | 全局头部、今日模式条、计划头、协作矩阵顶部 |
| Advisory | "我建议，你决定" | "今天有 1 个计划等你确认；你不点，我就不动" | 全局头部、今日模式条、计划头 |
| Auto | "我在按你的规则自动安排" | "今天已经安排了 2 个动作；想改随时说" | 全局头部、今日模式条、计划头 |
| Conservative | "我现在比较保守" | "原因：电价数据今天没拿到。恢复条件：数据恢复后由你确认，我再放开" | 全局头部、今日模式条、计划头、协作矩阵顶部 |
| Safe | "我已经停止自动优化" | "原因：电池温度告警。需要处理：沃太售后已收到通知。你什么也不用做" | 全局头部（不可关闭）、今日模式条、异常页 |
| Manual Hold | "有人正在处理" | "接管人：沃太售后 / 开始时间：今天 14:20。处理完我会告诉你" | 全局头部（不可关闭）、异常页 |

**位置规则**：① 全局头部状态条常驻且不可关闭（硬规则 1），字号不小于正文；② 降级与接管状态不得折叠进设置或二级菜单；③ 今日页模式条额外承载"原因 + 恢复条件"，可点击进入对应异常或模式说明；④ 协作页在权限分级矩阵顶部重复一次当前模式，并显示"这个模式下我能做什么"的一行摘要。

|---|---|---|---|---|---|
| T-01 | 无 | Shadow | 首次开通完成 T1 三问 | 是 | 引导完成页（含影子期结束日期） |
| T-02 | Shadow | Advisory | 影子期到期且用户选择"只给我建议" | 是 | 影子期小结页 + 模式变更回执 |
| T-03 | Shadow | Advisory | 用户主动提前结束影子期并选择建议模式 | 是 | 确认页 + 留痕（Actor=用户，Level=L1） |

| T-05 | Advisory | Auto | 用户开启自动执行（L2） | 是 | 确认页 + 留痕 |

| T-08 | Auto / Advisory | Conservative | 触碰备电预留边缘 | 是（L2 请示） | 推送 + 今日模式条 + 安装商后台可见 |

| T-11 | Auto / Advisory | Conservative | 循环预算过半 | 是（低优先，不推送） | 日报/周报内 + 电池页提示条 |

| T-13 | Conservative | Safe | 降级期间再次触发更高级别事件 | 是（L3 立即） | 同 T-12 |
| T-14 | Safe | Conservative | 触发条件消除且数据源恢复，**并经人工确认** | 是 | 事故简报页确认 + 恢复汇报 |
| T-15 | 任意 | Manual Hold | 人工介入处置（用户/安装商/售后点"我来处理"） | 是 | 接管通知（含接管人、时间、"我暂停了所有动作"） |
| T-16 | Manual Hold | Conservative | 接管人标记处置完成 | 是 | Agent 主动汇报："我恢复了，接下来我会这样做" |
| T-17 | Conservative | Auto | **仅在用户明确确认后**（L2） | 是 | 确认页（含恢复后首日计划预览）+ 留痕 |
| T-18 | Auto / Advisory | Conservative | 市场级全局熔断（影响 > 50 户的系统性异常） | 是 | 市场公告 + 推送 + 安装商后台；文案含原因与预计恢复 |
| T-19 | Shadow | Shadow | 到期后用户无动作 | 是（温和） | 第 31 天起每 30 天一次"要不要开始"，上限 3 次 |
| T-20 | 任意 | 已退出（终止态） | 用户一键回退出厂策略（L3-B 用户主权动作） | 是 | 知情确认页 + 生效回执 + 留痕 |
| T-21 | 已退出 | Shadow | 用户重新开启管家 | 是 | 重新开通引导（可跳过三问，沿用历史偏好版本） |
| T-22 | Conservative | Conservative | 恢复条件已满足但用户未确认 | 是（上限内） | 每日至多 1 次，连续 3 次后停止，改为日报内提示 |

**硬规则**：① 任何降级都不得静默发生，用户必须能随时知道"系统现在不在全自动状态"；② 人工接管期间 Agent 完全静默，不得与人工操作打架；③ 安全模式不自动回 Auto，必须人工确认；④ 影子期可主动跳过、不能自动跳过；⑤ 模式切换必须留痕（`category = run-mode`），原因须可由 `triggerRef` 回溯；⑥ 状态条不得被任何页面遮挡或折叠，全屏流程也保留一行摘要。
### 1.5 边缘情形
**① 终止态：已退出（管家停用）**。一键回退出厂策略后，管家不处于六种模式中的任何一种。界面标识：中性灰条 + "管家已停用，设备按出厂策略运行"，副文案"想重新开启随时可以，我还记得你的规则"。历史计划、决策日志、留痕、收益记录不受影响（§9.4）且仍可查看与导出。停用后第 7 天与第 30 天各给一次温和提示（可关闭），不得反复劝说（反面清单第 12 条）。重新开启回到 Shadow，可跳过三问并沿用上一版偏好，历史版本保留为 `vN`。

**② 全局熔断期间的局部行为**。熔断后受影响用户统一进入 Conservative 并收到说明；熔断期间用户不能单方面切回 Auto（可切 Advisory），由策略运营确认后解除。

**③ 数据源分级降级（避免"一失效就切安全模式"的过度反应）**

分级处置：单一时段预报置信度低 → 该时段按保守动作执行并在计划页声明不可靠（L1，不切模式）；电价第二信号（电网费）缺失 → 只按电价单信号执行并声明"少算了一部分"（L1，记日志）；电价主数据源全部失效 → 切 Conservative 并请示（L2）；电池状态数据失效或通信中断 → 切 Safe，**禁止用"最后已知值"驱动调度**（L3）。

## 2 · 权限分级矩阵落地规格
### 2.1 判定规则（顺序不可调换，命中即停）
| 序 | 判定问题 | 命中结果 |
|---|---|---|
| R1 | 是否触碰安全参数、并网参数、质保承诺或跨户一致性？ | **L3-X 禁止类**（产品内无入口） |
| R2 | 是否改变红线值、权重配比、预算上限或授权范围？ | **L3-A 审批类** |
| R3 | 是否是用户本人的主权动作（停用、撤回授权、撤销常设许可、一键回退）？ | **L3-B 主权类**（无需审批，须知情确认 + 留痕） |
| R4 | 该操作是否已被一份有效常设许可覆盖且落在其边界内？ | **L1**（按许可执行，事后告知） |
| R5 | 是否在已批准的偏好与红线内，且属计划内安排或计划内微调？ | **L1** |
| R6 | 是否单次超出常规安排、或触碰红线缓冲带，但未越过红线？ | **L2** |
| R7 | 是否影响多户（> 1 户）？ | **L3-A**，附加签核规则（§4.2） |
| R8 | 无法判定时 | **按更高一级处理**（升级原则），留痕标注 `downgrade-review-needed = true` |

补充两条：**用户意愿优先**——用户明确提出要求时，只要不越过安全红线，先执行再解释风险（§6.7）；执行动作按 R5 记 L1，但若该要求构成"规则"则必须走分流（第 9 章）。**不可拆分绕过**——同一意图拆成多次 L1 动作以规避 L2 的，判定为 L2 并记入"规避标记"，由策略侧复核。
### 2.2 L1 清单：Agent 自主（事后告知）
| # | 事项 | 判定要点 | 界面承载 / 留痕 |
|---|---|---|---|
| L1-01 | 当日充放电时段的执行与执行前后 30 分钟以内的时点微调 | 收益与备电影响均在阈值内 | 计划页时间线（已执行/已修正）/ 是 |
| L1-02 | 日内小幅修正 | 功率不超过额定 30%、电量变化不超过 8 个百分点、收益影响绝对值不超过 €0.50 | 计划页"日内修正记录" / 是 |
| L1-03 | 放弃低于收益门槛的套利机会，或单一数据源置信度低时该时段改用保守动作 | 属弃权清单第 1 类；不切换运行模式 | 计划页"我主动放弃的机会" / 数据可信度条 / 是 |
| L1-04 | 生成日报 / 周报 / 月度账单对照报告 | 口径固定 | 收益页、今日页 / 是（生成记录） |
| L1-05 | 画像的日常更新、置信度调整与新增"猜测"类条目 | 不构成结构性变化；猜测项必须带一键否认入口 | 家庭页画像卡 / 是 |

### 2.6 设计检验标准的度量与告警阈值
| 指标 | 定义 | 目标值 | 警戒 | 破线（判定失败） | 破线处置 |
|---|---|---|---|---|---|
| **M1 · L2 日均弹出条数** | 近 14 天每户每日新产生 L2 条数（按户平均） | ≤ 0.2（约每 5 天不超 1 条） | 0.2–0.5 | > 0.5 且连续 7 天 | 冻结该类事项的新提议，进入策略侧降频评审 |
| **M2 · 单日出现 L2 的比例** | 有 L2 的天数 ÷ 总天数 | ≤ 10% | 10%–25% | > 25%（月度口径） | 判定该事项默认值设计失败，必须改为常设许可或调整默认红线 |
| **M3 · "每天弹出"红线** | 连续 3 天每户每天都出现 L2 | 0 次 | 出现 1 次 | **出现即失败** | 立即触发产品负责人评审（对应"L2 每天弹出，产品就是失败的"） |
| **M4 · L2 超时率** | 超时未处理条数 ÷ 总条数 | ≤ 15% | 15%–30% | > 30% | 提议不痛不痒或用户不看，需重设计提议本身 |
| **M5 · L2 同意率** | 同意条数 ÷ 已处理条数 | ≥ 70% | 50%–70% | < 50% | 提议不符合用户偏好，复核画像与默认值 |
| **M6 · 未被授权的 L3 打扰** | Agent 主动发起的 L3 申请次数（安全事件除外） | **0** | — | > 0 | 流程违规，需代码级修正 |
| **M7 · 用户主动发起的 L3 频次** | 每户每季度用户主动发起次数 | ≤ 3 | 4–6 | > 6 | 说明默认红线不合理或界面暗示用户频繁调参 |
| **M8 · L1 无感率** | 用户在 L1 事项上产生操作（查看以外）的比例 | ≤ 5% | 5%–15% | > 15% | L1 自主范围定义过宽，需回收权限 |

**口径要求**：所有指标按"户"聚合，不按"打开次数"聚合；L2/L3 计数以留痕记录为准，不以界面曝光为准（关闭 App 的用户同样计入分母）。
### 2.7 常设许可（Standing Consent）
当某一类 L2 事项在 14 天内对同一户出现 3 次以上，**不允许**通过降低提示来"解决"，只允许两条路：调整默认红线，或建立常设许可。

| 项 | 规格 |
|---|---|
| 定义 | 用户一次性授权 Agent 在**指定边界内**对某一类事项自主执行，事后告知 |
| 建立入口 | L2 队列的"以后都这样"（非红线类）；季度复核向导第 5 问 |
| 必填边界 | 事项类型 / 数量上限（如每月不超过 4 次）/ 幅度上限 / 有效期 |
| 有效期与撤销 | 有效期默认到下一次季度复核（最长 1 季），到期自动失效并提示是否续期；设置页与协作页可一键撤销（L3-B），撤销即时生效 |
| 留痕 | 建立、每次按许可执行、撤销全部留痕，执行记录标注"依据常设许可 #id" |
| 不适用与展示 | 任何触及红线、权重、授权范围、质保与安全的事项**不得**转为常设许可；常设许可清单必须与"红线"视觉同级，避免用户误以为是无限授权 |

### 3.2 三个动作的后续流程
**动作一 · 同意**：① 立即写入 `AuditEntry`（`level=L2`、`actor=用户`、`action=approve`、`reasonCode=user-approved`）；② 状态置 `approved`，按 `effectiveAt` 执行——影响当日计划则即时重算并标注"已按你的确认调整"，影响次日计划则次日 00:00 生效；③ 卡片转结果态，`revocable=true` 时撤销入口保留 24 小时；④ 来源页同步（计划页"因你确认而调整"标记、涉预算时电池页账本更新）；⑤ 通知为 App 内确认反馈（不推送）+ 次日日报一句话回执；⑥ 连续同意同一类 L2 达 3 次 → Agent 提示是否建立常设许可（§2.7）。

**动作二 · 不同意**：① 必须选择**驳回原因标签**（单选必填）：不划算 / 不安全 / 我今天有特殊情况 / 我不喜欢这个做法 / 我不确定，先别做 / 其他（需填 5 字以上）；② 选择后**强制进入分流问句**（第 9 章）——`[就这一次]` 记为一次性例外、不改规则，生成 `ExceptionRecord(scope=once)` 并将状态置 `rejected`；`[以后都这样]` 转规则变更请求，非红线类走 L2 建立抑制规则或反向常设许可，红线类预填 L3-A 申请表单（放弃提交即回退为"就这一次"）；③ 留痕含原因标签、自由文本与分流结果（各一条）；④ 不推送；若该提议属"每天都会出现"的类型，文案必须说明"我不会再问这件事了，除非情况变了"；⑤ 立刻切回最保守动作执行，**不产生任何抱怨或劝说文案**（反面清单第 12 条）。

**动作三 · 以后都这样**：① 判定是否触及红线 / 权重 / 预算上限 / 授权范围——**不触及**则走常设许可建立流程（L2 一键确认，展示边界、上限、有效期、可撤销性，确认后写入 `StandingConsent`），**触及**则预填 L3-A 申请转人工审批，审批通过前本次提议不执行；② 先显示"你会失去什么"（如"以后这类动作我不会再问你，如果我判断错了，你可以在记录里撤销"）；③ 下一次日报内给出生效回执"我以后都会这样做（依据：你的常设许可 #SC-0031）"；④ 可在设置页与协作页一键撤销（L3-B），撤销后恢复逐次确认。
### 3.3 超时未处理的默认行为
**总原则：超时不等于同意。**

| 项 | 规格 |
|---|---|
| 默认行为 | 提议**不执行**，系统保持当前保守动作，状态置 `expired`（依据：Agent 不得执行任何未被授权的动作，§6.5；把"沉默"解释为"同意"是产品立场错误） |
| 唯一例外 | 提议本身是安全类动作（如"要不要切安全模式"）——不设超时，30 分钟后自动执行安全动作并明确告知 |
| 截止时间 | 默认 24 小时；若必须在某时点前决定（如夜间充电窗口），截止时间 = 生效时刻前 2 小时，卡片必须写明 |
| 超时通知与重提 | 不重复推送；超时后在次日日报出现一行"昨天有 1 件事我没等到你的回复，我就没做"；同一事项最多重提 1 次且 7 天内不重复，重提时必须说明"这是我第二次问，如果你不想再看到，可以告诉我别再问" |
| 批量过期 | 同时过期超过 3 条时，把同类提议合并为一次常设许可建议，不逐条重问 |
### 3.4 同屏数量与"更多"的处理
| 承载位置 | 最多显示 | 超出处理 |
|---|---|---|
| 今日页"需要你决定" | **1 条** | 显示"还有 N 条"，点击进入协作页队列 |
| 协作页队列 | **5 张卡片** | 分页 / 加载更多；顶部出现提示条"有 6 件事在等你，其中 4 件我可以先按保守方式处理" |
| 来源页（计划/电池/市场）上下文卡片 | 1 条 | 与今日页共用同一条优先级最高的记录，不重复计数 |

**排序规则（同时决定哪一条上今日页）**：① `severity = edge` 优先；② 按 `deadlineAt` 升序；③ 按影响绝对值降序；④ 按 `createdAt` 升序。

**队列积压（> 5 条）时的动作**：`[逐条处理]`（默认，进入单条全屏确认页）；`[全部保持保守]`（一键驳回全部，驳回标签统一为"我不确定，先别做"）；**不提供 `[全部同意]`**——批量同意会让用户在未阅读的情况下授权，违反"危险动作永不自主"。

### 3.6 状态与留痕
```
pending ──同意──► approved ──► executed
   │                 └──(revocable 且未执行)──► cancelled
   ├──不同意──► rejected ──(分流：以后都这样)──► 规则变更 / L3-A 申请
   ├──超时────► expired ──(最多重提 1 次)──► pending
   └──用户清空队列（L3-B）──► cancelled
```
每次状态变化产生一条 `AuditEntry`，`category ∈ {l2-proposal, l2-approve, l2-reject, l2-expire}`；`reasonText` 必须写入用户选择的原因标签原文。

## 4 · L3 人工专属操作规格
### 4.1 申请表单字段（通用化后的 `L3Request`，`GuardrailChange` 为其子类型）
| # | 字段 | 类型 | 必填 | 校验与说明 |
|---|---|---|---|---|
| 1 | `requestId` | string | 是 | 系统生成，格式 `L3-YYSSTT-NNN` |
| 2 | `applicant` | `{ role, id, display }` | 是 | 角色 ∈ 用户 / 安装商 / 客服 / 策略运营 / 护栏复核人 |
| 3 | `onBehalfOf` | `{ householdId }` | 是 | 安装商发起时必填，须记录"已与客户沟通"的证据引用 |
| 4 | `category` | enum | 是 | 备电预留 / 最低电量 / 循环预算上限 / 权重配比 / 寿命保护强度 / 收益门槛 / 保障设备 / 批量策略 / 客诉口径 / 数据授权 |
| 5 | `target` | `{ subject, subjectId }` | 是 | 变更对象（护栏项 / 偏好项 / 策略包） |
| 6 | `beforeValue` / `afterValue` | string | 是 | 变更前值（系统自动填，不可手改）/ 变更后值（用档位文案，不暴露裸参数） |
| 7 | `reasonText` | string | 是 | 变更理由，**不少于 20 字** |
| 8 | `necessity` | enum | 是 | 用户主动要求 / 市场规则变化 / 设备与家庭变化 / 异常复盘结论 / 合规要求 |
| 9 | `impactEarning` | `Range` | 是 | 收益影响预估（带区间），系统自动计算 |
| 10 | `impactRisk` | string | 是 | 风险变化（如"停电时少用 2 小时"），系统自动计算 |
| 11 | `impactWarranty` | string | 条件 | 涉及质保影响时必须填写并由法务确认 |
| 12 | `scope` / `affectedCount` | `single` / `multi` + number | 是 | 影响范围（`multi` 触发多签与灰度）；`multi` 时影响户数必填 |
| 13 | `effectiveAt` | enum | 是 | 立即 / 指定时间 / 下次计划生成时（默认，推荐） |
| 14 | `rollbackPlan` | string | 条件 | `scope=multi` 或影响 > 50 户时必填 |
| 15 | `evidence` / `consentConfirmed` | `EvidenceRef[]` + boolean | 是（后者） | 附件与数据依据；用户本人发起时勾选"我明白这会改变什么"，他人发起时必须附用户沟通记录 |
### 4.2 审批角色与签核规则
| 角色 | 职责 | 权能边界 | 必需签核的场景 |
|---|---|---|---|
| 用户本人 | 红线类变更的最终确认人 | 必须本人确认，任何人不得代签 | 单户红线、非红线变更、数据授权扩大 |
| 护栏复核人（沃太） | 保证"人仍立法"，审批 L3-A、规则变更把关 | 可批准与驳回，不可代替用户确认 | 单户红线（弱电网必加）、多户、市场级 |
| 策略运营 | 多户与市场级变更的申请与执行 | 可发起；多户变更需复核人联签 | 多户（≤ 50 户）、市场级 |
| 法务 / 合规 | 涉质保、安全、并网、数据授权、对外表述 | **拥有否决权** | 涉质保 / 安全 / 并网 / 对外表述 |
| 客服 / 售后 | 客诉答复口径、异常复盘结论转入规则 | 最终答复需主管确认 | 客诉最终口径 |
| 安装商 / 经销商 | 可发起、可查看客户留痕 | **不可批准任何 L3**（硬约束，§4.11） | 无（仅发起） |

**附加要求**：多户（≤ 50 户）必填灰度方案；市场级（> 50 户）必填灰度方案 + 回滚预案 + 影响户数披露。
### 4.3 审批状态机
```
draft ──提交──► pending ──┬─► approved ──► effective ──┬─► revoked（撤销 / 回滚）
  ▲                        │        ▲                  └─► superseded（被新版本取代）
  └──补充材料──── info-required ────┘
                           ├─► rejected（驳回）
                           └─► expired（30 天未处理自动关闭）
```
| 状态 | 界面文案 | 可见对象 | 时限 |
|---|---|---|---|
| `draft` | 草稿（还没提交） | 申请人 | 30 天后自动清理 |
| `pending` | 等待审批 | 申请人与审批人 | 单户 48 小时内给结论；多户 5 个工作日 |
| `info-required` | 需要补充材料 | 申请人 | 7 天内未补充转 `expired` |
| `approved` | 已通过，等待生效 | 全相关方 | 按 `effectiveAt` |
| `effective` | 已生效 | 全相关方 + 留痕可见 | — |
| `rejected` | 未通过 | 申请人 | 必须附驳回理由与替代方案 |
| `revoked` | 已撤销 | 全相关方 | 留痕保留 |
| `superseded` | 已被新版本取代 | 全相关方 | 保留版本链 |
| `expired` | 超期未处理，已关闭 | 申请人 | 可重新发起 |

**生效时刻约束**：默认 `effectiveAt = 下次计划生成时`，避免当天计划中途变更造成"用户以为没变、实际变了"；立即生效仅用于安全相关与用户明确要求的情形。
### 4.4 驳回分支
1. **驳回必须给理由**，理由标签固定：证据不足 / 影响过大 / 与其他红线冲突 / 合规不允许 / 建议更保守的替代方案。
2. **必须给替代方案**：Agent 生成 1–2 个更保守的方案（如"不能取消备电预留，但可以把停电够用时长从 12 小时降到 8 小时"），附影响对比。
3. **可一键接受替代方案**：接受后自动生成新申请并关联原申请（`supersededBy` 关系），无需重新填表。
4. **用户知情后坚持**：用户可坚持原方案，但必须完成二次确认，界面完整展示"如果你坚持，会发生什么"（收益与风险两栏），并生成 `informed-override` 留痕。产品立场：用户有最终决定权，但记录必须完整。
5. **不得反复劝阻**：同一条被驳回的申请，30 天内不得再次向同一用户建议；仅可在下一次季度复核第 5 问中作为议题列出一次。
6. **安装商发起的被驳回**：结果同步给安装商后台（含理由），避免重复发起。
### 4.5 生效通知
| 环节 | 通道 | 文案模板（界面文案） |
|---|---|---|
| 提交成功 | App 内 | "你的申请我已经送到审核人那里了，最多 48 小时会有结果。" |
| 需补材料 | App 推送 | "还差一点信息：{缺什么}。补齐后我继续帮你送。" |
| 通过待生效 | App 推送 + 协作页 | "你的修改通过了，从{生效时间}开始生效。" |
| 已生效 | App 内 + 日报一行 | "从今天起：{变更后的人话表述}。上一次是{变更前的人话表述}。" |
| 被驳回 | App 推送 + 协作页 | "这次没通过，原因是{理由}。我给你准备了两个更稳妥的做法：{替代方案}。" |
| 被撤销 | App 内 | "这项修改已撤销，回到{原值}。" |

**生效后必须同步刷新**：全局状态条、电池页护栏清单、设置页偏好、收益页口径说明、协作页留痕表。
### 4.6 留痕字段（L3 专项）
| 字段 | 说明 |
|---|---|
| `requestId` | 关联申请 |
| `approvalChain` | 审批链快照：`[{ approver, role, at, decision, note }]` |
| `beforeSnapshot` / `afterSnapshot` | 变更前后完整快照（含偏好版本号） |
| `preferenceVersionBefore` / `preferenceVersionAfter` | 偏好版本链，用于季度复核差异对比 |
| `effectiveAt` / `effectiveConfirmedAt` | 计划生效时间与实际确认生效时间 |
| `informedOverride` | 是否为"用户知情后坚持" |
| `rollbackOf` | 若本记录是回滚，指向被回滚记录 |
| `correctsId` | 若本记录是对更早记录的更正，指向被更正记录（不允许原地覆盖） |

## 5 · 留痕（AuditEntry）规格
### 5.1 必填字段
| # | 字段 | 类型 | 说明 | 界面呈现 |
|---|---|---|---|---|
| 1 | `id` / `householdId` / `siteId` | string | 全局唯一、单调递增；归属家庭与站点 | 不显示（可复制） |
| 2 | `occurredAt` | string | 发生时间（设备本地时区 + 偏移） | "今天 17:32" |
| 3 | `actorType` | enum | `user / agent / installer / support / reviewer / operator / system` | 操作人列来源 |
| 4 | `actorId` / `actorDisplay` | string | 操作人标识与显示名 | "管家" / "你" / "沃太售后 · 张工" |
| 5 | `level` | enum | `L1 / L2 / L3-A / L3-B / L3-X` | 级别标签（文字，非纯色） |
| 6 | `category` | enum | 见 5.1.1（15 类） | 分类筛选 |
| 7 | `subject` / `subjectId` | enum + string | 护栏 / 偏好 / 运行模式 / 计划 / 决策 / 异常 / 策略包 / 常设许可 | 点击跳转对象页 |
| 8 | `action` | enum | `create / update / approve / reject / override / take-over / resume / revoke / expire / correct / export` | 动作列 |
| 9 | `beforeValue` / `afterValue` | string \| JSON | 变更前后值（人话表述 + 原始值双写） | 悬停显示"从…到…" |
| 10 | `reasonCode` | enum | 结构化原因，见 5.1.2 | 原因列 |
| 11 | `reasonText` | string \| null | 自由文本原因（用户填写或系统生成） | 展开显示 |
| 12 | `sourceModule` | enum | 来源模块标记（与 §3.5 一致） | 来源列 |
| 13 | `relatedIds` | object | `{ decisionId?, incidentId?, requestId?, pendingId?, reviewId? }` | 关联列（可跳转） |
| 14 | `channel` / `hashPrev` / `hashSelf` | enum + string | 通知与操作通道；哈希链（§5.2） | 深水区；"这条记录没有被改过" |
| 15 | `correctsId` / `schemaVersion` | string \| null + string | 指向被更正的记录；结构版本 | 更正关系可见 / 深水区 |

**5.1.1 `category` 枚举（15 类）**：`run-mode`（运行模式迁移）、`l2-proposal`、`l2-approve`、`l2-reject`、`l2-expire`、`l3-request`、`l3-decision`、`guardrail-change`、`preference-change`、`standing-consent`、`override-exception`、`rule-change`、`take-over`、`manual-action`（安装商 / 售后的现场动作）、`data-privacy`（授权、导出、删除）。

**5.1.2 `reasonCode` 枚举**：`agent-auto`、`user-approved`、`user-rejected`、`user-insisted-after-warning`、`timeout-default-safe`、`guardrail-triggered`、`safety-triggered`、`market-rule-change`、`data-source-degraded`、`review-output`、`installer-requested`、`compliance-required`、`correction`。
### 5.2 不可篡改要求
1. **追加写（append-only）+ 哈希链**：一经写入不可修改、不可删除；更正必须新增记录并用 `correctsId` 指向被更正记录（对应总 PRD §7.4 第 6 条）；`hashSelf = H(hashPrev ‖ 规范化序列化(payload))`，每日 00:00 对当日末条哈希做时间锚定。
2. **写入即同步**：L2/L3 动作在**执行前**写入意图记录，执行后写入结果记录；不允许"先执行后补记"。
3. **撤销不复原、可见性分级**：撤销、回滚、拒绝都产生新记录，历史保留；用户可看本人全部留痕，安装商只看其服务客户的留痕，运营看脱敏后的聚合与个案。
4. **可自证**：任一记录详情页提供校验入口，显示"这条记录自{时间}起未被修改"与前后哈希片段（深水区，默认折叠）。
5. **删除请求的处理**：用户撤回授权或请求删除时，删除画像类与曲线类原始数据，但**法定与质保必要的最小留痕保留**，并在删除回执中逐条列出保留了什么、为什么。
### 5.3 筛选与导出
| 筛选项 | 取值 |
|---|---|
| 时间范围 | 近 7 天 / 30 天 / 本季 / 本年 / 自定义（默认近 30 天） |
| 级别与操作人 | 级别 L1 / L2 / L3-A / L3-B（默认 L2 + L3）；操作人 我 / 管家 / 安装商 / 沃太售后 / 审批人 |
| 分类与对象 | 5.1.1 的 15 类（多选）；对象 护栏 / 偏好 / 运行模式 / 计划 / 决策 / 异常 / 策略包 / 常设许可 |
| 来源模块 | 与 §3.5 一致 |
| 其他 | 仅看被更正的记录 / 仅看"用户知情后坚持"的记录 |

**导出规格**：① 格式为 CSV（含全部字段与英文列名）+ PDF（含口径说明与哈希校验摘要）；② 单条导出从记录详情页发起；③ 区间导出按筛选条件，单次上限 10 000 条，超出分卷；④ **导出本身必须留痕**（`action = export`）并记录范围与用途；⑤ 导出文件必须含口径说明页（收益口径、术语对照、时间口径、`schemaVersion`）；⑥ 权限与可见性分级一致。
### 5.4 保留期限建议
| 数据类别 | 建议保留期 | 依据与备注 |
|---|---|---|
| 运行模式迁移与 L1 决策日志 | **永久**（用户侧可查） | 与"决策日志对用户永久开放"对齐（§8.1） |
| L2 / L3 操作留痕与审批链 | **永久**（用户侧）；运营侧 5 年 | 责任边界证据（§9.1）。5 年为建议值，需法务确认 |
| 护栏变更、偏好版本链与循环记账原始数据（含温度、深度、次数） | 设备质保期结束后 **2 年**，并符合欧盟电池法规可追溯性要求 | 质保争议证据；§6.3、§9.2，需法务确认 |
| 安全事件与事故简报 | **永久** | 安全责任证据 |
| 导出文件副本 / 画像原始曲线 | 导出副本不长期保存（链接 7 天后失效）；画像曲线按授权范围保留，删除请求时删除 | 数据最小化与隐私合规 |

> 以上期限为产品侧建议值，最终以法务与合规意见为准（对应总 PRD 附录 B 的核实要求）。
### 5.5 留痕在各页面的位置
| 页面 | 呈现 | 目的 |
|---|---|---|
| 协作 | 全量留痕表 + 筛选 + 导出 | 主入口，"谁、何时、改了什么、为什么" |
| 今日与计划 | 时间线"谁做的"标记 + "这个计划被谁改过"（安全覆盖、用户调整、接管冻结） | 让用户知道 Agent 与人各自做了什么，消除"背着我改"的怀疑 |
| 决策与电池 | 被推翻记录 + 分流结果 + 接管记录；红线变更历史（申请、审批、生效、回滚） | 解释与信任（§8.4）；责任边界证据 |
| 异常与安装商视图 | 处置时间线（Agent / 用户 / 安装商 / 售后分段）；客户留痕只读、不可编辑 | 人机交接标准物；远程支持与对账，**不可修改客户红线** |
| 设置 | 授权、导出、删除的留痕 | 隐私合规 |

## 6 · 五个协作触点汇总表
| 触点 | 名称 | 目标 | 触发时机 | 参与者 | 产出物 | 成功判据 | 承载页面 |
|---|---|---|---|---|---|---|---|
| **T1** | 冷启动三问定调 | 10 分钟内完成定调，用户不填任何技术参数 | 首次开通（安装商并网调试完成后） | 用户（Agent 引导） | 初版偏好与红线 `PreferenceSet v1` + 影子期开始 | 完成率 ≥ 80%；中位耗时 ≤ 10 分钟；"以后再说"后仍能拿到保守默认值 | 引导（⑨，主）；协作页"我的定调"只读回看 |
| **T2** | 影子期 | 把黑盒变白盒，零风险验证 Agent 能力 | T1 完成后的 14–28 天 | 用户（每日查看或不查看） | 影子期单日对照 `ShadowDay[]` + 影子期小结 | 查看率 ≥ 60%；小结后选择开启自动的比例 ≥ 50%；影子期零调度动作 | 引导（⑨ 影子期看板）；今日页角标；协作页摘要 |
| **T3** | 计划审批与锁单 | 一天一张计划，可接受 / 调整 / 按老办法来 / 锁单 | 每日傍晚 17:30–18:30 生成次日计划 | 用户（一方） | 已确认或自动生效的 `EnergyPlan` + 锁单记录 | 自动模式下撤销率 ≤ 5%；调整后重算 < 2 秒；锁单期间无安全外覆盖 | 计划（②，主）；今日页（L2 摘要）；协作页（等待确认计数） |
| **T4** | 异常接管 | 标准交接物，人工不从零排查 | 异常发生（停电 / 电池告警 / 数据失效 / 收益异常） | 用户 + 安装商 + 沃太售后 + Agent | 事故简报（六要素）+ 处置时间线 + 闭环回写结论 | 六要素齐全率 100%；接管期间 Agent 自主动作数 = 0；恢复汇报送达率 100% | 异常（⑦，主）；全局状态条；协作页（接管留痕） |
| **T5** | 季度策略复核 | 30 分钟，把"人做立法者"制度化 | 每季度到期；或规则变更、家庭结构变化、安装商发起时提前触发 | 用户 + Agent（可选安装商 / 护栏复核人陪跑） | 新版偏好与红线 `PreferenceSet vN+1` + 差异对比 + 复核记录 | 到期后 30 天内完成率 ≥ 60%；中位用时 ≤ 30 分钟；每次至少产出 1 项明确结论（含"维持现状"） | **协作（⑧，主）**；议题来源在收益 / 电池 / 家庭 / 市场页；生效结果回写设置与电池页 |

**触点之间的关系**：T1 决定初始边界，T2 验证能力，T3 是日常节拍，T4 是异常兜底，T5 是周期性重新立法。**五个触点缺席任何一个产品都会退化**：缺 T2 用户不敢开，缺 T3 用户觉得被夺权，缺 T4 出事没人管，缺 T5 就会"设完就忘"。协作页必须有一处汇总视图展示全部触点的完成状态（"你的协作节拍：定调已完成 / 影子期剩余 9 天 / 下次复核在 3 月 12 日"）。

## 8 · 季度复核向导规格（T5）
### 8.1 向导总览与分步交互
**目标**：30 分钟内完成，产出一份**新版偏好与红线**，并让用户明确知道"这次你主要改了什么，我会怎么变"。

| 步 | 标题（界面文案） | 主题 | 建议时长 | 产出 |
|---|---|---|---|---|
| 0 | 开始 | 说明要花多久、会做什么、可随时中断 | 30 秒 | 会话开始留痕 |
| 1 | 这一季省得怎么样 | 收益复盘 | 6 分钟 | 收益结论（维持 / 调整方向） |
| 2 | 电池累不累 | 循环预算消耗 | 5 分钟 | 护电池强度结论 |
| 3 | 停电的时候够不够用 | 备电体检 | 5 分钟 | 备电结论与季节性设置 |
| 4 | 你的电价合同还合适吗 | 合同与市场规则体检 | 5 分钟 | 是否触发规则复核 |
| 5 | 你的想法有变化吗 | 偏好复核 + 家庭变化 | 7 分钟 | 权重配比与新增事项 |
| 6 | 确认新版规则 | 差异对比 + 确认生效 | 3 分钟 | `PreferenceSet vN+1` |

**交互规格**：① 单步单问，证据在上、问题在下、选项在手边，不做多层跳转；② 顶部固定进度（1/5，不用装饰性点状图）；③ 中断可续，草稿保留 30 天，重进时显示"你上次停在这里"；④ 每题都有"为什么问这个"一句话说明；⑤ 每题默认答案 = **维持现状**，全部选默认也能完成并产出"维持版"；⑥ 每题都能选"我不知道"，该项按当前值冻结并在下一季给更详细的证据；⑦ Agent 的发现必须可展开到电价、天气、画像、电池状态、循环记账的来源与时间戳（P6 可回溯）；⑧ 零裸术语，所有数字用人话 + 区间；⑨ 键盘可 Tab 完成，焦点环可见，选项组有组标签；⑩ **不劝说**，只解释影响，不表达倾向、不重复劝说（反面清单第 12 条）；⑪ 可选"邀请安装商 / 沃太陪同"，陪跑标注进入留痕但不改变结论；⑫ 季度到期后第 1、7、21 天各提醒一次（上限 3 次），可延期一次（≤ 30 天），延期记录进留痕。
### 8.2 五问逐问展开
**第 1 问 · 这一季省得怎么样**（界面提问："这一季，我帮你省下来了吗？"）
- **发现**：本季预计净收益 €{likely}（区间 {min}–{max}）；比上一季{高/低} €{delta}；比出厂策略多省 €{deltaBaseline}；与理论最优还差 €{gapOptimal}。
- **证据**：四栏对照（什么都不做 / 出厂策略 / 管家 / 理论最优）；收益归因 6 项拆解（含效率损失与折旧两项负项）；账单核对差异率 {reconDiff}%；数据来源与生成时间。
- **建议**：与理论最优差距扩大 > 15% 且与数据质量无关 → 建议"更省钱一点"；收益正常 → 明确建议"维持现状，不需要改"（允许 Agent 建议"什么都不用改"，这本身就是可信度）。
- **选项**：`[维持现状]`（默认）· `[更省钱一点]` · `[少动手一点，别太折腾电池]` · `[看看钱省在哪]`（展开归因，不改变选择）。
- **当前答案**：默认 = 维持现状（省钱 40% / 备电 40% / 护电池 20%），保存后进入第 6 步差异对比。

**第 2 问 · 电池累不累**（界面提问："这一季电池用得省吗？"）
- **发现**：本季用掉 {usedPct}% 的循环预算，还剩 {leftPct}%；按现在的用法电池预计还能用 {years} 年；本月温度与单体温差{正常/偏高}。
- **证据**：循环预算账本（月 / 季 / 年三条）；消耗趋势曲线；温度与温差的区间统计；与同期机型对比（±{peer}%）；质保循环余量。
- **建议**：剩余预算低于 30% → 建议"电池用得久一点"；预算充足且用户是省钱型 → 说明"你还有空间，可以用得更积极，但我不主动建议"。**红线提示**：若涉及调整循环预算上限，界面必须标注"这是人工专属操作，需要你确认后生效"（L3-A）。
- **选项**：`[维持现状]`（默认）· `[电池用得久一点]` · `[可以用得积极一点]` · `[看看账本]`。
- **当前答案**：默认 = 当前的电池寿命保护强度与收益门槛档位。

**第 3 问 · 停电的时候够不够用**（界面提问："这一季停过电吗？留的电够用吗？"）
- **发现**：本季停电 {count} 次，累计 {hours} 小时；其中 {edgeCount} 次备用余量低于 2 小时（擦边）；最久一次 {maxOutage} 小时；当前保障时长 {backupHours} 小时。
- **证据**：停电历史与时间分布；每次停电前后的余量曲线；区域电网检修与天气背景；因备电不足而未执行的弃权记录（弃权清单第 2 类）。
- **建议**：有擦边事件 → 建议"停电时多留一点"；区域进入台风季 / 极端高温期 → 建议开启"按季节自动提高备电"（默认开启，需用户知情）。**安全约束**：弱电网市场不得低于当地策略包下限，界面说明原因且不提供非法选项。
- **选项**：`[维持现状]`（默认）· `[停电时多留一点]` · `[少留一点，我想多省点]` · `[按季节自动调整]`（推荐勾选）。
- **当前答案**：默认 = 当前"停电时够用多久"档位 + 季节性自动调整开关状态。

**第 4 问 · 你的电价合同还合适吗**（界面提问："你的电费合同，还是划算的那个吗？"）
- **发现**：你的合同类型：{tariffMechanism}；本季有 {ruleChangeCount} 条市场规则变化，其中 {affected} 条影响你的省钱方式；电网费机制{有/无}变化。
- **证据**：合同关键条款摘要（不含签约建议）；本季电价曲线形态变化；电网费规则变更条目与生效时间；同类合同在该市场的平均表现（脱敏，仅供参考）。
- **建议**：规则变化影响现有策略 → 建议"触发一次规则复核"；合同仍是合理选择 → 明确说明"现在这份合同没有明显问题"。**合规约束**：必须标注"仅供参考，不构成推荐意见"，不得出现对外承诺或"保证更便宜"的表述（§4.6）。
- **选项**：`[知道了，不用改]`（默认）· `[帮我触发一次规则复核]` · `[把合同体检改成每月提醒我一次]` · `[看看依据]`。
- **当前答案**：默认 = 不变更；仅当用户主动选择才生成复核任务（交策略运营，属 L3-A 多户流程）。

**第 5 问 · 你的想法有变化吗**（界面提问："家里有什么变化吗？你想让我多省一点，还是多稳一点？"）
- **发现**：你的实际行为与设定偏好有 {driftDesc}（如"你三次手动把备电留得更多，比你现在设定的更保守"）；检测到的变化：{新增 EV / 新增热泵 / 作息变化 / 用电量结构性上升}。
- **证据**：过去一季的推翻与分流结果（就这一次 {onceCount} 次 / 以后都这样 {ruleCount} 次）；常设许可清单与使用次数；画像结构性变化条目与置信度；大功率设备清单变化。
- **建议**：实际行为与设定偏好持续背离 → 建议把偏好改成与行为一致（"你实际上更在意停电够用，要不要把配比调过来"）；有新设备 → 建议纳入画像并重算可移动负荷。
- **选项**：配比滑杆（省钱 / 备电 / 护电池，三档联动）；变化勾选清单（新增设备 / 家庭人数变化 / 长期外出 / 新增必须保障设备）；`[都不变]`（默认）。**交互细节**：拖动即时显示"预计每季收益 {±delta} / 停电可用时长 {±hours} / 电池寿命影响 {档位}"，不暴露裸参数。
- **当前答案**：默认 = 当前配比与画像条目不新增；滑杆初值 = 当前配比。

### 8.4 与上一版的差异对比呈现

| 已完成 / 已延期 | 正常行可展开差异对比；延期时显示原到期日与延后到期日，附延期留痕 |
| 数据不足（运行不足 60 天） | 明确说明"数据还不够，我先给你看能看的部分"，第 1、2 问降级为部分展示 |

**附加区块**：偏好版本链时间轴（v1 → v2 → v3 → v4，任两点可对比）；常设许可历史（建立、使用次数、撤销）；推翻与分流统计（本季"就这一次"与"以后都这样"各多少次，其中多少次转化为规则）。

## 9 · 强制分流机制规格
### 9.1 触发原则
> 用户推翻一个决策时，Agent 必须问一句：**这次是例外，还是以后都这样？**

**不可绕过的硬规则**：① 任何推翻路径都必须经过分流问句，不存在"直接执行"的推翻入口；② 分流问句**只有两个等权选项**，不得有默认选中项、不得出现"推荐"标记；③ **关闭 / 返回 = 放弃推翻**（保持原决策），而不是默认记为"就这一次"——防止"沉默被记成例外"从而悄悄污染偏好记录；④ "就这一次"**不修改任何规则**，"以后都这样"**必须产生一条可留痕的规则变更**；⑤ 若被推翻的动作触及红线（备电预留、最低电量、预算上限、权重、授权范围），**不提供"就这一次"**，只能走 L3-A，并直接说明"这件事不能只改一次，需要走人工确认"；⑥ 三个入口共用同一张 `OverrideRecord`，留痕中标注入口来源 `entryPoint`。
### 9.2 三个入口
| # | 入口 | 位置 | 用户视角的动作 | 前置必填 | 入口特有说明 |
|---|---|---|---|---|---|
| **E-1** | 决策详情页的推翻 | 决策页 → 单条详情底部 `[这个决定我不同意]` | "我不认同这次的做法" | 驳回原因标签（必选）+ 可选自由文本 | 面向已发生的动作：先说明"这个动作已经执行 / 没执行"，再问分流；若已执行，明确告知"我无法回到过去，但可以现在调整" |
| **E-2** | 计划页的调整与按老办法来 | 计划页 → `[我要调整]` 提交时 / `[明天按老办法来]` | "我今天不想按你的计划来" | 调整方向（更省钱 / 更保险 / 多留备电 / 今晚别充）或"按老办法" | 面向未发生的动作：先重算计划预览再问分流，让用户看到后果再决定是否长期化 |
| **E-3** | L2 待确认队列的"不同意" | 今日页与协作页的 L2 卡片 | "这个提议我不接受" | 驳回原因标签（必选，见 §3.2） | 面向未授权的提议：拒绝即默认不执行（保守分支），分流在第 2 步出现 |

**第四类入口的处理**：安装商后台与客服代操作中的"撤销 / 干预"也必须走同一分流，由运营侧记录并回写用户侧留痕（`actor = installer / support`，`entryPoint = console`）。**不允许存在通过后台绕过用户分流的路径。**
### 9.3 交互实现
**界面形态**：全屏页（不用模态弹窗，避免误触与误关闭，与 §4.1 一致）。**页面结构自上而下**：① 发生了什么（一行摘要 + 时间 + 涉及动作，人话）；② 我为什么这么做（一句话理由，可展开 L2 依据）；③ 你不同意之后会怎样（两种结果的收益、备电、电池寿命三项变化并列）；④ 必填的驳回原因标签（6 个固定标签 + 其他）；⑤ 可选自由文本（"还有别的想告诉我的吗"）；⑥ 分流问句（大字号）：

> "这次是例外，还是以后都这样？"
> `[就这一次]`　`[以后都按我说的来]`
> 小字说明：`[就这一次]` = 只改这次，规则不变；`[以后都按我说的来]` = 我会把规则改掉，以后都照这个来。

⑦ 确认区：提交按钮文案随选项变化（`[就这一次，别改规则]` / `[改规则，从下次生效]`）。

**交互细节**：两个选项**视觉等权**（同尺寸、同色阶、同字重），不预选、不高亮；未选择任一项时提交按钮不可用，旁注"选一个我才能知道怎么记住这件事"；选择"以后都按我说的来"后若涉红线，立刻转为 L3-A 预填表单，可直接提交或放弃，放弃即回退为"就这一次"并提示"那我只改这次"；全程不用"偏好 / 参数 / 权重"等词，用"规则 / 做法 / 以后都照这个来"；无障碍上使用原生单选控件组（带组标签），键盘可完成全部操作。
### 9.4 `[就这一次]` 的后续影响链
```
选择「就这一次」→ 生成 ExceptionRecord { scope: 'once', targetDecisionId, expireAt: 当日 24:00 }
 ├─ 计划层：该时段动作替换为用户意图（hold / idle / 用户指定），仅当日有效
 ├─ 学习层：不写入画像、不修改偏好、不建立常设许可
 ├─ 反馈层：当日日报一句话回执「这次按你说的改了，规则没动」
 ├─ 留痕：AuditEntry { category: 'override-exception', reasonCode: 'user-rejected', level: 'L1' }
 └─ 观察窗：7 天内同类推翻 ≥ 3 次 → Agent 主动建议一次（只建议一次，用户拒绝后 30 天内不再提）
     「你最近三次都改了这个，要不要把它变成常态？」
```
**影响边界（写死）**：**不改变**偏好配比、红线值、预算上限、常设许可、画像条目；**可改变**当日计划与该时段的执行动作、当日收益预估（随之更新并说明差额）；**不可越界**——即便用户选"就这一次"也不得越过安全红线（如把备电余量放到 0），若用户要求越界则直接转 L3-A，不提供"就这一次"。
### 9.5 `[以后都按我说的来]` 的后续影响链
```
选择「以后都这样」→ 生成 RuleChangeRequest { origin: entryPoint, target, proposedRule, scope }
 ├─ 触及红线 / 权重 / 预算上限 / 授权范围
 │    → L3-A 审批流（预填表单 + 影响评估 + 已知情确认）
 │    → approved → effective（生效时间 = 下次计划生成时）；rejected → 执行 §4.4 驳回分支（给理由 + 给替代方案）
 └─ 未触及红线 → L2 一键确认 → 建立常设许可（Standing Consent）或偏好微调 → 立即留痕并给出生效回执
 共同后续：
 ① 版本层：PreferenceSet 或常设许可清单版本递增；旧版本保留、不覆盖
 ② 执行层：从下一个计划周期开始按新规则执行，不追溯更改历史记录
 ③ 反馈层：App 内 + 次日日报一行回执「我记住了：以后{新规则的人话表述}。从明天开始生效。」
 ④ 解释层：若 Agent 认为该选择不明智，在回执中附「我要告诉你一件事」区块说明风险（不阻断、不重复、不说教）—— 先照做，再解释（§6.7）
 ⑤ 留痕：AuditEntry { category: 'rule-change' / 'standing-consent', level: 'L2' 或 'L3-A' }
 ⑥ 复核挂钩：本季新增的规则变更自动进入下一季复核第 5 问的议题清单
```
**影响边界**：**改变**偏好、红线（经审批）、常设许可、后续所有计划的生成逻辑；**不追溯**已发生的决策、收益记录与历史留痕；**可撤销**——常设许可一键撤销（L3-B），红线变更可回滚（生成反向申请，留痕 `rollbackOf`）。
### 9.6 冷却与学习
| 情形 | 规格 |
|---|---|
| 规则变更后 7 天内反向推翻同一规则 | 标记 `preference-unstable = true`；不再自动建议该方向；第 15 天主动询问一次（仅一次） |
| 同一议题一个季度内被反向改动 ≥ 3 次 | 进入季度复核设为固定议题，并显式提示"我们在这件事上摇摆过" |
| 连续两次对同一类提议选"就这一次" | 不视为规则；第三次出现时降低该类提议的发起频率（计入 M1） |
| 连续两次对同类提议选"以后都这样" | 检查是否应直接修改默认红线（而非建立常设许可），触发产品侧默认值评审 |
| 冷却的边界 | 冷却只约束 Agent 的主动行为，**不约束用户主权动作** |

### 10.5 本模块明确不做的事
1. 不实现真实的审批后端与权限系统，原型以角色切换模拟审批角色。
