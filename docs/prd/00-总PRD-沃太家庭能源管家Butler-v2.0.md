# 第一章 背景、问题与定位

## 1.1 行业背景：户储的价值逻辑正在换挡

户用储能过去几年的增长靠**补贴 + 高电价 + 停电焦虑**三件事驱动：装一套光伏加电池，白天存电晚上用，靠自用率提升就把钱赚回来。这套逻辑不需要用户做决策——"自发自用优先"这个出厂默认策略就能兑现大部分价值。

现在三件事都在变：

- **补贴退坡**（德国、澳洲、英国等主要市场陆续收紧或改为贷款贴息），"装了就赚"的确定性下降；
- **固定零售电价合同被动态电价合同替代**（德国、北欧、英国、西班牙、澳洲已大规模提供小时级甚至 15 分钟级变动电价），电价从一张静态表变成一条曲线；
- **硬件同质化**，电芯、逆变器功率、容量档位差异越来越小，价格战压缩硬件毛利。

结果是结构性变化：**户储的收益来源，从"硬件本身"转移到了"电池每天怎么用"上。**

同一套光伏 + 电池，在不同调度策略下年度收益差距可以很大；而大多数家庭的电池，今天跑的还是三年前写死的出厂策略。这是户储行业下一个真正的价值洼地。

## 1.2 沃太能源的业务处境

沃太能源（Alpha ESS）是国内较早出海的户用储能企业，总部位于江苏南通，以欧洲市场为起点建立户用储能业务，品牌海外认知度高于国内。

- **业务结构**：以户用储能系统为主，"电池 + 逆变器"一体化储能机，配套自有 App 与云平台完成监控、报表与固件升级；延伸至工商业储能与便携储能。
- **目标市场与渠道**：德国、英国、意大利、澳洲、南非等为主要海外市场，销售以**海外经销商 + 本地安装商**为主。典型的技术型品牌出海路径——产品力强、渠道依赖重、直面终端消费者的触点较薄。
- **既有能力**：硬件与系统集成是强项，电池、逆变器、BMS、云平台自有，数据闭环掌握在自己手里。**"读懂电池状态"这件事，沃太比任何第三方软件公司都有优势**：SOH、温度、单体温差、历史循环，这些数据别人拿不到。
- **既有缺口（立项理由）**：
  1. App 能力停留在**监控 + 报表 + 手动设置**。用户能看见，但不能省心。
  2. 调度策略**出厂固定，或由用户手设时段**。电价合同一变，App 里那套"谷电充电时段"基本失效。
  3. 面对**两套完全独立的价格信号**（零售商动态电价 + 电网公司电网费机制），产品没有能力合并考虑。
  4. **决策是黑盒**。用户不知道电池为什么半夜在充电，于是不敢开自动，或者开了又关掉。
  5. 海外市场规则差异大，每进一个新市场都要重做一套策略，**反应慢**。

## 1.3 竞争格局与空位

| 类型 | 代表 | 现有做法 | 短板 |
|---|---|---|---|
| 整车厂式硬件巨头 | Tesla（时间电价模式、风暴预警）、华为 FusionSolar | 有自动调度，但规则化、模式少，用户只能在几个固定模式里选 | 调度逻辑不透明，无法干预细节；通常绑定自家生态 |
| 传统逆变器/储能厂商 | sonnen、GivEnergy、SolaX、Fronius、SMA、GoodWe、Growatt、Enphase、Anker SOLIX | 多数为固定模式 + 手设时段；动态电价能力参差不齐，往往先支持本国或单一零售商 | 需要用户自己搞懂电价规则；跨市场适配慢 |
| 纯软件/新零售侧玩家 | Tibber、Octopus（Intelligent Flux）、Amber（SmartShift）、Evergen、Kaluza、Lunar | 算法能力强，自动调度做得好 | 只服务自家客户、锁定单一零售商；拿不到电池底层健康数据；不掌握硬件 |
| 聚合商 / VPP | sonnen 的 VPP 类业务、各类聚合商 | 以电网服务收益为主 | 收益归聚合商，家庭感知弱；用户几乎不参与决策 |

**空位**：没有人同时做到 **跨零售商的动态电价调度 + 电网费第二信号 + 电池寿命护栏 + 可解释决策 + 多市场快速复制**。

而这恰好是沃太的位置——**硬软件一体、数据闭环自有、渠道覆盖多市场**。

同时必须清醒：**这是一个"信任门槛高于技术门槛"的产品**。竞品翻车的典型场景就是"自动模式半夜突然充电，用户一脸懵，第二天关掉功能"。本产品的核心难点不是算得准，而是**让人敢用、看得懂、随时能接管**。

## 1.4 问题定义

> 帮一个装了光伏和电池的家庭，在"想省钱、怕停电、怕电池早衰减"三个互相冲突的诉求之间，**每天自动做出最优的充放电安排，并让用户看得懂、管得住、随时能推翻**。

## 1.5 产品目标

**业务目标（对沃太）**

1. 让智能调度成为户储产品的**差异化卖点**与**软件/服务收入来源**，把一次性硬件生意变成持续的服务关系。
2. 让"进入一个新的动态电价市场"从"改固件等半年"变成"**云端配置策略包、几周上线**"。
3. 把**售后与渠道服务成本降下来**——安装商不再充当客户的人工调度员。
4. 沉淀家庭用能画像与调度记录，为将来参与**需求响应 / 虚拟电厂**积累可信的调度能力与用户授权基础。

**用户目标（对家庭）**

1. 电费账单**实打实地下降**，且用户能看懂省在哪。
2. 停电时**电一定够用**，不是"运气好还有电"。
3. 电池**不因为套利被过度使用**，质保期内健康度可控。
4. **不用每天看 App**、不用研究电价规则——越少操心越好。

## 1.6 非目标（本期明确不做）

1. **不做电力交易业务**。Agent 只做家庭侧自用优化，不代替用户签合同、不对外售电、不参与需要资质的市场交易。
2. **不做硬件的安全参数自动修改**。电压、保护阈值、并网参数等安全相关设置，Agent 永不可触碰。
3. **不做跨用户的策略自动变更**。所有影响多个家庭的规则调整，必须由人批准后发布。
4. **不做智能家居全屋控制**。热泵、EV 充电桩等只作为"可观测、可建议"的对象，本期不直接控制。
5. **不做收益承诺**。对外不得出现"每月保证省 XX 元"的表述。

## 1.7 一句话定位

> **沃太家庭能源管家（Butler）**——一个住在 App 里的家庭能源调度 Agent：它学会你家的用电和发电规律，读懂电价与电网费两条曲线，在你划定的红线内自动安排每天的充放电，并告诉你每一步为什么这么做。

## 1.8 三代做法对比

| 维度 | 第一代：出厂固定 | 第二代：用户手设时段 | **第三代：管家 Agent** |
|---|---|---|---|
| 谁做决策 | 厂商写死 | 用户凭感觉 | **Agent 每天算，用户定边界** |
| 输入信号 | 无 | 用户填的几个时段 | **电价曲线 + 电网费 + 天气 + 家庭画像 + 电池健康 + 用户偏好** |
| 适配变化 | 不适应 | 用户自己回来改 | **自动跟随，规则变化时提醒** |
| 备电保障 | 静态设定 | 静态设定 | **动态预留，绝不被套利侵占** |
| 电池寿命 | 无意识 | 无意识 | **循环预算记账，超支自动降级** |
| 用户理解 | 不需要 | 以为自己懂 | **每步可解释，主动说明"我为什么没做那件看似赚钱的事"** |
| 服务成本 | 低（价值也低） | 高（安装商被反复咨询） | **低，安装商可一键查看决策日志** |
| 新市场 | 改固件 | 改固件 | **云端策略包配置** |

关键差异不在"自动化程度"，而在两件事：**信号融合**（电价与电网费一起算）和**可解释**（看得懂才敢长期用）。

## 1.9 产品形态与入口

- **主入口**：沃太 AlphaESS App 内的"管家"分区（不新做 App，避免用户装第二套软件）。
- **次要入口**：安装商/经销商侧后台的"客户管家视图"——查看某位客户的当前策略、红线设置、近期决策日志与异常记录，用于远程支持。
- **推送通道**：App 通知 + 邮件（月度报告）。**不默认使用短信/电话**。
- **物理侧**：调度执行通过逆变器与电池既有通道完成，用户无需理解。

# 第二章 用户、痛点与需求本质

## 2.1 用户角色地图

这个产品有个容易搞错的地方：**掏钱的人、用的人、被麻烦的人，是三个不同的角色。**

| 角色 | 是谁 | 关心什么 | 在本产品中的位置 |
|---|---|---|---|
| **家庭业主（主人）** | 装了沃太系统的家庭决策人 | 这个月电费多少、停电怕不怕、这机器会不会坏 | **付费与授权主体**，Agent 的"委托人" |
| **家庭其他成员** | 配偶、老人、孩子 | 别半夜跳闸、别把电用光 | 体验相关方，**不应被要求学习任何规则** |
| **安装商 / 经销商** | 本地安装与售后伙伴 | 客户别老打电话、别投诉、能不能多卖点 | **隐性关键用户**，Agent 的推广放大器与一线接管人 |
| **沃太服务与运营团队** | 售后、技术支持、策略运营 | 工单量、告警处置、市场规则更新 | **Agent 的"上级"与立法者**，异常裁决人 |
| **电网公司 / 零售商 / 聚合商** | 电力侧商业对手方 | 可调节容量、削峰效果 | 未来价值交换对象，本期只做规则遵从 |

> **结论：产品表面服务家庭业主，实际必须同时服务安装商。** 安装商如果觉得这套 Agent 会给他增加麻烦，他会在客户面前把它关掉。因此"**减少安装商的工作量**"和"**让家庭业主省心**"必须同时成立。

## 2.2 As-Is：今天一个家庭的真实流程

1. **签约阶段**。家庭在零售商那里选了一个电价产品。很多市场现在推的是动态电价（小时级或 15 分钟级波动），但用户签的时候**基本不理解这意味着什么**，往往是被"平均更便宜"吸引。
2. **安装阶段**。安装商把系统装好、并网、调试、开通 App。**调度策略在这一步就定死了**：安装商在几个预设模式里选一个，或者干脆用出厂默认。这一步通常只花几分钟，**没有人真正了解这家的用电习惯**。
3. **摸索阶段**。用户过几周发现电费没省多少，于是自己进 App，凭感觉填两三个充电时段。填完就再也没改过。
4. **失效阶段**。情况一变，整套设置就作废了：
   - 冬夏日照变化，光伏发不出来，原来"白天存电"的计划空转；
   - 换了电价合同，或者零售商的电价波动区间变了，原来的充电时段不再是低价时段；
   - 家里添了电动车，晚上充电负荷变了；
   - 电网费机制变了（峰段划分调整、容量费出台）。
   **没有人会主动回来重设这些参数。**
5. **投诉或放弃阶段**。用户发现账单不对劲，打电话给安装商。安装商远程看一眼，也不知道该怎么调，只能建议"你把它切回自发自用吧"。**智能功能被关掉**，电池退化成"白天存、晚上放"的普通电池，卖掉它的商业理由也就没了。

> **致命之处**：整套系统的价值兑现，卡在一个**用户既没能力、也没意愿、也没时间**去完成的日常决策上。而且这个决策一旦定错，**没有任何人会收到反馈**——直到用户发现账单不对。

## 2.3 痛点清单

**A. 认知负担类——用户根本算不过来**

- 动态电价是小时级甚至 15 分钟级的曲线，一天几十上百个价格点。人脑无法判断"今晚该不该充、充几个小时、充到多少"。
- **电价便宜 ≠ 值得充电**。要把收益算清楚，必须同时考虑往返效率损失、充电功率限制、以及这些电量本来能不能留给光伏。
- **第二套信号没人管**：电网费（分时输配电价、容量费、需量电费、可控负荷网费减免档位）与零售电价是**两条独立的曲线**，方向可能相反。**现有产品完全不处理这个信号。**
- 用户看不懂 App 里的数字。SOC、kW、kWh、循环次数——这些术语对普通家庭是噪音。

**B. 经济性损失类——每年都在悄悄漏水**

- **默认策略本身就是收益下限**。"自发自用优先"在动态电价市场里会把最有价值的时段白白错过。
- **反向套利**：用户凭感觉设的充电时段，很可能落在高价时段，等于**主动买贵电**，还要额外付出循环损耗。
- **毛收益当净收益**：宣传里的"价差 × 电量"是毛数，扣掉往返效率损失（示例约 10%）、电池折旧、税费之后会明显缩水。
- **买贵电充、又在低价时段放电**：缺乏整体视野的策略经常自己和自己打架。

**C. 风险失控类——省的钱不够赔的**

- **备电被套利抽干**。为了赚价差，电池在傍晚被放到很低的电量。如果当晚停电，家庭连冰箱都保不住。**这是本产品最不能犯的错**。
- **频繁浅循环导致衰减**。每天多跑一次套利循环，一年下来是几百次额外的等效满循环。
- **责任真空**。电池是沃太的，电价是零售商的，网费是电网公司的，调度是算法做的。**出了问题，用户只会找沃太。**
- **停电正好发生在电池空的时候**——这种"运气不好"发生一次，用户对整个品牌的信任就没了。

**D. 服务成本与信任类**

- **安装商被迫当人工调度员**。客户打电话来问"为什么昨天半夜在充电"，安装商答不上来。
- **黑盒调度无法解释**。用户看不到"为什么"，就不敢开自动。
- **新市场适配慢**。每个国家的电价机制、网费规则、上网限制都不同，靠固件迭代根本跟不上市场变化。

## 2.4 需求本质：一道"三约束权衡题"

> 同样是 1 kWh 电池电量，它有三种互相排斥的用途——**卖掉赚价差、留着备用、省下来不消耗寿命**。三者不可兼得，必须取舍。

| 用途 | 收益形式 | 代价 |
|---|---|---|
| 套利（充低放高） | 直接的电费节省 | 消耗循环寿命 + 占用备用电量 |
| 备电（留着不用） | 停电时的保险价值 | 放弃当期套利收益 |
| 护电池（少动） | 延缓衰减、保住质保 | 放弃当期套利收益 |

**只有当前者的收益明显大于后两者的代价时，才值得动手。** 这个判断每天都要重做一次，因为电价、天气、家庭计划每天都在变。

由此推出本产品的**核心设计立场**：

> **用户不是每天的操作员，而是规则的立法者。**
> 用户定的是边界和偏好（我要多省心、停电要够用多久、电池我用得省一点），Agent 负责在边界内每天自动执行，并把每一次判断讲清楚。人只在**异常**和**周期性复核**时进场。

这一句是后面所有功能设计与协作机制的根据。

## 2.5 用户分层与优先级

| 分层 | 画像特征 | 核心诉求 | 对 Agent 的期待 | 优先级 |
|---|---|---|---|---|
| **省心型（主力）** | 双职工家庭、有孩子、不折腾技术 | 别让我操心，账单别涨，停电别慌 | 全自动 + 定期告诉我结果 | **P0** |
| **省钱型（先锋）** | 对电价敏感、会主动研究、可能已是动态电价用户 | 把每一分价差榨干 | 自动执行 + 我要能看细节、能调参数、能质疑 | **P0** |
| **保守型** | 高龄用户、有医疗设备/居家办公、第二住宅 | 可靠性第一，省不省无所谓 | 只给我建议，我自己按 | **P1** |
| **离网/弱网地区用户** | 南非等电网不稳定市场 | 停电是常态，备电是刚需 | 优先保供电，套利次要 | **P1**（市场差异化产品） |

**设计含义**：

- 默认档位面向"省心型"——**默认值必须保守、默认解释必须人话、默认不打扰**。
- 必须给"省钱型"留出**深水区**：能看到每一次决策的完整依据，能推翻、能锁单、能改红线。这批人是口碑的源头。
- "保守型"只需要一个开关：**只建议，不执行**。这个开关必须在首次引导里就能看到，不能藏在三层菜单下。

## 2.6 产品成功指标

**北极星**：**自动模式下、每户每月的可验证净收益**（口径见 6.2，需扣除效率损失与电池折旧）。

**护栏指标（任何一项破线，不得扩大推广）**

| 护栏指标 | 目标 | 破线含义 |
|---|---|---|
| 备电失守次数 | **0** | 产品定位崩塌，立即停止推广 |
| 循环预算超支率 | **0** | 护电池承诺失效 |
| 用户推翻率（稳定期） | < 5% | 决策质量或偏好理解有问题 |
| 自动模式 90 日留存率 | ≥ 70% | 信任未建立 |
| 因调度问题的客诉率 | 不高于基线 | 没降低服务成本，商业逻辑不成立 |
| 收益报告与实际账单偏差 | < 3% | 口径不可信，最危险的一类问题 |

**特别提醒**：**不要用 App 打开率作为核心指标。** 本产品的成功意味着用户**更少**打开 App。激活率、留存率、净收益、备电达成率才是对的；日活是错的。

## 2.7 验证路线：四步走

| 阶段 | 形态 | 用户感受 | 出口条件 |
|---|---|---|---|
| **① 影子模式** | 只出计划，不执行 | "它给我看，我自己按" | 建议准确率达标；用户查看率与互动率达标 |
| **② 建议模式** | 出计划，用户一键确认执行 | "它说，我点头" | 确认率达标、推翻原因可归类、无安全事件 |
| **③ 自动模式** | 护栏内自主执行，事后告知 | "它做，偶尔告诉我" | 净收益达标、留存达标、推翻率达标、备电失守为 0 |
| **④ 自动 + 需求响应** | 在授权范围内参与电网服务 | "它连电网的事也管了" | 资质、合作伙伴、责任边界全部落定 |

**灰度分层**：按市场（先德国）→ 按电价零售商 → 按硬件型号 → 按用户类型（先"省钱型"先锋用户，再"省心型"主流用户）。
**先先锋用户的原因**：他们愿意容忍瑕疵、会给出高质量反馈、是口碑源头。**但主流用户的默认值必须比先锋版更保守，两套默认值分开设计。**

# 第三章 信息架构与核心用户旅程

> v1.0 只定义了"能力"，没有定义"用户从哪里进入、看到什么"。本章补齐。

## 3.1 设计原则（约束所有后续 UI 决策）

| # | 原则 | 具体含义 | 反面案例 |
|---|---|---|---|
| P1 | **一屏一结论** | 每个页面顶部必须先给出一句人话结论，细节向下展开 | 首页直接铺满 8 条曲线 |
| P2 | **默认人话，深水区可展开** | 默认不出现 SOC / DoD / kW / kWh 裸术语；专业数值折叠在"展开细节"之后 | 首页大字显示 "SOC 62%" |
| P3 | **弃权必须解释** | 没有执行的赚钱机会要主动列出，不能沉默 | 只显示已执行的动作 |
| P4 | **不确定必须声明** | 预测一律用"预计 + 区间"，不给假精度 | "今天省 €1.86"（应写"€1.40–2.20"） |
| P5 | **危险动作永不自主** | 触碰红线的操作一律走 L2/L3 流程，界面上有明确标识 | 一个开关就改掉备电底线 |
| P6 | **每个数字可回溯** | 任一结论都能点进去看到依据（电价、天气、画像、历史） | 只给结果不给来源 |
| P7 | **降级状态可见** | 系统处于保守/安全模式时，全局有明显但克制的标识 | 悄悄降级，用户以为还在自动 |
| P8 | **不打扰即价值** | 不制造焦虑文案；用户不打开 App 是好事 | "你已经浪费了两周" |

## 3.2 视觉与交互基调

采用 **Minimalism / Swiss Style（国际主义排版风格）**：

- **字形**：几何无衬线（Inter），数字统一等宽对齐（tabular-nums），标题收紧字距。
- **网格**：12 列硬网格，模块间 24px 基线间距，所有卡片对齐同一列宽。
- **色彩**：以黑/白/中性灰为主体，**仅保留一个强调色**用于"管家在为你工作"的信号；红/琥珀色**只用于语义告警**，绝不用于装饰。
- **圆角**：0–4px（接近直角），不使用大圆角与拟物。
- **阴影**：一律使用 1px 实线边框表达层级，**不使用投影与渐变**。
- **图标**：统一 1.5px 线宽的矢量图标，**禁止使用 emoji 作为图标或装饰**。
- **数据可视化**：单色阶 + 一个强调色；图表必须有坐标轴标签与单位；禁止纯靠颜色传达信息（需叠加图形/文字编码）。
- **动效**：150–250ms，仅用于表达状态变化与空间连续性；尊重 `prefers-reduced-motion`。

## 3.4 核心用户旅程

### 旅程 A · 首次开通（目标：10 分钟内完成，用户零学习成本）

```
安装商完成并网调试
      ↓
用户在 App 看到"管家"入口（引导气泡，非弹窗）
      ↓
T1 三问定调（单屏，3 个问题，可全部用默认值跳过）
      ↓
系统自动换算备电预留 SOC（用户永远看不到百分比）
      ↓
进入影子期（默认 14 天），明确告知结束日期
      ↓
每天傍晚收到"如果按我说的做"计划 → 次日早晨收到"建议 vs 实际"对照
      ↓
影子期结束 → 影子期小结 → 用户选择开启自动（或继续只建议）
```

**关键设计**：

- 影子期开始**不要求**授权自动执行。
- 用户在任何一步都能选"以后再说"，未回答部分用最保守默认值。
- 影子期内不产生任何实际调度动作，零风险。

### 旅程 B · 日常闭环（设计目标：用户 0 次打开 App 也能正常运转）

```
17:30 推送次日计划（L1，除非需要用户决定）
      ↓
用户可接受 / 调整 / 按老办法来；不操作则默认生效
      ↓
夜间执行充电 → 早晨简讯（可关闭）
      ↓
日内小幅修正（静默） / 大偏差（推送 + 说明）
      ↓
当晚日报：今天实际省了多少、有没有修正、明天大概怎么走
```

### 旅程 C · 用户质疑（信任修复的关键路径）

```
用户在任意页面看到某个动作 → 点"为什么"
      ↓
L1 一句话理由 → L2 展开依据（电价/电网费/画像/放弃项）→ L3 历史对比
      ↓
用户推翻 → Agent 必问："这次是例外，还是以后都这样？"
      ↓
[就这一次] → 记为一次性例外，不改规则
[以后都这样] → 进入规则变更流程（若涉红线则走 L3 审批）
      ↓
留痕：谁、何时、改了什么、为什么
```

### 旅程 D · 异常接管

```
异常发生（停电 / 电池告警 / 数据失效 / 收益异常）
      ↓
Agent 按级别自动处置（降级 / 切安全模式 / 停止优化）
      ↓
生成事故简报（六要素）→ 按级别通知对应角色
      ↓
人工处理（用户只需知道 / 安装商远程诊断 / 沃太售后排障）
      ↓
Agent 在人工接管期间完全静默，不执行任何优化动作
      ↓
处理完成 → Agent 主动汇报"我恢复了，接下来我会这样做"
      ↓
闭环回写：这是"这一次"的问题，还是"这一类"的问题？
      个案 → 记录，不改进规则
      系统性 → 升级为规则变更任务，人工批准后进入策略包
```

### 旅程 E · 季度复核（30 分钟，制度化的"人做立法者"）

```
季度到期 → Agent 发起，用户安排时间
      ↓
五问向导：收益复盘 / 循环预算 / 备电体检 / 合同体检 / 偏好复核
      ↓
产出一份新版偏好与红线
      ↓
用户确认 → 明确告知与上一版的差异（"这次你主要改了什么，我会怎么变"）
      ↓
新版本生效并留痕
```

# 第四章 页面级需求规格

> 每一页包含：**页面目标 / 关键元素 / 关键交互 / 必须覆盖的状态 / 文案规则**。
> 页面内所有数值均为模拟数据的口径示例，正式口径见第六章。

## 4.0 通用状态矩阵（所有页面必须实现）

任何页面在以下五种状态下都必须有明确呈现，**不允许出现空白屏或冻结界面**：

| 状态 | 呈现要求 |
|---|---|
| **加载中** | 骨架屏（skeleton），保留与最终内容一致的行高与列宽，避免布局跳动 |
| **空数据** | 说明"为什么是空的" + 一个明确的下一步动作 |
| **数据源失效** | 明确标注"该数据暂不可用"，并显示系统已采取的降级策略（不得用最后已知值冒充实时值） |
| **降级运行** | 页面顶部出现运行模式标识（保守模式 / 安全模式），并说明原因与恢复条件 |
| **权限不足** | 明确标注该操作属于 L2/L3，给出"谁有权做"与发起路径 |

**全局文案规则**

1. 不出现 `SOC`、`DoD`、`EFC`、`kW`、`kWh` 裸术语（深水区展开后除外）。
2. 所有预测使用"预计"，并附区间。
3. 不出现"保证/确保省 XX 元"。
4. 不出现 emoji。
5. 紧急通知文案必须包含：发生了什么、我做了什么、你需要做什么（或"你什么也不用做"）。

## 4.1 今日（Today）

**页面目标**：用 10 秒回答用户三个问题——今天省了多少、停电够不够用、电池累不累；并在需要用户决定时把决定推到最前面。

**关键元素（自上而下）**

1. **运行模式条**：当前处于 影子期 / 建议模式 / 自动模式 / 保守降级 / 安全模式 / 人工接管，附一句原因（降级时）与预计恢复。
2. **结论卡（三格）**
   - 今日预计净收益：`€1.86` + 区间 `€1.40–2.20` + 与出厂策略的差额
   - 明早备用余量：`62%` → 翻译为 **"够你家基础用电约 9 小时"**
   - 本次动用循环：`0.42 次` → 翻译为 **"相当于电池寿命的 0.02%"**
3. **实时能量流**：光伏 / 电网 / 电池 / 家庭 四个节点 + 四条有向流量，标注瞬时功率的**人话版本**（"屋顶正在发 3.2 度电每小时"）。数据源失效时该区块整体置灰并说明。
4. **今日时间线**：横轴 24 小时，叠加电价曲线（背景）、计划动作（上轨）、实际执行（下轨）。允许点击任一时段展开原因。
5. **需要你决定（L2 队列）**：仅在有内容时显示，最多显示 1 条 + "还有 N 条"。每条含：Agent 的提议、一句话理由、影响、`[同意] [不同意] [以后都这样]`。
6. **今日已发生 / 待发生**：紧凑列表，每条一行，含时间、动作、原因摘要、状态（已执行 / 已修正 / 已放弃）。
7. **下一页入口**：查看完整计划 / 查看决策日志。

**关键交互**

- 点击时间线上任一时段 → 侧边抽屉展开 L1 一句话解释，抽屉内可继续进入 L2/L3。
- 点击"需要你决定"的任一项 → 全屏确认页（不弹模态，避免误触）。
- 长按/点击结论卡的任一格 → 显示该数字的构成（可回溯原则 P6）。

**必须覆盖的状态**

- 影子期（收益数字标记为"如果按我说的做"）
- 自动模式正常
- 保守降级（顶部标识 + 原因 + 恢复条件）
- L2 待确认（≥1 条）
- 电价数据源失效（能量流置灰 + 时间线仅显示历史）

## 4.2 计划（Plan）

**页面目标**：把"今天电池该怎么用"变成一张一眼能看懂、可以质疑、可以推翻的表。

**关键元素**

1. **计划头**：日期 + 天气（文字，不用图标代替信息）+ **三问数字**（预计净收益 / 明早备用余量 / 本次循环消耗）。
2. **24 小时计划图**：横轴 24h。三条轨道：
   - 轨道 A：电价曲线（含电网费叠加开关）
   - 轨道 B：计划动作（充电 / 放电 / 待机 / 光伏优先），色块表达，高度表达功率
   - 轨道 C：电量变化曲线（百分比，右轴）
   - 鼠标悬停显示该时段的完整依据。
3. **计划动作表**：`时段 | 做什么 | 电量变化 | 原因`，原因必须落到用户能理解的因果关系。
4. **我主动放弃的机会**：本页最有价值的一栏。至少 1 条，含放弃的动作、理论上能赚多少、为什么不做的具体原因、以及"如果你希望我做，点这里"。
5. **电网费视角切换**：一个开关，打开后电价曲线叠加输配电费第二信号，并高亮"两条曲线方向相反"的时段。
6. **计划操作**
   - `[接受这个计划]`（自动模式下为"计划已生效，撤销"）
   - `[我要调整]` → 只给方向性选项：更省钱一点 / 更保险一点 / 多留点备电 / 今晚别充，**不暴露参数**
   - `[明天按老办法来]`
   - `[锁定这一天的计划]`（锁单）
7. **日内修正记录**：每次修正的时间、原因、幅度、是否需要告知。区分"静默修正"与"已告知"。
8. **数据可信度条**：光伏预报置信度、电价数据来源与更新时间；置信度低时明确说"这个时段的判断不可靠，我采用了保守策略"。

**关键交互**

- 调整采用方向性滑杆（省钱 ←→ 保险），实时重算并显示收益/备电的变化对比。
- 锁单后在时间线上出现锁形标识（**矢量图标，非 emoji**）。
- 任一动作行点击 → 展开 L2 解释。
- 计划被安全原因覆盖时，覆盖处必须显示"我改了这个计划，因为……"。

**必须覆盖的状态**

- 影子期（`[接受这个计划]` 变为 `[我会照这个做]`，不产生实际动作）
- 计划已锁单
- 计划被安全事件覆盖
- 光伏预报置信度低（保守策略声明）
- 电价数据缺失（只显示电价未知时的安全计划）

---

## 4.3 决策（Decisions）

**页面目标**：把黑盒变白盒，让用户敢开自动、敢长期用。

**关键元素**

1. **决策日志列表**：按日期倒序，每条含时间、动作、收益影响、是否被推翻、是否被人工接管。支持按类型（充电/放电/弃权/降级/修正）与结果筛选。
2. **单条决策详情（三层解释）**
   - **L1 一句话**：大字号结论句。
   - **L2 展开**：为什么是这两个小时？其他时段为什么不选？电网费怎么算进去的？我放弃了什么？——每问一段，带证据（曲线、数字、来源）。
   - **L3 深挖**：与上周对比 / 与"什么都不做"对比 / 与"理论最优"对比；历史同类决策；事后实际结果与偏差。
3. **决策依据卡**：电价、电网费、天气、家庭画像、电池状态、用户偏好，六项各一行，标注数据来源与时间戳。
4. **推翻入口与分流**：`[这个决定我不同意]` → 必问"这次是例外，还是以后都这样？"
5. **导出**：单条 / 区间导出（CSV/PDF），含口径说明。

**必须覆盖的状态**

- 无决策记录（空状态）
- 决策被用户推翻（显示推翻原因与后续影响）
- 决策被人工接管（显示接管人、时间、处置）
- Agent 声明"我不知道"（数据不足时的保守决策）

## 4.4 家庭（Household）

**页面目标**：让用户在第一天就体会到"它能被我说了算"，而不是"它在替我决定"。

**关键元素**

1. **画像卡**：用大白话写的条目列表。**必须视觉区分"确定的事实"与"我的猜测"**，猜测条目带一键否认。
   - 例：*平日上午 9 点到下午 5 点基本没人在家，基础用电约 0.3 kW*（事实）
   - 例：*你周末可能经常外出*（猜测，带 `[不对]`）
2. **24 小时用电曲线**：基线负荷 + 大功率设备叠加，支持 工作日/周末/假期 与 夏/冬 切换，可与光伏发电曲线同屏对照。
3. **大功率设备清单**：名称、典型启动时段、持续时间、用电量、**可移动性**（可挪 / 建议挪 / 不可挪）。
4. **光伏特征**：朝向、遮挡、季节差异、阴天表现、冬季发电截止时间。
5. **停电风险画像**：所在区域过去 N 次停电的时间与时长分布；对应的备电策略保守程度。
6. **纠正入口**：`[全部正确]` / `[我要修改]`。修改后立即反馈"我会怎么变"。

**必须覆盖的状态**

- 冷启动（数据不足，画像条目少于 5 条，显示"我还在学"）
- 画像漂移告警（家庭用电模式发生结构性变化）
- 用户否认猜测后的更新反馈

---

## 4.5 电池（Battery）

**页面目标**：把"电池会不会早衰减"这件让人焦虑的事，变成一本看得懂的账。

**关键元素**

1. **健康概览**：寿命消耗进度、健康度趋势（近 12 个月）、当前温度与单体温差、累计等效满循环。**默认用"预计还能用 X 年"表达**，百分比折叠在细节里。
2. **循环预算账本**：本月 / 本季 / 本年，已用 / 剩余 / 按当前用法预计可用年限。预算过半时页面顶部出现提示条。
3. **护栏清单**（分两组，视觉上明确区分可改与不可改）

| 分组 | 项目 | 表述方式 |
|---|---|---|
| **你可调整** | 停电时够用多久 | 4 / 8 / 12 / 自定义 小时（**不出现 SOC 百分比**） |
| | 最少留多少电 | 用"保护电池"的强度档位表达 |
| | 要不要充满 | 用"给明天的太阳能留点空间"表达 |
| | 电池寿命保护强度 | 宽松 / 平衡 / 保守 |
| | 多小的便宜值得动手 | 用"为几毛钱不值得伤电池"的档位表达 |
| **系统强制（不可调整）** | 温度与功率保护 | 说明为什么不能改 |
| | 电网指令遵从 | 同上 |
| | 安全参数（电压 / 保护阈值 / 并网参数） | 明确写"管家永不可触碰" |

4. **红线变更流程**：从清单点任一可调整项 → 显示"这会改变什么"（收益预估变化 + 风险变化）→ 提交 → **L3 审批状态**（待批 / 已生效 / 被驳回）→ 留痕。
5. **告警与保护状态**：当前是否有保护性限制生效，生效原因与预计解除时间。

## 4.6 收益（Reports）

**页面目标**：给用户一个**可验证**的结果，否则所有解释都只是说法。

**关键元素**

1. **四栏对照表**（核心）

| 对照对象 | 本月电费 | 差额 | 说明 |
|---|---|---|---|
| 什么都不做（没有光伏和电池） | €185 | — | 基准 |
| 出厂默认策略 | €121 | 省 €64 | 硬件本身的价值 |
| **管家 Agent 调度** | **€108** | **再省 €13** | **本产品创造的价值** |
| 理论最优（事后回看） | €101 | 还有 €7 空间 | 诚实披露上限 |

2. **收益拆解**：光伏自用节省 / 低价充电节省 / 高价放电节省 / 电网费规避 / **效率损失（负）** / **电池循环折旧（负）** / 税费与上网费用影响（负） / **净收益**。正负项在视觉上必须区分。
3. **趋势**：月 / 季 / 年切换，显示净收益与与出厂策略的差额。
4. **合同体检**：一句话结论 + 依据摘要 + "仅供参考，不构成推荐意见"标注。
5. **口径说明**：默认折叠，但必须存在且可展开；随报告一同呈现假设条件。

**必须覆盖的状态**

- 首月（数据不足，只给部分拆解并说明）
- 报告中出现异常月份（收益转负）
- 与理论最优的差距扩大（诚实披露）

**三条诚实原则（不可妥协）**

1. 必须计入效率损失与电池折旧。只报毛价差是欺骗，会在用户对账时崩塌。
2. 必须披露与理论最优的差距。
3. 宁少报不多报。

## 4.7 异常（Incidents）

**页面目标**：让"人机交接"有标准物，人工不必从零排查。

**关键元素**

1. **事件列表**：按 L0–L3 分级标签 + 时间 + 一句话摘要 + 当前状态（处理中 / 已闭环 / 待你确认）。L0 默认折叠。
2. **事故简报（六要素固定格式）**
   1. 发生了什么（时间线，人话叙述）
   2. 我的判断与依据（当时的电价、天气、设备状态）
   3. 我做了什么（已执行的处置）
   4. 现在的状态（当前电量、备电可用时长、设备状态）
   5. 建议动作（我建议你怎么做）
   6. 需要谁决策（用户 / 安装商 / 沃太售后）
3. **处置时间线**：从触发到闭环的完整时间轴，标注每一步是谁做的（Agent / 用户 / 安装商 / 售后）。
4. **闭环回写**：`[这是一次性问题]` / `[这是系统性问题]` → 后者升级为规则变更任务。
5. **恢复汇报**：人工处理完成后，Agent 必须主动汇报"我已经恢复了，接下来我会这样做"。

**分级处置表**

| 级别 | 判定 | Agent 动作 | 通知谁 | 时限 |
|---|---|---|---|---|
| **L0 静默** | 小偏差、瞬时抖动 | 静默修正，记日志 | 无 | — |
| **L1 告知** | 收益异常、画像漂移、循环预算过半 | 继续运行，记入日报 | 用户（日报/周报内） | 24 小时内 |
| **L2 请示** | 需触碰备电预留边缘、需超额动用循环预算、电价数据源失效 | **降级为保守模式**，等待确认 | 用户（推送）+ 安装商（后台可见） | 同步 |
| **L3 紧急** | 停电、电池告警、SOC 异常跳变、安全相关 | **立即切安全模式**，停止一切优化 | 用户 + 安装商 + 沃太售后 | 立即 |

## 4.8 协作（Collaborate）

**页面目标**：把"人定边界、Agent 在边界内自主"这条立场变成可操作、可留痕的界面。

**关键元素**

1. **权限分级矩阵**（可视化三栏对照）

| 级别 | 定义 | 具体事项 | 谁决定 |
|---|---|---|---|
| **L1 Agent 自主** | 在已批准的偏好和红线内直接执行，事后告知 | 每日充放电时间点安排与微调；日内小幅修正；数据缺失时切安全模式；生成日报周报；画像日常更新 | **Agent** |
| **L2 事前确认** | Agent 提出，用户一键确认后执行 | 首次启用某类策略；单次动作临时突破常规但仍未越过红线；启用新电价产品；启用一次需求响应奖励；打开"自动执行" | **用户（一键）** |
| **L3 人工专属** | Agent 只能建议和准备材料，不能执行 | 修改备电预留与最低电量红线；调整循环预算上限；修改"省钱/备电/护电池"权重；涉质保、安全参数、并网参数的变更；批量策略调整；客诉答复 | **人（并留痕）** |

2. **待你确认（L2 队列）**：卡片列表，每条含提议 / 理由 / 影响 / 三个按钮（同意、不同意、以后都这样）。
3. **人工专属操作（L3）**：申请列表 + 审批状态 + 审批人 + 生效时间。
4. **操作留痕表**：时间、操作人、级别、改了什么、为什么、影响范围。可导出。
5. **协作节奏日历**：日 / 周 / 月 / 季 的交互一览，标注是否推送。
6. **季度复核向导（T5）入口**：五问流程 + 新版偏好产出 + 与上一版差异对比。

**设计检验标准**

- L1 的事必须让用户感觉"我不用管"；
- L2 的事必须少到不烦人（**如果 L2 每天弹出，产品就是失败的**）；
- L3 的事必须由用户主动发起或每季度一次，绝不能高频打扰。

## 4.9 引导（Onboarding）

### T1 · 冷启动"三问定调"（10 分钟内完成，单屏）

**问 1：你更在意什么？** 三选配比滑杆（**三个都想要**，所以是配比而非单选）
- 把电费省下来 / 停电时不慌 / 电池用得久一点
- 默认配比：省钱 40% / 备电 40% / 护电池 20%

**问 2：停电时，你最需要保证什么？** 用生活语言问
- 冰箱 + 照明 + 网络（基础）：4 小时 / 8 小时 / 12 小时
- 还有别的必须保证的设备吗？（医疗设备、居家办公、鱼缸加热）
- **用户不填 SOC，Agent 自己换算成预留值。"备电预留比例"这个词永远不出现在用户界面。**

**问 3：你希望我多主动？**
- 只给我建议，我自己决定要不要按（最保守）
- 帮我自动执行，但每次都告诉我（推荐）
- 帮我自动执行，有异常再找我（最省心）

**设计要点**

- 三问必须在**一屏内**完成，不能有"下一步"的层层跳转。
- 所有默认值都要保守，面向"省心型"用户。
- 允许"以后再说"，未回答部分用最保守默认值。
- **第一次打开不要求用户授权自动执行**，先进入影子期。

### T2 · 影子期（建议 14–28 天）

**做法**：Agent 只出计划、不执行。每天推送"如果按我说的做，今天会怎样"，次日给出一句对照。

**关键元素**

1. 影子期进度条 + **明确的结束日期** + "什么时候可以开始自动"。
2. 建议 vs 实际对照表：逐日列出"我建议做什么 / 实际发生了什么 / 差多少钱"。
3. 影子期小结：如果一直按建议做，这段时间会省多少。
4. `[现在就开始自动]`（可主动跳过，但不能自动跳过）与 `[再观察一段时间]`。

**文案要求**：不制造焦虑。避免"你就这样浪费了两周"，改为"接下来我可以帮你把这些省下来"。

## 4.10 市场（Markets）

**页面目标**：让"进入一个新市场"从研发排期变成运营配置。

**关键元素**

1. **市场列表**：国家/地区、电价机制类型、电网费机制、上网规则、当前策略包版本、活跃用户数、健康状态。
2. **策略包详情**：电价机制（固定/分时/动态小时级/动态 15 分钟级/阶梯）、电网费机制（是否分时、容量费/需量费、可控负荷减免档位及其代价）、上网规则（是否允许、费率、是否划算、限制）、需求响应机会、补贴与合规约束、当地默认红线（弱电网地区默认备电更高）。
3. **规则变更提醒**：变更条目 + 影响的存量用户数 + "触发复核"动作。
4. **全局熔断开关**：远程一键停用某市场的自动调度 + 通知所有受影响用户。**这个开关的存在本身就是产品成熟度的标志。**

## 4.11 安装商视图（Installer）

**页面目标**：让安装商不再充当人工调度员。

**关键元素**

1. **客户列表**：客户名、系统容量、当前模式、近 7 日异常数、待办数、最近联系时间。支持按"有异常 / 有 L2 待确认 / 收益异常"筛选。
2. **客户详情**：当前策略与红线 / 近 30 日决策日志 / 异常记录 / 收益走势 / 家庭画像摘要。
3. **远程支持工具**：与出厂策略对比、导出决策日志、一键回退出厂策略、生成客户沟通话术。
4. **工单与跟进**：来源（客户来电 / 系统告警）、状态、负责人、处置记录。

**硬约束**：安装商**不能**直接修改客户红线（属 L3），只能发起申请或引导客户自行操作。

## 4.12 设置（Settings）

**关键元素**

1. **偏好**：省钱 / 备电 / 护电池 配比（修改属 L3，需确认流程）。

# 第五章 运行状态机

> v1.0 多处提到"降级""安全模式""影子期"，但没有定义它们之间的关系。本章把它们定义成一个**有限状态机**，这是产品行为可预测、可测试的基础。

## 5.1 六个运行模式

| 模式 | 含义 | Agent 是否产生实际调度动作 | 用户可见标识 |
|---|---|---|---|
| **影子期 Shadow** | 只出计划、不执行 | 否 | 灰色条："我在学习，只看不做" |
| **建议模式 Advisory** | 出计划，用户确认后执行 | 仅用户确认后 | 蓝色条："我建议，你决定" |
| **自动模式 Auto** | 护栏内自主执行，事后告知 | 是 | 强调色条："我在按你的规则自动安排" |
| **保守模式 Conservative** | 只做最保守的动作（自发自用 + 备电优先） | 是，但范围受限 | 琥珀条：原因 + 恢复条件 |
| **安全模式 Safe** | 停止一切优化，回到硬件安全默认 | 否（交回设备默认行为） | 红色条：原因 + 需要谁处理 |
| **人工接管 Manual Hold** | 人工正在处理，Agent 完全静默 | 否 | 红色条：接管人 + 开始时间 |

## 5.2 状态迁移

```
                      ┌─────────────────────────────────────┐
                      │                                     │
   首次开通            完成三问                 用户主动开启     │
   ──────►  Shadow ──(影子期结束/主动跳过)──► Advisory ────► Auto
              ▲                                  ▲  │         │
              │                                  │  │用户降级  │
              │                                  │  ▼         │
              │                             (用户选择)      (护栏触发)
              │                                  │  │         │
              │                                  │  └────────►│
              │                                  │            ▼
              └──── 影子期不可自动跳过 ───────────┘       Conservative
                                                            │  ▲
                                            (护栏恢复/用户确认)│  │(数据失效/触碰红线)
                                                            ▼  │
                                                          Safe ◄┘
                                                            │
                                              (人工介入处置) │
                                                            ▼
                                                       Manual Hold
                                                            │
                                              (处置完成 + 恢复汇报)
                                                            ▼
                                          回到 Conservative（不直接回 Auto）
```

## 5.3 迁移规则表

| 从 | 到 | 触发条件 | 是否通知用户 | 通知方式 |
|---|---|---|---|---|
| Shadow | Advisory | 影子期结束（默认 14 天）或用户主动提前开启 | 是 | 影子期小结页 |
| Shadow | Auto | 用户主动选择"帮我自动执行" | 是 | 确认页 |
| Advisory | Auto | 用户主动开启自动执行（L2） | 是 | 确认页 + 留痕 |
| Auto | Advisory | 用户降级 | 是 | 设置页确认 |
| Auto/Advisory | Conservative | 触碰备电预留边缘 / 需超额动用循环预算 / 电价数据源失效 / 循环预算过半 | 是（L2 请示） | 推送 + 安装商后台可见 |
| Auto/Advisory | Safe | 停电 / 电池告警 / SOC 异常跳变 / 安全相关 | 是（L3 立即） | 多通道通知 |
| Conservative | Safe | 降级期间再次触发更高级别事件 | 是 | 多通道通知 |
| Safe | Conservative | 告警解除且数据源恢复 | 是 | 恢复汇报 |
| 任意 | Manual Hold | 人工介入处置 | 是 | 接管通知 |
| Manual Hold | Conservative | 人工处置完成 | 是 | Agent 主动汇报"我恢复了，接下来我会这样做" |
| Conservative | Auto | 仅在**用户明确确认**后 | 是 | 确认页 |

**硬规则**

1. **任何降级都不得静默发生。** 用户必须能随时知道"系统现在不在全自动状态"。
2. **人工接管期间 Agent 必须完全静默**，不得继续执行优化动作，避免与人工操作打架。
3. **安全模式不自动回到自动模式**，必须经过人工确认。宁可多问一句。
4. **影子期可以主动跳过，但不能自动跳过。**

## 5.4 全局熔断

当某市场出现系统性异常（如策略包缺陷导致多户收益转负）时，必须支持**远程一键停用该市场的自动调度**，并通知所有受影响用户。

- 影响范围 > 50 户的规则变更：必须经护栏复核人批准 + 灰度 + 回滚预案。
- 熔断触发后，受影响用户统一进入 Conservative，并收到说明。

# 第六章 关键业务规则

## 6.1 三角权衡：什么时候才该动手

**核心判据**：

> 一次套利动作只有在 **预期净收益 > 电池折旧成本 + 备电保险价值** 时才值得做。

| 项 | 内容 | 谁决定 |
|---|---|---|
| **预期净收益** | （高价时段放电单价 − 低价时段充电单价）× 电量 × 往返效率 − 网费与税费影响 | 算法算，市场定 |
| **电池折旧成本** | 本次动作消耗的等效满循环 × 每循环折算成本 | 电池参数 + 用户风险偏好 |
| **备电保险价值** | 本次动作占用的备用电量的机会价值，与停电风险正相关 | 用户偏好 + 区域停电历史 |

**关键洞察**：**备电保险价值不是常数**，它随天气、季节、区域电网状况浮动。台风季、极端高温、电网检修期的保险价值明显更高。所以"雨季/灾害季自动提高备电预留"应当是**一个默认开启的机制**，而不是等用户想起来的设置项。

**示例算例（数字为示意，需实测标定）**

- 峰谷价差 €0.25/kWh，往返效率 90% → 每放电 1 kWh 的毛收益 ≈ €0.225
- 减去电池折旧（示例 €0.06/kWh）
- 减去网费/税费影响（示例 €0.02/kWh）
- 净收益 ≈ **€0.145/kWh**

→ 因此收益门槛建议设在 **€0.15/kWh 价差** 附近。**低于这个门槛的"机会"，Agent 应当主动放弃并向用户说明。**
→ **该门槛对用户表现为档位**（"为几毛钱不值得伤电池"），不暴露具体金额。

## 6.2 收益计算口径（对外必须一致）

```
净收益 = 光伏自用节省
       + 低价充电节省
       + 高价放电节省
       + 电网费规避（网费减免 / 避免容量费）
       − 往返效率损失
       − 电池循环折旧
       − 税费与上网费用影响
```

**与谁比**：必须明确基线，且至少给出两个对照——"出厂默认策略"（衡量产品增量价值）和"什么都不做"（衡量整体价值）。

**对外披露纪律**

- 不得单独宣传毛价差；
- 不得使用"最高可省"这类上限表述作为主口径；
- 必须同时披露"与理论最优的差距"；
- 所有对外数字必须标注假设条件。

## 6.3 循环预算的记账方式

**为什么要记账**：电池的寿命是用循环消耗的。套利本质上是在**用电池寿命换电费**。如果不记账，用户省下的电费可能不够覆盖电池提前衰减的损失——那这个产品就是在坑客户，也会引发质保争议。

**记账规则**

1. 把每一次充放动作按其深度折算成**等效满循环**（放掉 30% 电量记为 0.3 个等效循环）。
2. 分**月度预算**和**年度预算**两层。
3. 预算默认值来自电池循环寿命参数与用户选择的"护电池"强度。
4. **每个动作执行前先查预算余额**：余额不足则不执行，并说明"这个月为了护电池，我不建议再做额外套利了"。
5. **预算消耗过半时提前告知用户**，让用户有心理准备，而不是月底突然降级。
6. **预算可被用户临时突破**，但必须走 L2 确认流程，且明确告知对电池寿命的影响。
7. **质保口径预留**：记账数据必须可作为质保争议的证据（记录温度、深度、次数）。

## 6.4 弃权清单：什么情况下宁可放弃套利

1. 预期净收益低于收益门槛；
2. 动作会触碰或逼近备电预留；
3. 电池处于不利温度区间，或近期健康度下降异常；
4. 电价与电网费信号方向相反（省了电价但多付了网费，净亏）；
5. 当地不允许或极不划算的上网行为；
6. 电网发出限功率或需求响应指令；
7. 预报不确定性过高（极端天气、光伏预报置信度低）；
8. 用户临时外出但家中留有需要供电的设备（医疗设备、宠物、安防）；
9. 循环预算余额不足；
10. 用户已"锁单"当天计划。

> **产品要求**：以上每一条弃权都要在计划表中**以人话说明**。**弃权不是沉默，弃权是必须解释的动作。**

## 6.5 Agent 自主边界之外（必须人工的事）

- 修改备电预留、最低电量红线、循环预算上限（属 L3）
- 调整"省钱 / 备电 / 护电池"的权重
- 启用需求响应、参与任何形式的电力市场交易
- 接入新的电价产品 / 变更零售商
- 任何涉及质保承诺、安全参数、并网参数的变更
- 对客户投诉的最终答复
- 影响多个家庭的策略变更（必须人工批准后统一发布）
- 超出既定范围的任何"创新"动作

> **Agent 产品的最大风险不是它做得不好，而是它做了没人授权它做的事。自主边界必须在文档层面写死。**

## 6.6 反面清单：Agent 明确不该做的事

1. 不为了小额价差频繁循环电池。收益门槛必须存在。
2. 不擅自突破备电预留。这是不可协商项。
3. 不在用户未授权时切换模式。
4. 不用专业术语轰炸用户。界面上不出现 SOC、DoD、kW/kWh 裸数值（除非用户主动展开深水区）。
5. 不在深夜推送非紧急通知。
6. 不承诺收益数字，不用"保证省 XX 元"的表述。
7. 不绕过电网运营商的限制，不做当地不允许的并网行为。
8. 不在数据缺失时凭猜测运行，一律降级到安全模式。
9. 不把用户的一次临时操作当成永久偏好（必须问"例外还是规则"）。
10. 不在人工接管期间继续自主行动。
11. 不做超出授权范围的"聪明事"。哪怕逻辑上更优，没授权就不做。
12. 不在用户放弃套利选择保守时表达不满或反复劝说。用户选了就执行。

## 6.7 通知规范矩阵

| 场景 | Agent 的行为 |
|---|---|
| 常规充放电、计划内动作 | **沉默**（只在日报里提） |
| 预测小偏差、已在阈值内的修正 | **沉默**（记日志） |
| 单日收益明显低于预期、画像被显著修正、循环预算过半 | **低优先告知**（日报/周报内，不推送） |
| 触碰备电预留边缘、需超额用循环预算、电价数据源失效 | **必须请示**：降级 + 推送，等用户确认 |
| 停电、电池告警、SOC 异常跳变 | **立即叫人**：切安全模式 + 多通道通知 |
| 用户明确提出要求（无论是否合理） | **立即响应**：先执行用户意愿（在安全边界内），再解释风险 |
| Agent 自己不确定 | **声明不确定**，采用保守策略，并告知用户 |

**一条容易忽略的规则**：当用户明确要求某事、而 Agent 认为不明智时，**Agent 应当先照做（只要不越过安全红线），然后把风险和理由讲清楚**。用户有最终决定权——这不是技术妥协，是产品立场。**如果 Agent 会拒绝主人，用户就不会把它当自己的管家。**

## 6.8 协作节奏日历

| 频率 | 交互 | 谁发起 | 是否推送 |
|---|---|---|---|
| **每日** | 次日计划（傍晚推送）；当日执行结果（次日早晨简讯，可关闭） | Agent | 是（可关） |
| **每周** | 周报（收益、异常、画像变化） | Agent | 否，App 内可查 |
| **每月** | 账单对照报告（四栏对照 + 归因 + 合同体检） | Agent | 邮件/App，一次 |
| **每季** | 策略复核向导（T5） | Agent 发起 + 人参与 | 是，需用户安排时间 |
| **随时** | 异常接管（T4）；用户主动查看与质疑 | 双方 | 按级别 |
| **事件驱动** | 市场规则变更、电价合同到期、设备告警 | Agent | 按级别 |

## 7.4 数据一致性硬规则

# 第八章 人机协作机制的落地机制

> 这是本产品的灵魂章节。功能可以被抄，协作机制决定了用户会不会长期留下来。

## 8.1 四条协作原则

1. **人定边界，Agent 在边界内自主。** 人不参与日常执行。每一次"让用户点一下"都是在消耗他的耐心，必须证明这个点击的必要性。
2. **一切自主决策可解释、可回溯、可推翻。** 决策日志对用户永久开放。
3. **Agent 只对"钱和舒适"负责，绝不替人做承诺。** 不签合同、不承诺收益、不改变质保、不代替用户与电网或零售商交涉。
4. **不确定时降级，而不是冒险。** 宁可少赚，不可失责。

## 8.2 五个关键协作触点

| 触点 | 名称 | 目标 | 详见 |
|---|---|---|---|
| **T1** | 冷启动"三问定调" | 10 分钟内完成，不填技术参数 | §4.9 |
| **T2** | 影子期（14–28 天） | 把黑盒变白盒，零风险验证 | §4.9 |
| **T3** | 计划审批与"锁单" | 一天一张计划，可接受/调整/按老办法来 | §4.2 |
| **T4** | 异常接管 | 标准交接物，人工不从零排查 | §4.7 |
| **T5** | 季度策略复核 | 30 分钟，人做立法者的制度化落地 | §4.8 |

## 8.3 五个触点的详细规格

### T3 · 计划审批与锁单（补全 v1.0）

- **推送时机**：本地时间每天傍晚（17:30–18:30，因人而异，可配置）。电价曲线通常已确定，家庭方便看一眼，不打扰睡眠。**禁止深夜推送非紧急通知（23:00–07:00）。**
- **三种响应**：接受 / 我要调整 / 明天按老办法来。
- **默认可自动接受**：已授权"自动执行"时，计划默认自动生效，推送只是告知；用户可在生效前撤销。
- **锁单**：可锁定某一天或某段时间（如"假期期间别动"）。锁定期间 Agent 只在安全原因下覆盖，且必须告知。
- **调整的粒度必须简单**：只提供"更省钱一点 / 更保险一点 / 保持备电更多"这类方向性调整，**不暴露参数**。深水区用户可在设置里展开参数，但默认折叠。

### T5 · 季度策略复核（五问）

1. **本季收益复盘**：实际净收益、与上一季对比、与理论最优的差距、钱省在哪。
2. **循环预算消耗**：本季用了多少循环预算、剩余多少、按当前用法电池预计能用多久。
3. **备电体检**：本季有没有停电、备电是否够用、是否需要提高预留。
4. **合同体检**：当前电价合同是否仍是好选择、市场规则有无变化。
5. **偏好复核**：省钱/备电/护电池的配比是否要调整、有没有新的家庭变化（买电动车、添了孩子、装了热泵）。

**产出**：一份**新版偏好与红线**，用户确认后生效，并**明确告知与上一版的差异**（"这次你主要改了什么，我会怎么变"）。

> **重要性**：这是"人做立法者"这个定位的唯一制度化落地。**没有季度复核，产品就会退化成另一个"设完就忘"的手动模式。**

## 8.4 解释与信任的机制化设计

信任不能靠文案，要靠机制。

| 机制 | 作用 |
|---|---|
| 每一次动作都能回答"为什么" | 消除黑盒感 |
| 主动披露放弃的机会 | 消除"它是不是漏了"的怀疑 |
| 不确定时明说，给区间不给假精度 | 避免事后被指"你当时说得那么肯定" |
| 允许说"我不知道" | **编造理由是最严重的信任事故** |
| 推翻时问"例外还是规则" | 避免越学越偏 |
| 决策日志永久可查、可导出 | 用户和安装商都能事后对账 |
| 收益按净额口径报告（扣效率损失与折旧） | 对账时不会崩 |
| 季度复盘主动找用户 | 不让"设完就忘"发生 |
| 第一年以保守优先，不追求收益极限 | 用确定性换信任 |

## 8.5 被推翻之后的强制分流

用户推翻一个决策时，Agent 必须问一句：

> **这次是例外，还是以后都这样？**
> `[就这一次]`　`[以后都按我说的来]`

- 选"就这一次" → 记为一次性例外，**不修改规则**；
- 选"以后都这样" → 进入规则变更流程，若涉及红线变更则走 L3 审批。

> **这个分流动作是整个 Agent 学习机制的关键。** 绝大多数"智能产品"的失败都是因为把用户的一次临时操作当成了永久偏好，从此越用越偏。

# 第九章 风险、合规与责任边界

## 9.1 责任矩阵（必须在项目启动前定稿）

| 情形 | 责任归属 | 依据与前提 |
|---|---|---|
| Agent 在用户授权范围内的正常自主决策造成的收益偏差 | **沃太承担服务责任**，但不承担收益承诺 | 用户协议需明确"不保证收益" |
| 用户主动覆盖或突破 Agent 建议造成的后果 | 用户知情同意，**留痕** | L2/L3 操作留痕机制 |
| 设备故障、电池告警、硬件质量问题 | **沃太硬件质保责任** | 既有质保体系 |
| 电价/天气等第三方数据错误导致的决策失误 | 数据供应方责任；**沃太需证明已有多源校验与降级策略** | 数据失效必须降级，不得凭猜测运行 |
| 用户按不符当地规则的方式使用（如违规上网） | 沃太需在配置层面阻止 | 市场策略包内置合规约束 |
| 参与电力市场交易/需求响应 | **须另行取得资质或通过持牌合作伙伴**，本期不做 | §1.6 边界 |
| 停电时备电不足引发损失 | **视情形**：若因 Agent 占用备电导致，沃太承担；若因设备故障或极端情形，按质保条款 | **所以备电预留必须做成不可侵占的硬约束** |

## 9.2 合规要点

- **电力市场资质**：家庭侧自用优化与"对外售电/参与市场交易"是两件事。后者通常需要成为市场参与者或通过聚合商/持牌方，**本期严格限定在前者**。
- **电网接入规则**：各市场的并网、限功率、防逆流、可控负荷要求必须内置在策略包中，**由系统强制，不可被 Agent 绕过**。
- **电池法规与循环数据**：欧盟电池法规对碳足迹、电池护照、循环数据与可追溯性有要求。循环记账数据**可成为合规资产**，设计时应保证数据完整性与可导出性。
- **数据隐私**：家庭用能曲线可以推断出"家里有没有人""作息习惯"，属于敏感信息。必须做到：明确授权、最小必要、可撤回、可删除、区域存储合规、脱敏后再用于分析。
- **消费者保护**：不得在营销中使用收益承诺；收益报告的假设条件必须随报告一同呈现；用户必须能随时关闭自动化并收回授权。

## 9.3 安全与售后风险

- 所有安全相关参数（电压、保护阈值、并网参数）**完全在 Agent 的作用范围之外**；
- 电池告警一律优先于经济性优化；
- 数据源失效、通信中断时必须降级，**不允许"最后已知值"继续驱动调度**；
- 任何自动调度都必须提供一个"一键停止并回到出厂策略"的开关，且该开关必须在 App 首页可达。

## 9.4 回退设计

- **一键回退**：用户随时可退回到出厂策略，且回退**不影响**历史数据与收益记录；
- **自动降级**：护栏触发、数据失效、异常告警时自动回退到安全默认，并告知用户；
- **全局熔断**：见 §5.4。

## 9.5 风险登记表

| 风险 | 后果 | 应对 |
|---|---|---|
| 电池提前衰减 | 省的电费不够换电池，品牌灾难 | 循环预算硬约束 + 折旧计入收益口径 + 温度保护 |
| 解释不清导致用户关掉功能 | 投入无法兑现，退化回出厂策略 | 影子期 + 主动披露放弃项 + 季度复盘 |
| 一次备电失守 | 单个用户的口碑事故，且可能引发索赔 | 备电预留为硬约束，任何优化不可侵占 |
| 收益不及用户预期 | 首月报告被质疑，信任崩塌 | 净额口径、宁少报不多报、披露与最优的差距 |
| 市场规则变化快，跟不上 | 策略失效，收益转负 | 必须配置专职策略运营；规则变更触发存量复核 |
| 电价数据源被限制或收费 | 核心输入失效 | 多源备份 + 用户手动导入兜底 + 数据失效时降级安全模式 |
| 责任边界不清 | 出事后三方推诿，用户只找沃太 | §9.1 责任矩阵前置定义并写入用户协议 |
| 定价不被接受 | 用户不愿为"本来以为该免费"的功能付费 | 首年随硬件赠送/订阅捆绑，第二年再验证订阅意愿 |

| 顺序 | 市场类型 | 理由 | 产品形态 |
|---|---|---|---|
| 1 | **德国（首选）** | 动态电价合同成熟、户储保有量大、电网费机制复杂（正好体现"双信号融合"的价值） | 完整版 |
| 2 | 英国、澳洲 | 动态电价与需求响应机制成熟；澳洲家庭对电池套利认知高 | 完整版 + 需求响应预留 |
| 3 | 意大利、荷兰、北欧 | 电价波动结构不同，验证策略包机制的可移植性 | 完整版 |
| 4 | 南非等弱电网市场 | 停电是常态，备电优先级高于套利 | **简化版：备电优先 + 有限套利** |
| 5 | 中国市场 | 以分时电价为主、缺乏零售侧动态电价 | **简化版：分时套利 + 备电 + 护电池** |

> **关键判断**：不要把德国版的默认值直接搬到弱电网市场。**南非用户的默认备电预留应当显著高于德国用户**——这类本地化默认值必须写进市场策略包。

## 10.2 组织与角色（本产品的隐性成本）

| 角色 | 职责 | 为什么必须有 |
|---|---|---|
| **产品负责人** | 定义偏好模型、护栏默认值、协作机制 | 决定产品立场 |
| **策略运营（新岗位）** | 跟踪各市场电力规则变化，维护市场策略包，触发存量用户复核 | **没有这个角色，产品半年后就失效** |
| **护栏复核人** | 季度复核陪跑、异常裁决、L2/L3 申请审批、规则变更把关 | 保证"人仍立法" |
| **客服/售后支持** | 按事故简报处置，维护话术，反馈系统性问题 | 人机交接的落地端 |
| **渠道赋能** | 培训安装商使用客户管家视图与季度复核流程 | 渠道是推广放大器 |
| **法务/合规** | 责任边界、用户协议、数据合规、市场资质 | 前置而非事后 |

## 10.3 关键 SOP

1. **事故简报模板**：六要素固定格式，所有人看同一套。
2. **客诉话术**："为什么半夜充电"必须有标准解释路径——先给当日电价曲线，再给收益对照，最后给出"你也可以改成备电优先"的选项。
3. **季度复核向导脚本**：五问固定，产出固定，差异对比固定。
4. **策略包发布流程**：任何影响多户的规则变更，必须经护栏复核人批准 + 灰度 + 回滚预案。
5. **收益口径文档**：对外一律使用同一套净收益口径，营销、客服、报告三处一致。

## 10.4 迭代节奏

| 阶段 | 交付 | 目标 |
|---|---|---|
| **MVP** | F1（轻量）+ F2 + F4 + F5 + F7（基础） | 单个市场（建议德国）跑通"影子 → 建议 → 自动"完整链路，验证用户是否敢用 |
| **V1** | F3 + F6 + F8 + 画像深化 | 提升收益、接入多市场、把收益证明做扎实 |
| **V2** | F9 + 需求响应联动 | 从调度工具变能源顾问，探索第二收入曲线 |

> **关键节奏判断**：MVP 阶段**不追求收益最大化**，追求**"用户敢开通自动模式并留住"**。收益是 V1 的事。

## 11.2 验收标准（原型级）

| 编号 | 验收项 | 判定方式 |
|---|---|---|
| A1 | 12 个页面全部可正常访问，无控制台报错 | 浏览器实测 |
| A2 | 每个页面均实现加载 / 空 / 降级三类状态 | 通过页面内的状态切换开关人工检视 |
| A3 | 全局运行模式标识在任意页面可见 | 切换模式后逐页检查 |
| A4 | 界面不出现 SOC / DoD / EFC / 裸 kW 术语（深水区展开除外） | 全文检索 |
| A5 | 界面不出现 emoji | 全文检索 |
| A6 | 所有预测值均带区间 | 数据检查 |
| A7 | 每个收益数字可点击查看构成 | 交互实测 |
| A8 | 弃权机会在执行计划中必有至少 1 条 | 数据检查 |
| A9 | 计划表可执行 接受 / 调整 / 按老办法 / 锁单 四种操作并更新状态 | 交互实测 |
| A10 | 护栏清单明确区分可调与不可调，L3 变更走审批流 | 交互实测 |
| A11 | 事故简报六要素齐全 | 内容检查 |
| A12 | 推翻决策时强制出现"例外还是规则"分流 | 交互实测 |
| A13 | 响应式：1440 / 1024 / 768 三档布局不破版 | 浏览器实测 |
| A14 | 键盘可达：所有交互元素可 Tab 聚焦且有可见焦点环 | 键盘实测 |

## 11.3 原型明确不做的事

- 不接入真实电价 / 天气 / 设备数据，全部为模拟数据。
- 不实现真实调度算法，只实现**业务规则的确定性演算**（护栏校验、收益口径、循环记账）。
- 不做用户体系与登录。
- 不做后端与持久化（状态保存在前端内存）。
