## 0. 边界、约定与口径

### 0.1 覆盖范围

**本模块负责**：护栏清单与逐项字段规格；多护栏冲突的判定顺序与解决规则；护栏触发后的统一处置（退出优化 → 切安全默认 → 事故简报 → 分级通知 → 日报告知）；循环预算账本（月/季/年三层、过半提醒、超支降级、用户临时突破的 L2 流程）；红线变更（L3）全流程与留痕；电池健康全部呈现规格；可作为质保证据的循环记账与导出字段；电池页完整状态矩阵与验收条件。

**本模块不负责**（只定义接口）：收益门槛的数值计算与归因（F6，本模块只消费档位）；24 小时计划排布算法（F2，本模块只输出"允许/禁止/需请示"）；事故简报的页面呈现与闭环回写（F7，本模块只生成数据）；三问定调（F1，本模块只把答案翻译成护栏初始值）；电压与并网参数的具体数值（硬件与安装商）。

### 0.2 架构约定：护栏引擎是运行模式的唯一写入方

总 PRD §5 定义了六个运行模式，但未指定谁有权切换。若多个模块各自降级，会出现"计划页显示自动、电池页显示保守"的状态撕裂。本模块规定：**护栏引擎**是进入 Conservative / Safe、恢复到 Conservative 的唯一入口；**用户**可在 Shadow / Advisory / Auto 之间主动切换（属 L2）；**人工（安装商 / 售后）**负责进入与解除 Manual Hold；**F2 计划引擎**只能**请求**降级，不能直接改模式。

### 0.3 术语与文案硬约束（覆盖本页全部文案与通知）

| 硬约束 | 说明 |
|---|---|
| **备电预留永远用"够用几小时"表达** | 清单、变更确认页、通知、日报、面向用户的报告与导出**一律不出现百分比、不出现 SOC 字样**。后台换算出的预留电量只存在于工程视图与质保证据包。 |
| **最低电量用"保护电池"强度档位表达** | 不出现百分比，不出现"下限"这类词。 |
| **循环用"电池用掉了多少寿命"表达** | 可写「用掉 14.2 次」，不出现 EFC 缩写。 |
| **不出现 emoji** | 全文、全界面、通知标题与图表标注均适用。 |
| **不出现裸术语** | 不出现 SOC / DoD / EFC / 裸 kW / 裸 kWh，深水区主动展开后除外。 |
| **预测必须带区间** | 「预计还能用 8 年」必须附区间，不给单点假精度。 |
| **不制造焦虑** | 禁止「你已经浪费了」「再不处理就晚了」这类句式。 |

**深水区例外声明**：计划页 §4.2 轨道 C 的"电量变化曲线（百分比，右轴）"是**电池总电量**的时间曲线，与备电预留不是同一个值，按总 PRD 保留；但该轴标题必须写「电池里的电」，不得写 SOC。

### 0.4 数字口径声明

本文所有金额、循环次数、温度阈值、年限均为**用于说明业务逻辑的示例假设**（依据总 PRD 数字口径声明与附录 B）。温度与功率上限必须由电池团队按电芯规格标定，质保口径必须经法务复核后方可对外使用。示例机型口径：可用容量 10 kWh；质保 10 年或 6,000 次等效满循环，以先到者为准；装机日期 2024-06-20。

## 1. 护栏清单的完整字段规格

### 1.1 分组、命名与字段模板

| 分组 | 界面标识 | 视觉处理 | 允许的操作 |
|---|---|---|---|
| **你可调整**（`group = user`） | 「你可以改」 | 实线边框卡片，行尾有「改」入口 | 走 §5 变更流程 |
| **系统强制**（`group = system`） | 「改不了，也不该改」 | 灰底、无操作入口、锁形**矢量图标** | 只提供"为什么不能改"的展开说明 |

命名规则：用户可读名称必须是生活语言；ID 采用 `GR-{U|S}-{两位序号}`，发布后不得复用或改义。每项规格必须包含九个字段（与 E20 对齐；标注「新增」的数据字段为本模块新增，需补进数据模型）：

| 字段 | 数据字段 | 说明 |
|---|---|---|
| 护栏 ID | `id` | 稳定标识 |
| 用户可读名称 | `name` | 生活语言 |
| 组别 | `group` | 你可调整 / 系统强制 |
| 当前值文案 | `currentValueLabel` | 档位文案 + 一行人话副行 |
| 可选档位 | `options`（新增） | 用户能选的值集合 |
| 变更所需级别 | `level` | L2 或 L3 |
| 收益影响话术 | `impactOnEarning` | 调整后大概多省/少省，必须给区间 |
| 风险变化话术 | `impactOnRisk` | 调整后什么变危险或变安全 |
| 为什么这么设 | `reason` | 写给用户看的理由，不是写给工程师看的 |

内部字段映射（`internalKey`，新增）只用于工程视图与质保证据包，**不得出现在任何面向用户的文案中**。

### 1.2 你可以调整的护栏（GR-U）

**GR-U-01 · 停电时够用多久**

- **组别与级别**：你可调整 · **L3**；内部映射 `backupReserveHours`（后台换算为预留电量，仅工程视图可见）
- **当前值文案**：「够你家基础用电 8 小时」；副行：「按你家最近 30 天晚上的基本用电折算，冰箱、照明、网络和安防能一起撑 8 小时。」
- **可选档位**：4 小时 ／ **8 小时（默认）** ／ 12 小时 ／ 自定义 2–24 小时（步长 1 小时）
- **收益影响话术**：调低 →「从 8 小时改成 4 小时：我每天能多拿出约 4 度电去赚价差，预计每月多省 €8–14（示例区间，实际取决于当月电价）。」调高 →「从 8 小时改成 12 小时：每天要多留一些电不动，预计每月少省 €8–14。」
- **风险变化话术**：调低 →「停电时你家的冰箱、照明和网络大约能撑 4 小时。如果停电正好发生在早晨电量偏低的时候，可能撑不满 4 小时。」调高 →「停电时更从容，但能拿去赚钱的电变少，省钱速度会慢下来。」
- **为什么这么设**：§2.6 把"备电失守次数"目标定为零次，§9.1 规定"若因 Agent 占用备电导致停电损失，沃太承担责任"。默认值取自冷启动三问第 2 题（冰箱 + 照明 + 网络，4/8/12 小时）；弱电网市场由策略包把默认值提高到 12 小时。
- **补充规则**：无论上调还是下调一律走 L3。若下调到**低于当地策略包默认值**，审批人必须是沃太护栏复核人，不能由家庭业主单独批准。

**GR-U-02 · 最少给电池留多少电（保护电池的强度）**

- **组别与级别**：你可调整 · **L3**；内部映射 `minSocFloor`
- **当前值文案**：「留得少一点」；副行：「电池每次可以放到更低，能多赚一点，但电池会比较吃力。」
- **可选档位**：「留得少一点」／**「标准（推荐）」**／「留得多一点」／「留得最多」
- **收益影响话术**：调松 →「从标准调到留得少一点：我每天能多放出一些电去赚价差，预计每月多省 €4–8。」调紧 →「从标准调到留得多一点：能赚钱的电变少，预计每月少省 €4–8。」
- **风险变化话术**：调松 →「电池每次会放得更深一点，长期看会加快老化。这一档我会同时盯住温度，一旦吃力就自动收回来。」调紧 →「电池更轻松，预计可用年限会变长；代价是省钱变慢。」
- **为什么这么设**：最低电量越低，单次放电越深，寿命消耗越快。本条与 GR-U-04 共同决定电池的"吃力程度"：一个管**放多深**，一个管**跑多勤**。用四档而非连续滑杆，是为了让用户能对自己的选择负责、也能事后对账。

**GR-U-03 · 要不要把电池充满**

- **组别与级别**：你可调整 · **L2**；内部映射 `chargeTargetCeiling`
- **当前值文案**：「给明天的太阳能留一点空间」；副行：「晚上不充到最满，白天屋顶发的电才有地方存。」
- **可选档位**：「留得多」／**「留一点（默认）」**／「尽量充满」
- **收益影响话术**：改成「尽量充满」→「预计每月多省 €1–3，把夜间便宜的电多存一点。但白天屋顶发的电可能没地方放，会低价卖出去，好的月份反而少省。」改成「留得多」→「预计每月少省 €2–5，白天自用更多、电池更省。」
- **风险变化话术**：改成「尽量充满」→「每月大约多用 3–5 次寿命，且高温天我更倾向于不充满。」改成「留得多」→「晚上以光伏为主时，用电高峰可能要从电网买一点电，这部分差价我已经算进上面的区间。」
- **为什么这么设**：这条的核心不是"充多满"，而是**给白天的光伏留空间**。留太少会浪费屋顶发电，留太多会导致高峰时段电量不足。默认档位由光伏特征（F1）与季节差异推导。

**GR-U-04 · 电池寿命保护强度**

- **组别与级别**：你可调整 · **L3**（会重置月/季/年三层循环预算上限，属规则级变更）；内部映射 `lifeProtectionLevel`
- **当前值文案**：「平衡（推荐）」；副行：「我每个月最多动用的寿命额度是 25 次。按现在的用法，预计每月用掉 20 次左右。」
- **可选档位**：「宽松」／**「平衡（推荐）」**／「保守」
- **收益影响话术**：调到宽松 →「我能做的套利变多，预计每月多省 €5–9。」调到保守 →「我只做很明显的便宜，预计每月少省 €5–9。」
- **风险变化话术**：调到宽松 →「每月额度提高到 40 次左右，若接近用满，预计可用年限会缩短约 1 年。」调到保守 →「额度降到 15 次左右，电池更轻松，预计可用年限会变长约 1 年。」
- **为什么这么设**：§6.3 规定预算默认值来自电池循环寿命参数与用户选择的护电池强度。三档分别对应"收益优先 / 平衡 / 寿命优先"三种立场。
- **补充规则**：与冷启动三问的配比滑杆联动，但**只建议、不静默改动**；用户只改配比而未同步确认本项时必须显式提示。

**GR-U-05 · 多小的便宜值得动手**

- **组别与级别**：你可调整 · **L2**（只影响弃权频率，不会让任何边界变松）；内部映射 `earningThresholdLevel`
- **当前值文案**：「便宜比较明显才动手（推荐）」；副行：「为几毛钱不值得伤电池。太小的价差我会主动放弃，并告诉你我放弃了什么。」
- **可选档位**：「有一点便宜就动手」／**「便宜比较明显才动手（推荐）」**／「便宜很明显才动手」／「只捡大便宜」
- **收益影响话术**：调激进 →「我会更多地出手，预计每月多省 €3–7；被放弃的机会也会变少。」调保守 →「预计每月少省 €3–7，但每一次出手都更有把握。」
- **风险变化话术**：调激进 →「每月大约多用 4–8 次寿命；雨天和冬天我会自然收敛。」调保守 →「电池更省，但明显的便宜也可能被我放过，我会在"我主动放弃的机会"里逐条写清楚。」
- **为什么这么设**：§6.1 建议门槛设在约 €0.15/kWh 价差附近，低于门槛的机会应主动放弃并说明。**该门槛对用户只以档位呈现，不暴露金额**，避免用户换算成收益预期后失去信任。
- **补充规则**：本条直接决定弃权记录（E17）中 `below-threshold` 类的触发频率，是"弃权必须解释"原则在用户设置上的落点。

### 1.3 系统强制的护栏（GR-S）

以下三项**没有可选档位、没有变更入口**（`options` 为空数组），只提供"为什么不能改"的展开说明。当前值文案的作用是让用户看见"系统正在替我盯着这件事"。

**GR-S-01 · 温度与功率保护**

- **组别与级别**：系统强制 · 不可变更；内部映射 `tempPowerProtection`；阈值表见 §6.4
- **当前值文案**：「电池现在 24 度，单体温差 1.8 度，都在安全范围内。」
- **收益影响话术**（固定）：「天太冷或太热的时候，我会少做甚至不做套利。这部分收益损失由我承担，不会记在你头上。」
- **风险变化话术**（固定）：「不会变化。阈值由电池本身决定，不由我决定。」
- **为什么这么设**：温度是电池衰减与安全的第一变量，也是质保争议中的关键证据（§6.3 第 7 条）。改动阈值等于改硬件安全边界，属 §1.6 非目标第 2 条。

**GR-S-02 · 听电网的**

- **组别与级别**：系统强制 · 不可变更；内部映射 `gridCommandCompliance`
- **当前值文案**：「今天没有收到电网的限功率或调度指令。」
- **收益影响话术**（固定）：「电网要求少放功率或防逆流的时候，我会照做。这不影响你家的正常用电。」
- **风险变化话术**（固定）：「不会变化。不遵守会带来并网合规风险，这个风险没有任何收益能覆盖。」
- **为什么这么设**：§9.2 规定并网、限功率、防逆流、可控负荷要求由系统强制、不可被 Agent 绕过；§6.4 第 6 条把电网指令列为弃权理由。

**GR-S-03 · 电压、保护阈值、并网参数**

- **组别与级别**：系统强制 · 不可变更；内部映射 `safetyParams`
- **当前值文案**：「由设备和安装商设定。最近一次更新：2026-03-11，由安装商完成。」
- **收益影响话术**（固定）：「没有关系，这些参数和你的电费无关。」
- **风险变化话术**（固定）：「不会变化。**管家永不可触碰这些参数。**」
- **为什么这么设**：§1.6 非目标第 2 条与 §6.5 自主边界都写明这一点。写进界面的意义不是解释，而是**让用户看见边界**——用户敢开自动，靠的是知道有些事这个系统永远做不了。

**两条不占清单条目的引擎硬约束**（`GR-EN`）

护栏清单固定为 8 条（5 条可调 + 3 条系统强制），与 E20 的数量约定一致；另有两条**恒先生效、不作为 Guardrail 记录**的引擎闸门。它们不进清单、没有「改」入口、当前状态在"告警与保护状态"区呈现，但仍然参与 §2.1 的判定：

- **`GR-EN-01` 备电不被侵占**：当前值文案「已生效。今天有 2 次机会因为会碰到这条线，被我主动放弃。」收益影响话术「我不会为了赚价差去用掉你留给停电的那部分电。代价是我放弃了一些赚钱机会，每一个都会写进"我主动放弃的机会"。」风险变化话术「不会变化。这一条在任何模式下都成立，包括我自己降级运行的时候。」为什么这么设：§6.6 第 2 条"不擅自突破备电预留，这是不可协商项"。GR-U-01 决定**留多少**，本条保证**留下的一定不被侵占**——前者是门的高度，后者是门上的锁。
- **`GR-EN-02` 看不清的时候不动手**：当前值文案「电价和光伏预报都在有效期内。最近更新：今天 16:40。」收益影响话术「数据看不清的时候我会停手，哪怕当时看起来很赚。它可能让你少赚一次，但不会让你亏一次。」风险变化话术「不会变化。用旧数据继续调度，是这类产品最危险的一类错误。」门槛：电价超过 90 分钟未更新、光伏预报置信度低于 0.6、通信中断超过 15 分钟。为什么这么设：§9.3 明确"数据源失效、通信中断时必须降级，不允许'最后已知值'继续驱动调度"；§6.4 第 7 条把预报不确定性过高列为弃权理由。

### 1.4 护栏清单页的呈现规则

1. **顺序固定**：GR-U 组在上（GR-U-01 至 GR-U-05），GR-S 组在下；组内顺序不随状态变化，避免用户找不到。
2. **每行三段式**：名称 ／ 当前值文案（含人话副行） ／ 行尾状态位。可调整项的状态位是「改」，系统强制项是锁形矢量图标 + 「为什么改不了」。
3. **当前值必须可追溯**：点击当前值展开一行依据，例如 GR-U-01 展开「依据：你家最近 30 天夜间基础负荷；来源：站点采集；更新：今天 06:00」。
4. **待批状态可见**：存在待审批变更时，该行显示「有一项修改在等审批，预计 1 个工作日内答复」，点击进入 §5 的进度视图。
5. **与告警联动**：当前生效的保护性限制在清单顶部以一条说明出现，并在对应系统强制项上高亮，说明"现在这条正在起作用"。
6. **无空状态**：不存在"护栏为空"。若站点尚未完成首次配置，显示骨架行 + 「等你完成设置后，这里会出现你的红线清单」+ 进入 T1 三问的按钮。

## 2. 护栏的判定顺序与冲突解决

### 2.1 判定顺序表

每个候选动作在执行前按 P0–P7 逐层判定。**顺序依据是"不可逆性 × 后果严重度"**：越靠前，出错后越无法挽回、影响面越大。

| 顺序 | 判定层 | 对应护栏 | 命中后的行为 | 为什么排在这一层 |
|---|---|---|---|---|
| **P0** | 设备与人身安全 | GR-S-03（安全参数）、GR-S-01（温度与功率） | 阻止动作；视严重度进入 Safe | 后果是硬件损坏或安全事故，不可逆 |
| **P1** | 电网合规与指令 | GR-S-02 | 按指令执行或放弃动作 | 后果是并网合规问题，责任在厂商 |
| **P2** | 数据可信度 | `GR-EN-02` | 阻止动作并降级为 Conservative | 数据不可信时，后面所有判定都不成立 |
| **P3** | 备电不可侵占 | `GR-EN-01`（保底）、GR-U-01（定门槛） | 放弃动作；用户主动要求则走 L2 请示 | 一次失守即击穿产品定位（目标为零次） |
| **P4** | 用户当天的明确指令 | 锁单、一次性例外 | 不做未授权的改动；安全原因除外 | 用户是委托人，其明确意愿高于 Agent 的经济判断 |
| **P5** | 循环预算 | GR-U-04 派生的三层账本 | 余额不足则放弃；用户要求继续走 L2 突破 | 影响长期资产，可逆性低于单日收益 |
| **P6** | 收益门槛 | GR-U-05 | 放弃并记入弃权清单 | 纯经济性判断，不涉及风险 |
| **P7** | 偏好配比 | 省钱/备电/护电池权重 | 仅用于通过上述判定后的动作排序 | 软权重，只影响排序，不影响放行 |

### 2.2 冲突场景与胜出规则

| # | 冲突场景 | 双方 | 谁赢 | 系统行为 | 用户看到什么 |
|---|---|---|---|---|---|
| 1 | 高价时段套利 vs 台风季保险价值上升 | P6/P3 | **P3** | 弃权并说明"这一带的停电风险这周明显变高" | 弃权清单新增一条，理由归入"停电保护"类 |
| 2 | 本月额度用完 vs 用户点"我要做这个" | P5/P4 | **P4 触发请示，不直接执行** | 生成 L2 待确认，附寿命代价说明 | 「你让我做，但我先把代价说清楚」确认页 |
| 3 | 用户已锁单当天 vs 电池温度越线 | P4/P0 | **P0** | 覆盖已锁计划并明确告知 | 「我改了你锁定的计划，因为电池温度越线了」 |
| 4 | 计划夜间充电 vs 电网限功率指令 | P6/P1 | **P1** | 放弃充电，记入弃权清单 | 「今天电网要求少用功率，我没充电」 |
| 5 | 光伏预报置信度低 vs 价差很大 | P2/P6 | **P2** | 转保守策略并声明不确定 | 「这个判断我不太有把握，所以我用了保守做法」 |
| 6 | 备电选了 4 小时 vs 本季已停 3 次电 | P3/P4 | **P3 生效，但主动提示** | 不动用户设定，加一条提示 | 「你选的是 4 小时，而这里本季停过 3 次电。要不要看看改成 8 小时？」 |
| 7 | 温度保护生效 vs 次日计划充电 | P0/P6 | **P0** | 计划改期或缩短，标注被安全原因覆盖 | 计划上出现「我改了这个计划，因为……」 |
| 8 | 额度只剩 2 次 vs 有 3 个候选机会 | P5 内部 | **按净收益排序，用满即止** | 只执行前 2 个，第三个记入弃权 | 第 3 条出现在"我主动放弃的机会"，理由写"额度不够了" |

### 2.3 判定输出契约

1. **单一结论**：一次判定只输出 `allow`（放行）／`skip`（放弃，附弃权理由码与护栏 ID）／`ask`（请示，生成 L2 待确认）三者之一。
2. **主因唯一、次因可多**：多护栏同时命中时，取 P 值最小者为主因，其余记为次因；事故简报只写主因，完整判定轨迹写入留痕，供安装商与售后排查。
3. **确定性**：相同输入必得相同结论，不得引入随机数或"学习中的权重"影响判定，保证可测试、可复现、可对账。
4. **可回溯**：每个被放弃的动作必须在 E17 中记录 `reasonKind` 与命中的护栏 ID，不得只记一句自由文本。
5. **性能预留**：单次完整判定应在 50 毫秒内完成（原型阶段不作性能要求，契约需预留）。

## 3. 护栏触发后的统一行为

### 3.1 五步统一处置

无论哪一条护栏触发，处置流程固定为五步，**不允许任何一步被静默跳过**。

| 步骤 | 动作 | 时限 | 关键要求 |
|---|---|---|---|
| **1 退出优化** | 停止一切以套利为目的的调度；已批计划中被否掉的部分立即失效 | 立即 | 只停套利，不停自发自用与备电保障 |
| **2 切安全默认** | L2 级 → 进入 Conservative（自发自用 + 备电优先）；L3 级 → 进入 Safe（交回硬件默认） | 立即 | 模式切换由护栏引擎写入 E29，全局头部同步可见 |
| **3 生成事故简报** | 按 §4.7 六要素生成 E25，附加护栏专属字段 | 1 分钟内 | 简报必须包含"我放弃了什么"，不能只讲做了什么 |
| **4 按严重度通知** | 按 §3.4 矩阵执行；L3 可穿透静默时段 | 立即或按级别 | 同一护栏 24 小时内只推送一次，去重不丢摘要 |
| **5 日报告知** | 当日日报增加"今天我为什么少做了动作"一节 | 当日日报 | 无论 L0 还是 L3，日报里都必须有一条人话说明 |

### 3.2 每一步的界面表现

**步骤 1 · 退出优化**：电池页顶部出现模式条（琥珀或红色），文字为原因 + 恢复条件，如「我暂停了赚价差的充放电，因为电池温度偏高。等温度回到正常范围我会自己恢复。」计划页中受影响的时段色块灰化并加文字标注「已放弃」——**用保留 + 标注表示，不删除**（用户需要看见"本来要做什么、为什么没做"）。决策日志立即写入一条 `degrade` 记录，收益影响显示为"少赚"而非"亏损"。

**步骤 2 · 切安全默认**：全局头部常驻模式标识切换，任意页面都可见（对应总 PRD A3）。电池页"告警与保护状态"区高亮显示生效中的保护，写明生效时间与预计解除时间；无法预计时写「暂时无法预计，我会在恢复时告诉你」，**禁止编造时间**。同时明确写「现在电池按出厂设置运行，不是你设的红线在起作用」。

**步骤 3 · 生成事故简报**：电池页出现一张可展开的简报卡，标题为一句人话结论，如「电池温度偏高，我暂停了赚价差的动作」。简报只读，链接到异常页的同一条 Incident，**两处内容必须同源**，不得各写一份。

**步骤 4 · 分级通知**：L2 推送一条，卡片含提议 / 一句话理由 / 影响 / 三个按钮（同意、不同意、以后都这样）。L3 同时发 App 推送 + 邮件 + 应用内红条，文案必须包含"发生了什么 / 我做了什么 / 你需要做什么"，或明确写"你什么也不用做"。被静默时段抑制的通知必须记录 `suppressed` 与原因（E33），并在静默结束后补发一条合并摘要。

**步骤 5 · 日报告知**：日报新增一节，固定三句式「今天有什么变化 / 我因此少做了什么 / 接下来会怎样」。示例：「今天下午电池温度偏高，我停掉了两次赚价差的动作，少赚了大约 €0.40。温度已经回落，明天照常。」

### 3.3 事故简报的护栏版模板（E25 扩展）

在 §4.7 六要素基础上，护栏触发的事件必须补充三个字段：

| 补充字段 | 说明 | 示例 |
|---|---|---|
| `guardrailId` | 命中的护栏 | `GR-S-02` |
| `triggerValue` / `threshold` | 触发值与阈值（深水区呈现） | `48.6 度` / `48 度` |
| `forgoneCount` | 因此放弃的机会数与金额 | `2 个机会，约 €0.40` |

六要素的护栏版写法示例：**发生了什么**——今天 14:20 到 15:05，电池温度升到 48.6 度，超过了我设定的保护线；**我的判断与依据**——当时室外 34 度、电池在满功率放电，这一段的价差不足以覆盖高温放电的寿命代价；**我做了什么**——停止了赚价差的充放电，交回出厂默认行为，15:40 恢复；**现在的状态**——电池 29 度，单体温差 2.1 度，停电备用还够 8 小时，设备无异常；**建议动作**——你什么也不用做，如果这一周连续出现，我建议让安装商检查电池的位置和通风；**需要谁决策**——用户（只需知道）。

### 3.4 通知矩阵（护栏专用）

| 触发项 | 级别 | 用户通知 | 安装商后台 | 沃太售后 | 时效 |
|---|---|---|---|---|---|
| 循环预算过半 | L1 | 日报内，不推送 | 无 | 无 | 24 小时内 |
| 循环预算余额不足 | L2 | 推送 + 待确认 | 可见 | 无 | 同步 |
| 触碰备电预留边缘 | L2 | 推送 + 待确认 | 可见 | 无 | 同步 |
| 电价或光伏数据失效 | L2 | 推送 + 说明降级 | 可见 | 无 | 同步 |
| 温度进入关注区（未越线） | L1 | 日报内 | 无 | 无 | 24 小时内 |
| 温度进入保护线 | L3 | 多通道立即 | 可见 | 可见 | 立即 |
| 单体温差越线 | L3 | 多通道立即 | 可见 | 可见 | 立即 |
| 电网指令生效 | L1–L2 | 按指令性质定 | 可见 | 无 | 同步 |
| 安全参数被外部改动 | L3 | 多通道立即 | 可见 | 可见 | 立即 |
| 备电失守（复盘发现） | L3 | 多通道 + 人工联系 | 可见 | 可见 | 立即并进入复盘 |

**硬规则**：L3 通知必须穿透静默时段；L1/L2 在 23:00–07:00 之间只入日报，不推送。

### 3.5 恢复与闭环

1. **恢复条件必须预先声明**：进入降级时，E29 的 `resumeCondition` 必须同时展示给用户（如"温度回到 42 度以下并稳定 30 分钟"）。
2. **恢复不直接回自动**：按 §5.3 硬规则，Safe 解除后只能回到 Conservative；回到 Auto 必须由用户明确确认。
3. **恢复汇报**：Agent 主动发一条「我恢复了，接下来我会这样做」，说明恢复了什么、明天计划是否有变、这次事件是否影响预算。
4. **闭环回写**：由用户或服务人员在异常页判定"一次性"或"系统性"；若为系统性，升级为规则变更任务；影响多户时须走 §5.4 全局熔断流程。

## 4. 循环预算账本规格

### 4.1 三层账本定义（E22）

账本同时维护月、季、年三层，**任何一层余额不足即停**（取最严格的那一层）。

| 层 | 用途 | 示例额度 | 过半提醒线 | 跨期规则 |
|---|---|---|---|---|
| **月** | 月度节奏把控，最早的刹车 | 25 次 | 12.5 次 | 每月 1 日 00:00 重置 |
| **季** | 与季度复核对齐 | 75 次 | 37.5 次 | 自然季度首日重置 |
| **年** | 与质保循环上限对照 | 300 次 | 150 次 | 每年 1 月 1 日重置，与装机周年对齐显示 |

额度来源：`GR-U-04 电池寿命保护强度` × 电池循环寿命参数 × 市场策略包默认值上限。界面上不出现"等效满循环"这个词，用户看到的表述是「这个月你的电池额度用掉了 14.2 次，还剩 10.8 次」。

### 4.2 记账规则

1. **折算**：每次充放按放电深度折算，放掉 30% 的电记为 0.3 次；记账与展示均保留一位小数。
2. **覆盖全部循环，但分账呈现**：账本同时统计"日常自用的循环"与"管家为赚价差动用的循环"，因为质保计数也是全部循环。
3. **降级只砍套利**：超支降级时**只削减额外套利循环**，绝不削减自发自用与备电相关的循环——后者是家庭刚需，削减它等于要求用户少用电，产品定位不允许。
4. **执行前查余额**：每个候选动作执行前先查三层余额；余额不足则不执行，并说明「这个月为了护电池，我不建议再做额外套利了」。
5. **扣减即入账**：动作开始即预扣；未完成或被打断则按实际深度回冲，回冲必须留痕（§7.1 第 2 条）。
6. **不做四舍五入的美化**：不足 0.1 次的用量照实记为 0.1 次，宁多记不少记。
7. **保护期间不扣账**：因温度保护、电网指令、数据失效而少做的动作不消耗额度。

### 4.3 账本状态机

```
     周期开始
        │
        ▼
  正常：三层用量均低于 50%
    │ 任一层用量达 50%
    ▼
  预算过半：50%–80%  ── 周期重置 ──► 回到正常
    │ 任一层用量达 80%
    ▼
  临界：80%–100%（停止新增套利，已批准的计划照常执行完）
    │ 任一层用量达 100%
    ▼
  超支降级：用量达到或超过额度（自动进入保守模式 + 生成 L2 请示）
    │ 用户点"继续，我知道代价"                ┌─ 新周期开始，自动重置并在日报汇报
    ▼                                        │
  破例中：额外额度有效期 7 天 ── 有效期到或用户叫停 ──► 回到超支降级
```

| 状态 | 判定 | Agent 行为 | 界面 | 通知 |
|---|---|---|---|---|
| **正常** | 三层均低于 50% | 正常自主执行 | 进度条中性色 | 无 |
| **预算过半** | 任一层达到 50% | 继续运行，但不追加新机会 | 页面顶部提示条（低优先，不刺眼） | L1，日报内 |
| **临界** | 任一层达到 80% | 停止新增套利，已批准计划照常执行完 | 顶部提示条 + 账本标出剩余区间 | L1，日报内 + 一次推送 |
| **超支降级** | 任一层达到 100% | **自动进入 Conservative**，停止一切套利 | 全局模式条 + 账本置顶说明 | L2，推送 + 待确认 |
| **破例中** | 用户经 L2 确认继续 | 按批准的增量额度继续套利，其余规则不变 | 账本显示"你批准了一份额外额度，3 天后到期" | 到期前 1 天提醒一次 |

### 4.4 账本区的页面规格

每一层（月/季/年）一行，三行结构一致：**主数值**「已用 14.2 次 ／ 额度 25 次」；**进展条**三段色阶（中性/琥珀/红），但**不得仅靠颜色传达**，必须叠加文字「还剩 10.8 次」；**换算一句**「相当于这个月额度的一半多一点」。

**预计可用年限**只在年度行出现，全页仅此一处：「按你现在的用法，电池预计还能用 8 年（区间 6–11 年）」，依据「按最近 90 天的用法估算」；深水区展开后可见分账「其中日常自用 11.6 次，管家为赚价差用了 2.6 次」。

**年限口径**：近期年化用量 = `max(近 90 天日均, 近 365 天日均) × 365`；技术可用年限 = 剩余可循环额度 ÷ 近期年化用量；**预计可用年限 = min(技术可用年限, 质保剩余年限)**，取更早到来的约束，并**明确写出是哪一种约束在起作用**（见 §6.6）。

### 4.5 过半提醒的文案模板

**日报内（L1）**：

> 这个月你的电池额度用掉了 14.2 次，还剩 10.8 次（本季还剩 35.4 次）。按现在的用法，电池预计还能用 8 年。
> 我不会停下来，接下来半个月我会更挑一点，只做比较明显的便宜。

**临界时追加一句**（仍不推送打扰）：

> 这个月剩下的额度不多了。如果这几天有很好的机会，我会用掉；如果机会一般，我会留到下个月。

**禁止的写法**：「你的电池正在加速老化」「再不控制就晚了」。

### 4.6 超支自动降级

触发条件：任一层用量达到 100%。系统按 §3.1 五步动作：立即停止一切套利进入 Conservative；生成 L2 事故简报，其中"我做了什么"写明"我把赚价差的动作全部停掉了"；推送 + 生成 L2 待确认卡片；日报说明。

**降级文案**：

> 这个月的电池额度用完了。我暂停了赚价差的充放电，现在只保证白天的光伏自己用掉、以及停电时有电可用。
> 下个月 1 号额度会自动回来，那时我会恢复正常。

**待确认卡片**：

> 提议：本月继续做套利
> 理由：今天到月底还有 6 天，其中有 2 个明显的机会
> 影响：大约再多省 €3–6，同时这个月的额度会超出 2 到 3 次
> `[继续，我知道代价]` `[就按你说的停]` `[以后都这样]`

### 4.7 用户临时突破预算的 L2 确认流程

| 步骤 | 界面元素 | 内容要求 |
|---|---|---|
| **1 用户发起** | 超支提示条上的「我想继续」 | 不得做成显眼的主按钮，避免诱导突破 |
| **2 代价说明页** | 全屏页（不用模态，避免误触） | 必须给出三项：多用多少、年限影响多少、有效期多久 |
| **3 显式确认** | 勾选框 + 主按钮 | 勾选框文案「我明白这会多用一点电池寿命」，必须手动勾选 |
| **4 生成待确认** | 生成 E27 L2 记录，来源标记为电池页 | 安装商后台可见，但不得代用户批准 |
| **5 生效并限期** | 账本顶部出现"额外额度"行 | 有效期 7 天，到期前 1 天提醒一次 |
| **6 到期处理** | 自动回到超支降级 | 「你上次批准的额外额度明天到期。要不要再来一次？」 |
| **7 留痕** | 写入 E28，`reasonCode = budget-override` | 字段见 §5.5 |

**代价说明页文案模板（完整）**：

> **你让我这个月继续做套利，我照做。先把代价说清楚。**
>
> - 多用的这几次，是从电池未来的寿命里提前借的。按目前的机会估算，这个月大约会多用 2 到 4 次，预计可用年限会从 8 年变成 7 年 10 个月左右。
> - 今年的总账会超过你设定的额度。超出的部分我会单独记在账本里，也写进可以给质保用的记录，将来对账时你能看到是我按你的要求做的。
> - 这一份额外额度 7 天后到期。到期我会问你一次还要不要继续，你不回答就默认停下。
>
> 你仍然可以随时让我停下来。
> `[我明白，继续]`　`[算了，停下来]`

**两句必须遵守的规则**：文案中的年限影响必须由系统按真实数据生成，**不得把示例文案直接上线**；若算出的影响小于显示精度（不足 0.1 年），必须如实写「这次的影响很小，看不出年限变化」，不得为了显得严肃而夸大。

## 5. 红线变更流程（L3）

### 5.1 入口

只有三个入口，不允许从其他页面直接改：电池页护栏清单行尾的「改」；季度复核向导（T5）产出的新版红线；安装商引导用户自行操作（安装商本身不能改，见 §4.11 硬约束）。

### 5.2 从点击到生效的完整步骤

| 步骤 | 名称 | 界面元素 | 输出 |
|---|---|---|---|
| **S1** | 点击「改」 | 展开该护栏的档位选择器 + 当前值 | 用户选定目标档位 |
| **S2** | 「这会改变什么」 | 影响预估卡：收益变化区间 + 风险变化 + 一句话理由 | 用户看到代价与好处 |
| **S3** | 二次确认 | 勾选框「我明白这与现在的设置不同」+ 主按钮「提交修改」 | 生成变更申请 |
| **S4** | 提交 | 状态位变为「等待审批」，显示审批人与预计答复时间 | 生成 E21，状态 `pending` |
| **S5** | 审批 | 审批队列（协作页可见）；电池页只显示状态 | 状态变为 `approved` 或 `rejected` |
| **S6** | 生效 | 显示「将在下一张计划开始时生效」+ 生效时刻 | 状态 `effective`，写回 E20 |
| **S7** | 留痕 | 协作页操作留痕表新增一条，可导出 | E28 |
| **S8** | 通知 | 生效通知（见 §5.6） | E33 |

**两个关键设计**：**不追溯当日已执行的计划**——变更只在下一张计划开始时生效，避免规则半路改变造成对账混乱；**生效前可撤回**——`pending` 与 `approved` 状态下用户可撤回，撤回同样留痕。

### 5.3 审批人角色

| 申请类型 | 审批人 | 说明 |
|---|---|---|
| 一般红线调整（备电时长、保护电池强度、寿命保护强度） | **家庭业主本人**（多人家庭需"主人"角色） | 用户自己的边界自己定，但必须留痕 |
| 下调备电时长到低于当地策略包默认值 | **沃太护栏复核人** | 涉及责任边界，不由用户单独决定 |
| 同时把寿命保护强度调到宽松并放宽预算上限 | **沃太护栏复核人** | 组合变更会显著改变衰减预期，需人工判断 |
| 安装商 / 经销商 | **无批准权，只能发起申请或引导用户操作** | §4.11 硬约束 |

审批时限 1 个工作日内答复；**超时 48 小时未处理则自动驳回并保持原值**（宁可多问一句，不可默认放宽）。

### 5.4 驳回分支

1. 电池页对应行显示「有一项修改没有通过」，点击展开驳回理由。
2. 驳回页必须包含三件事：**为什么没通过 / 如果坚持要改会怎样 / 我建议的替代方案**。
3. 替代方案必须可点击（如"改成维持 8 小时，但把寿命保护强度提到保守"），不能只给结论。
4. 用户可修改后重新提交；重新提交生成**新的** E21 记录，不覆盖原记录。
5. 被驳回的申请不计入"用户推翻率"指标，避免口径污染。

### 5.5 留痕字段（E21 / E28 扩展）

| 字段 | 说明 | 字段 | 说明 |
|---|---|---|---|
| `id` | 变更申请编号 | `approver` / `approverRole` / `approvedAt` | 审批人与角色 |
| `guardrailId` / `guardrailName` | 改的是哪一条 | `rejectedReason` | 驳回理由（驳回时必填） |
| `fromLabel` / `toLabel` | 变更前后的人话档位 | `effectiveAt` | 生效时刻 |
| `fromInternalValue` / `toInternalValue` | 变更前后的内部值（仅工程视图） | `status` | `pending` / `approved` / `rejected` / `effective` / `withdrawn` |
| `requestedBy` / `requestedAt` | 谁、何时发起 | `previousVersionId` | 上一版引用，形成可回溯链条 |
| `requestSource` | 电池页 / 季度复核 / 安装商引导 | `relatedIncidentId` | 若因某次异常触发，关联事件 |
| `reasonCode` / `reasonText` | 变更原因分类与用户说明 | `auditHash` | 本条记录的完整性校验值 |
| `impactAtSubmit` | 提交时的收益影响区间（**冻结快照**） | `riskAtSubmit` | 提交时的风险说明（**冻结快照**） |

**硬要求**：`impactAtSubmit` 与 `riskAtSubmit` 必须是提交当时的冻结值，禁止在生效时用最新数据重算覆盖——用户当时是看着这个数字同意的，事后改数字等于篡改同意内容。

### 5.6 生效后的通知文案

> 你改的那条规矩已经生效：**停电时够用多久，从 8 小时改成 12 小时**。
> 从明天的计划开始生效。代价是每天能拿去赚价差的电少了一些，预计每月少省 €8–14。
> 如果你觉得不合适，随时可以在电池页改回来。

若为沃太护栏复核人批准的变更，追加一句：

> 这一条是沃太的服务人员复核后同意的，复核记录已经在"操作留痕"里，你可以随时查看。

## 6. 电池健康呈现规格

### 6.1 默认结论区（大字号，一屏一结论）

主文案「**预计还能用 8 年**」，区间 6–11 年必须在同一视觉块内出现、不得省略。副文案「这是按你最近 90 天的用法估算的。你用得越温和，这个数字会往上走。」一句话归因（点击展开）「更早到来的约束是质保期（2034 年 6 月到期），不是电池本身的状态。」**健康度百分比折叠在细节里**：默认不出现任何百分比，展开「细节」后才显示健康度、月均衰减、累计用量、温度。

### 6.2 折叠细节区的字段与措辞

| 字段 | 对用户的说法 | 禁止的说法 |
|---|---|---|
| `sohPercent` | 「现在的储能能力：新电池的 96%」 | 「SOH 96%」（深水区可标注缩写，但必须紧跟中文） |
| `degradationPerMonth` | 「平均每个月下降 0.15 个百分点」 | 「衰减率 0.15%/月」 |
| `totalEfc` | 「累计用掉 612 次」 | 「EFC 612」 |
| `expectedLifeYears` | 「预计还能用 8 年（6–11 年）」 | 「寿命 8 年」 |
| `temperatureC` / `cellDeltaC` | 见 §6.4 | 不带单位与判断的裸数值 |

**深水区**：展开后可显示内部术语与更细参数，但必须中英对照，且需要用户主动点两次（先展开细节、再展开专业视图），避免误入。

### 6.3 健康度趋势图（近 12 个月）

**画法**：横轴为近 12 个月，刻度标签每 3 个月一个（2025-10、2026-01、2026-04、2026-07）；纵轴**从 90% 起、不从 0% 起**，否则一年的衰减完全看不出来，且**必须在轴旁明确标注「纵轴从 90% 开始」**——这是诚实披露的一部分；主折线为本机健康度，单色实线 + 数据点；参照虚线为同期同型号平均，图例写「同期装的同类电池平均」；当本机接近时显示一条水平参考线，标注「质保要求的最低水平」。

**标注**：单月下滑超过 1.5 个百分点的月份用三角标记 + 文字说明原因，例如「这个月掉了 2.1 个点，我查了原因：8 月连续高温 + 一次深度放电」——**点得出原因，不能只标异常**；坐标轴必须有标签与单位（§3.2 数据可视化规则）；**不靠颜色传达**，低于参照线用"折线在虚线下方" + 文字说明表达，不得只用红色。

**空状态**：装机不足 3 个月时显示「数据还太少，趋势要再等一段时间才有意义」+ 当前健康度单值，不画趋势线。

### 6.4 温度与单体温差

**呈现**：当前温度「24.3 度」大字 + 一句判断「正常范围」；24 小时温度带（横轴 24 小时、纵轴温度，用区间带表达当日波动，端点标注最低与最高，轴与单位必须存在）；单体温差「1.8 度」+ 一句判断 + 依据「同一块电池里最热和最冷的电芯相差 1.8 度，差得越小说明越均衡」；四段式阈值刻度条（正常 / 关注 / 限制功率 / 保护停机），当前值以三角标出，四段均有文字标签，不依赖颜色区分。

**阈值表（示例假设，必须由电池团队按电芯规格标定后替换）**

| 区间 | 温度 | 单体温差 | 系统行为 | 用户可见 |
|---|---|---|---|---|
| **正常** | 5–35 度 | 不超过 3 度 | 正常运行 | 无标识 |
| **关注** | 35–42 度 或 0–5 度 | 3–5 度 | 减少大功率充放，不新增套利 | 电池页一行提示 + 日报 |
| **限制** | 42–48 度 或 −10–0 度 | 5–7 度 | 限制功率，暂停套利，进入 Conservative | L2 推送 |
| **保护** | 高于 48 度 或 低于 −10 度 | 超过 7 度 | 停止充放，进入 Safe | L3 立即多通道 |

**边界规则**：温度在关注区内**不改变用户设定**，只调整 Agent 行为并在日报中说明；温度保护生效期间**不消耗循环预算**（限制功率导致的少做不算用户违约）；若 7 天内累计 3 次进入关注区，主动建议一次设备检查（走异常页，不让用户自己判断）。

### 6.5 与同期机型的对比（`peerComparison`）

**呈现**：「和你同期装的同型号电池相比，你的电池状态好一些（高出 1.8 个百分点）。同期 1,284 台的平均水平是 94.6%，你是 96.4%。」

**可比性条件**（四项全部满足才展示）：同型号同容量档位；安装时间相差不超过 3 个月；同一气候带（按年均温度与湿度划分）；可比样本不少于 50 台。**样本不足时**不展示数字，改为「和你同期的电池样本还不够多，我先不下结论」——禁止用少量样本制造优越感或焦虑。

**低于同期时的文案**（不得只报数字）：「比同期装的同型号平均低 1.2 个百分点。常见的原因有三个：安装在更热的位置、夏天做过比较多的深度放电、或者装机使用年限稍长。我已经把你今年的用法和温度记录整理好了，如果需要，可以让安装商看一眼。」

**合规约束**：该对比只能出现在电池页与安装商视图，**不得用于营销素材**，不得推导出"我们的电池比别家好"这类结论（对比对象是同型号，不是竞品）。

### 6.6 累计等效满循环与质保上限的对照

**呈现**：「累计用掉 **612 次**，质保内一共 **6,000 次**，还剩 5,388 次。质保覆盖到 **2034 年 6 月**。按你现在的用法，循环额度大约够用二十多年，所以**更早到的是质保期**——你的电池状态不会是先出问题的那一环。」

规则：**两个约束取更早者**并在文案中明确写出是哪一种在起作用（质保条款的通行口径，必须如实呈现）；当**循环先到**时文案改为「按你现在的用法，循环会先用完，不是年份先到。如果你希望它陪你更久，我可以把寿命保护强度调到更保守一档」并提供跳转 GR-U-04 的入口；剩余额度低于 20% 时，进度条与文案同时提示，年度账本行给出醒目但克制的标注；本区与循环预算账本**必须同源**，`totalEfc` 与账本累计是同一个数，禁止两处各算一份。

## 7. 质保口径与数据导出

### 7.1 证据链原则

循环记账必须能作为质保争议的证据（§6.3 第 7 条、§9.2 欧盟电池法规要求）。三条原则：

1. **来源可证**：所有循环与温度数据来自 BMS 原始读数；派生值必须标注为派生并给出算法版本。
2. **不可篡改**：每条记录写入时生成校验值并形成链式结构，导出包附整体摘要；任何回冲、更正生成新记录，**不允许原地覆盖**（§7.4 第 6 条）。
3. **缺失必须显式**：数据缺失时段导出为明确的缺口标记，**禁止静默插值**——用插值粉饰的曲线在质保争议中会直接摧毁证据效力。

### 7.2 导出字段清单

**A 组 · 逐次循环明细（每次充放一条）**

| 字段 | 说明 | 字段 | 说明 |
|---|---|---|---|
| `recordId` | 记录唯一编号 | `tempStartC` / `tempEndC` / `tempMaxC` / `tempMinC` | 过程温度 |
| `siteId` / `batterySerial` | 站点与电池序列号 | `cellDeltaMaxC` | 过程中最大单体温差 |
| `startAt` / `endAt` | 起止时间（含本地时区与 UTC 偏移） | `powerAvgKw` | 平均功率 |
| `action` | 充电 / 放电 | `trigger` | 触发来源：套利 / 自发自用 / 备电 / 人工 |
| `energyKwh` | 电量 | `guardrailsEvaluated` | 本次判定命中的护栏 ID 列表 |
| `socStart` / `socEnd` | 起止电量百分比（工程口径） | `approvedBy` | L2/L3 授权动作的授权人与时间 |
| `depthPercent` | 本次放电深度 | `firmwareVer` / `bmsFwVer` | 固件版本 |
| `efcDelta` | 折算后的用量 | `recordHash` / `gapFlag` | 本条校验值；缺失时段标记 |

**B 组 · 周期汇总（月 / 季 / 年）**：`period` / `budgetEfc` / `usedEfcTotal` / `usedEfcSelfUse` / `usedEfcArbitrage` / `overBudgetEfc` / 平均深度 / 深度分布（0–30%、30–60%、60–100% 三档占比）/ 温度分布（各区间时间占比）/ 最高温度 / 最大单体温差 / 预计可用年限区间 / 该周期内全部 L2 与 L3 授权记录引用。

**C 组 · 告警与保护记录**：`incidentId` / `guardrailId` / `startAt` / `endAt` / `triggerValue` / `threshold` / `systemAction` / `resolvedBy`。

**D 组 · 元数据**：导出人 / 导出时间 / 导出目的 / 口径版本号 / 假设条件 / 生成工具版本 / 整体校验摘要 / 数据来源清单（BMS、云平台、第三方电价）。

### 7.3 格式与隐私

1. **格式**：CSV（机器可读）+ PDF（人类可读，附口径说明）+ JSON（原始结构），三者必须同源生成，不得分别导出。
2. **两种口径**：面向用户版不含百分比与专业术语（§0.3）；面向质保与工程版含完整字段，并在文件头标注「工程口径，请勿直接用于对外宣传」。
3. **隐私最小必要**：默认**不包含家庭负荷曲线**（可推断居家作息，属敏感信息）；确需包含时必须单独勾选并单独留痕。
4. **撤回与删除**：用户撤回授权后，已导出的证据包不回收（质保争议需要），但后续不再生成；删除数据请求按 §9.2 合规流程处理，并明确告知"删除后无法用于未来的质保争议"。
5. **保留期限**：循环与温度记录保留至质保期结束后 2 年，与质保争议时效对齐。

|---|---|---|---|---|---|---|
| **正常** | 三层预算低于 50%，无保护生效，无未闭环 L2 以上事件 | 全局模式条显示当前运行模式，无告警 | 主文案「预计还能用 X 年（区间）」；趋势、温度、对比、循环对照全部正常 | 三行进度条中性色，年度行显示预计可用年限 | 两组清单正常展示；系统强制组灰底 + 锁形图标 | 无额外通知；状态变化写入决策日志 |
| **预算过半** | 任一层用量达到 50% | 顶部出现低优先提示条，不弹窗、不推送 | 年限结论下方追加「按现在的用法，这个数字可能会小幅下降」 | 该层进入琥珀区间，叠加文字「还剩 X 次」，展开有分账 | 清单不变；GR-U-04 行追加「本月额度已过半」 | L1：仅日报内 |
| **超支降级** | 任一层用量达到 100% | 模式条变为琥珀色保守模式 + 原因 + 恢复条件 | 年限结论附「这个月多用的部分已经记在账本里」 | 置顶显示超支说明与超出量；超过 100% 的部分用斜纹段表示并加文字标注 | GR-U-04 行高亮，显示「额度已用完」+ 待确认入口 | L2：推送 + 待确认 + 安装商后台可见 |
| **温度保护生效** | 温度进入限制区或保护区 | 限制区为琥珀条、保护区为红条，写明生效时间、原因、预计解除时间 | 温度区高亮，刻度条标出当前值，趋势图对应时段加标注 | 显示「这次少做的动作不占用你的额度」 | GR-S-02 行高亮并显示当前读数与阈值 | 限制区 L2 推送；保护区 L3 多通道立即 |
| **告警中** | 存在未闭环的 L2 或 L3 事件 | 红条显示告警摘要 + 需要谁处理 + 已过去多久 | 健康概览加一层说明条，指明哪些数字受事件影响 | 照常显示，但注明暂停期间的数据不计入 | 全部清单只读，禁止提交任何变更 | 按 §3.4 执行；通知记录可在设置页查 |
| **加载中** | 页面初次进入或数据刷新 | 骨架屏，保留与最终内容一致的行高与列宽，避免布局跳动 | 骨架块占位，**不显示任何占位数字**（禁止假数据） | 骨架行占位 | 骨架行占位，锁形图标一并占位 | 无 |
| **权限不足** | 当前身份（家庭成员、安装商）无权进行某项操作 | 页面正常展示，仅操作入口变化 | 正常展示 | 正常展示，但不显示"额外额度"入口 | 可调整项显示「只有主人可以修改」+ 谁有权 + 发起路径；系统强制项不受影响 | 无通知；点击受控项时给出提示，不静默失效 |

### 8.2 操作可用性矩阵

| 操作 | 正常 | 预算过半 | 超支降级 | 温度保护生效 | 告警中 | 加载中 | 权限不足 |
|---|---|---|---|---|---|---|---|
| 提交红线变更（L3） | 可 | 可 | 可 | 可 | **不可** | 不可 | 不可 |
| 提交预算突破（L2） | 不可（无必要） | 可 | 可 | 不可 | 不可 | 不可 | 不可 |
| 撤回待批申请 | 可 | 可 | 可 | 可 | 不可 | 不可 | 仅本人申请 |
| 查看趋势与导出 | 可 | 可 | 可 | 可 | 可 | 不可 | 可 |
| 查看事故简报 | 无内容 | 无内容 | 可 | 可 | 可 | 不可 | 可 |
| 关闭 / 开启自动执行 | 跳转设置页（L2） | 可 | 可 | 可 | **不可** | 不可 | 不可 |

**告警中禁止提交变更的理由**：告警未闭环时规则正被安全逻辑覆盖，此时接受红线变更会造成"用户以为改生效了、实际被安全逻辑压着"的认知错位。必须先闭环，再改规则。

## 9. 验收条件

- [ ] **1. 护栏清单完整性**：十条护栏全部出现在电池页，两组视觉明确可区分，系统强制组无任何操作入口，每条九字段齐全（ID、名称、组别、当前值文案、可选档位、级别、收益话术、风险话术、理由）。
- [ ] **2. 用语合规**：涉及备电的表述不出现百分比与 SOC（电池页、通知模板、日报、面向用户的导出）；GR-U-02 只以"保护电池强度"档位与人话副行呈现。判定方式：文案检索 + 人工检视。
- [ ] **3. 当前值可追溯**：点击任一护栏的当前值，展开依据、数据来源与更新时间。
- [ ] **4. 级别正确**：GR-U-01 / GR-U-02 / GR-U-04 走 L3 审批，GR-U-03 / GR-U-05 走 L2 一键确认，系统强制项无流程入口。
- [ ] **5. 判定顺序可复现且冲突场景覆盖**：同一候选动作同时命中两条护栏时，主因与次因输出稳定一致；§2.2 的八个冲突场景均可在原型中触发并呈现规定的界面表现。
- [ ] **6. 弃权必须解释**：被护栏否掉的动作全部出现在"我主动放弃的机会"中，且带护栏 ID 可回溯。判定方式：检查 E17 记录。
- [ ] **7. 五步处置完整且降级不静默**：退出优化 / 切安全默认 / 生成简报 / 分级通知 / 日报告知五步均可被观察，无一步静默跳过；降级后任意页面头部可见模式标识与原因（对应总 PRD A3）。
- [ ] **8. 事故简报字段齐全**：六要素 + `guardrailId`、触发值与阈值、放弃机会数与金额，三项补充字段均存在。
- [ ] **9. 通知去重与静默**：同一护栏 24 小时内只推送一次；L1/L2 在 23:00–07:00 不推送且记录抑制原因；L3 可穿透静默时段。
- [ ] **10. 账本三层同屏且年限给区间**：月/季/年三行同时可见，任一层余额不足即触发停止逻辑；预计可用年限始终带区间，并明确写出更早到来的约束是年限还是循环。
- [ ] **11. 过半提醒不焦虑**：预算过半时的文案符合 §4.5 模板，不含任何催促或指责句式。
- [ ] **12. 超支降级可复现**：把某层账本推到 100%，系统进入保守模式并生成 L2 待确认；周期重置后自动恢复并在日报汇报。
- [ ] **13. 突破预算需显式同意且限期**：临时突破必须经过勾选框 + 主按钮，代价说明页同时给出用量、年限影响、有效期三项；额外额度 7 天到期，到期前 1 天提醒，到期后回到超支降级。
- [ ] **14. L3 全流程可走通**：从点击到生效八步均可在原型中演示，包含待批、已生效、被驳回三种状态；驳回页含理由、坚持要改的后果与可点击的替代方案；重新提交生成新记录而不覆盖原记录。
- [ ] **15. 冻结快照与生效时点**：`impactAtSubmit` / `riskAtSubmit` 为提交时快照、生效时不重算（改动底层数据后检查历史记录未被改写）；变更只在下一张计划开始时生效，不追溯当日已执行的计划。
- [ ] **16. 健康默认文案**：健康概览首屏默认展示"预计还能用 X 年"及区间，不出现百分比；百分比只在主动展开细节后出现。
- [ ] **17. 趋势图诚实标注且不靠颜色传达**：纵轴从 90% 起并在轴旁明确标注；含同期平均虚线、质保下限线、月度异常三角标注与原因文字；坐标轴带单位与标签；所有依赖颜色的信息都有图形或文字编码叠加。
- [ ] **18. 温度可视化与阈值一致**：四段刻度条均有文字标签且阈值与 §6.4 表一致；对比保护前后的账本，保护期间的少做未增加用量。
- [ ] **19. 同期对比门槛与用途限制**：样本不足 50 台时不展示对比数字，改为声明样本不足；对比模块不出现在收益页，也不出现在任何对外素材中。
- [ ] **20. 循环与质保同源且缺失显式**：累计用量与账本累计是同一个数（数据一致性检查）；数据缺口在导出包与趋势图中显式标记、无静默插值（检查 `gapFlag`）。
- [ ] **21. 导出字段齐全且隐私最小必要**：A/B/C/D 四组字段全部存在，CSV 与 PDF 同源生成；默认导出不含家庭负荷曲线，包含时需单独勾选并留痕。
- [ ] **22. 状态矩阵七态全实现**：正常 / 预算过半 / 超支降级 / 温度保护生效 / 告警中 / 加载中 / 权限不足七种状态均可通过页内状态开关人工检视（对应总 PRD A2）。
- [ ] **23. 受控状态有出口**：告警未闭环期间红线变更入口不可用并给出原因说明；无权限时给出"谁有权"与"如何发起"，不静默失效。
- [ ] **24. 无 emoji、无裸术语、键盘可达、响应式**：电池页及全部通知与导出模板中不出现 emoji，不出现 SOC / DoD / EFC / 裸 kW / 裸 kWh（深水区展开除外，全文检索）；所有交互元素可 Tab 聚焦且有可见焦点环；1440 / 1024 / 768 三档不破版（对应总 PRD A13、A14）。

## 10. 护栏的下游消费契约

护栏引擎输出的不是文案，而是**可被其他模块直接判定的结构**。以下契约必须由各模块实现，否则会出现"同一条规则在不同页面说法不一致"。

| 消费方 | 读取什么 | 必须遵守的约束 |
|---|---|---|
| **F2 计划引擎** | 十条护栏的 `currentValue`、`group`、`level`；判定结果 `allow` / `skip` / `ask` | 只能读不能改；被否掉的动作必须生成 E17 弃权条目 |
| **F3 日内修正** | 判定结果与护栏 ID | 安全原因覆盖已锁计划时必须写入 `overrideNote` 并告知用户 |
| **F4 决策解释** | 命中的护栏 ID 与阈值 | L2 解释中必须能点进对应护栏，看到"是谁定的这条规矩" |
| **F6 收益归因** | 三层账本口径、质保上限、折旧假设 | 折旧必须使用账本口径；因预算造成的少省不得算作效率损失 |
| **F7 异常** | 触发事件、级别、事故简报数据 | 简报与电池页同源，禁止各写一份；闭环结论回写护栏引擎 |
| **T5 季度复核** | 三层账本、年限区间、本期保护触发次数 | 第 2 问取账本，第 3 问取 GR-U-01 与 GR-S-01 的命中记录 |
| **市场策略包（E30）** | `defaultGuardrails` 的键为护栏 ID | 弱电网市场默认提高 GR-U-01；默认值不得低于合规底线 |
| **安装商视图** | 红线清单、待批申请、命中的护栏 | **只读**，不得修改客户红线，只能发起申请或引导用户 |
| **设置页偏好** | 配比与护栏的联动关系 | 改配比属 L3；影响 GR-U-04 时必须显式提示，不得静默改动 |
| **通知中心（E33）** | 级别、抑制规则、去重键 | 去重键为 `guardrailId + incidentId`；被抑制必须留痕 |

**弃权理由码与护栏的映射**（E17 `reasonKind` 对应到护栏 ID）：

| `reasonKind` | 对应护栏 | 说明 |
|---|---|---|
| `below-threshold` | GR-U-05 | 价差不够明显 |
| `backup-edge` | GR-U-01 / GR-S-01 | 会碰到备电线 |
| `battery-temp` | GR-S-02 | 温度不利 |
| `budget` | GR-U-04 派生账本 | 额度不足 |
| `uncertainty` | GR-S-05 | 数据或预报不可信 |
| `outage-protect` | GR-U-01 + 停电风险画像（E11） | 区域停电风险升高 |
| `grid-fee-conflict` | 无（属收益口径，F6 负责） | 省了电价多付了网费，仍受 GR-U-05 门槛约束 |
| `lock` | 无（属计划锁单，F2/F3 负责） | 用户已锁定当天计划 |

**两处口径分歧（需评审决策）**

1. **循环预算是否包含自发自用产生的循环**。本模块立场：**记账包含、降级不含**（理由见 §4.2 第 2、3 条）。需与质保口径确认一致，否则会出现"账本说没用多少、质保说已经用了很多"。
2. **预计可用年限是否以质保到期为上限**。本模块立场：**取更早者并明说**（§6.6）。若法务认为这会引发"质保到期即报废"的误解，需重新设计措辞。
