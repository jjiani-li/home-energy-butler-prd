# 02 · 模块拆解 A —— 今日与能源计划（F2 + F3）

> 上游文档：`docs/prd/00-总PRD-沃太家庭能源管家Butler-v2.0.md`（下称"总 PRD"）
> 模块代号：**模块 A**；覆盖能力：**F2 每日能源计划表** + **F3 日内滚动修正**；宿主页面：**今日**、**计划**
> 版本：v1.0；用于指导前端原型与研发实现

## 0. 阅读约定

### 0.1 继承的硬约束（不得放宽）

| 来源 | 约束 |
|---|---|
| §3.1 P1–P8 | 一屏一结论；默认人话不出现裸术语；弃权必须解释；预测必带区间；危险动作永不自主；每个数字可回溯；降级可见；不制造焦虑 |
| §4.0 | 不允许空白屏或冻结界面；必须实现加载 / 空 / 数据源失效 / 降级 / 权限不足五态 |
| §4.0 文案规则 | 不出现 emoji；不出现"保证省 XX 元" |
| §6.6 反面清单 | 不擅自突破备电预留；不深夜推送；不把一次操作当永久偏好；人工接管期间完全静默 |
| §7.4 数据规则 | 金额统一欧元；时间戳必存；预测必有区间；只展示净收益；弃权记录与执行记录同等重要；更正必须留痕 |

### 0.2 字段名不等于文案

本文出现的 `socFrom`、`powerKw`、`plannedEfcUsed` 等是**内部数据契约字段名，不是界面文案**。写入界面的文字一律使用附录 A 说法：剩余电量写成"够用约 9 小时"；放电深度写成"这次放掉了多少电"；等效满循环写成"电池用掉的寿命"；循环预算写成"电池寿命保护强度"；备电预留写成"停电时够用多久"；电网费写成"输配电的费用（另一项要算的钱）"。凡本文给出界面文案模板，`{}` 内一律代表**已翻译成人话的结果**，不是原始字段值。

### 0.3 数字声明

本文所有金额、时长、循环数均为**说明业务逻辑的示例假设**，源自总 PRD 模拟口径，不构成对外承诺。正式对外数字须经目标市场实测标定并经法务复核（总 PRD 附录 B）。

## 1. 模块边界

### 1.1 本模块负责

1. **F2 的生成契约**：定义一张计划必须具备哪些字段、时段如何切分、动作如何表达、原因如何生成。
2. **F2 的呈现**：「计划」页渲染三轨图 + 动作表 + 弃权栏 + 操作组；「今日」页渲染结论部分（三问数字、时间线、待确认队列），构成 10 秒可读摘要。
3. **计划审批（T3）**：接受 / 我要调整（方向性滑杆）/ 明天按老办法来 / 锁定这一天的计划，四种操作的界面与状态流转。
4. **弃权机会的呈现与覆盖**：把 `ForgoneOpportunity` 翻译成人话，并提供"如果你希望我做，点这里"的入口与后续分流。
5. **F3 日内滚动修正**：触发判定清单、静默阈值、必须告知的判定、修正后"改了什么"的呈现、锁单与安全覆盖的优先级。
6. **三问数字的计算口径（业务级）**：预计净收益（含区间）、明早备用余量（小时）、本次动用循环（等效满循环）的输入字段与算式描述。

### 1.2 本模块不负责（交接清单）

下表是模块 A 与其余拆解文档的接口对照（模块 B/F4+F1 见 `03-…模块B…`；模块 C/F5 见 `04-…模块C…`；模块 D/F6+F7 见 `05-…模块D…`；协作与状态机见 `06-…模块E…`；冷启动/影子期/市场/安装商/设置见 `07-…模块F…`）。

| 不负责的事 | 归属 | 交接方式 |
|---|---|---|
| 决策三层解释（L1/L2/L3）、决策日志列表与筛选、推翻后的"例外还是规则"分流 | **F4 决策** | 本模块只负责**发起入口与摘要**：`PlanSlot.reason` 提供 L1 一句话；点击后跳 F4 并携带 `slotId` / `decisionLogId` |
| 护栏清单展示与修改、红线 L3 审批流、循环预算账本页、电池健康趋势 | **F5 电池** | 本模块**只读** `Guardrail.currentValueLabel` 与 `CycleBudget` 用于判定与文案；任何修改一律跳 F5 |
| 家庭画像生成、事实/猜测区分、用户纠正 | **F1 家庭** | 本模块**消费** `HouseholdProfile` / `LoadSeries` / `FlexibleLoad`，翻译成计划原因文案 |
| 收益归因四栏对照、收益拆解、月度报告、合同体检 | **F6 收益** | 本模块只产出**当日单期**净收益与基线差额；"看构成"跳 F6 |
| 事件列表、事故简报六要素、处置时间线、闭环回写 | **F7 异常** | 本模块只呈现**结果**：运行模式条、被覆盖说明条、"查看事件"入口 |
| 运行状态机的迁移判定 | **全局 E29** | 本模块**响应**模式，不决定模式；只把原因与恢复条件翻译成人话并常驻显示 |
| 市场策略包配置、规则变更提醒、全局熔断 | **F8 市场** | 只消费 `MarketPack` 下发结果（默认红线、上网规则、需求响应可用性） |
| 影子期看板、建议 vs 实际对照表、开启自动确认页 | **引导 T2** | 本模块只定义影子期的**文案替换规则**（见 9.3），对照表属引导页 |
| 一键回退出厂策略 | **设置 §4.12** | 按 §9.3 该开关须在「今日」页可达；本模块只约定**入口占位**与跳转 |

### 1.3 接口契约

**接收（只读）**：`E29 RunModeState`（模式与降级原因）、`E13 PricePoint[]`、`E14 GridFeeRule`、`E20 Guardrail`（备电红线、收益门槛档位、护电池强度）、`E22 CycleBudget`（预算余额与过半线）、`E06/E07/E08/E09`（基础负荷基线、负荷偏离、可挪动设备）、`E10 SolarCharacteristic`（光伏预报与置信度）、`E11 OutageHistory`（备电保险价值）、`E25 Incident`（安全覆盖原因）。

**输出**：`E15 EnergyPlan`、`E16 PlanSlot`、`E17 ForgoneOpportunity`、`E19 PlanRevision`、`E27 PendingApproval`——分别被 F4（解释层）、F6（当日归因）、F7（处置时间线）、安装商视图、协作页 L2 队列消费。

### 1.4 一句话边界判据

> 本模块回答"今天电池打算怎么用、为什么、你同意吗、中途变了什么"；不回答"这个决定背后的完整推理史"（F4），也不回答"电池还能用多久"（F5）。

## 2. 用户任务与成功判据

### 2.1 用户 10 秒内要得到哪三个答案

| 序 | 问题 | 主展示值 | 用户读完应能复述 |
|---|---|---|---|
| Q1 | 今天省了多少？ | 今日预计净收益 `€{likely}`，区间 `€{min}–{max}`，以及与出厂策略的差额 | "今天大概省一块八，最差一块四最好两块二，比出厂策略多省四毛" |
| Q2 | 停电够不够用？ | 明早备用余量，单位**小时**（"够你家基础用电约 9 小时"） | "万一明早停电，够我用九个小时" |
| Q3 | 电池累不累？ | 本次动用循环，翻译为"相当于电池寿命的 0.02%" | "今天这么用，大概用掉电池寿命的万分之二" |

顺序不可调换：省钱 → 安全 → 寿命，与用户焦虑强度一致，也符合"备电不可协商"的立场。**三问必须在首屏（不滚动）内全部可见**，任一格需下滑即视为不满足 10 秒目标。

### 2.2 如何度量"看懂了"（均为可观测行为，不依赖主观评分）

| 编号 | 判据 | 通过线 |
|---|---|---|
| M1 | 首屏三问识别时间（页面加载完成到用户开口答 Q1/Q2/Q3） | 中位数 ≤ 10 秒 |
| M2 | 不看页面、用自己的话复述三问 | ≥ 80% 受测者三问全对 |
| M3 | 用户是否用"小时"而非百分比复述备电 | 100% |
| M4 | 循环消耗被理解为"对电池寿命的消耗"而非"充了多少电" | ≥ 80% |
| M5 | 弃权栏理解率：能说出**为什么不做**那件看起来赚的事 | ≥ 70% |
| M6 | 原因字段复述质量：能用"因为……所以……"复述任一动作原因 | ≥ 70% |
| M7 | 不展开深水区即可完成的基本任务（看结论 / 接受计划 / 调整方向 / 找到弃权 / 看懂修正） | 5 / 5 |
| M8 | 冻结与空白：任何状态下无未解释的空白区块 | 0 例 |
| M9 | 界面可见文案不出现 SOC / DoD / EFC / kW / kWh / 百分比电量 | 0 例（深水区除外） |
| M10 | 所有预测值带区间或明确"约" | 100% |

### 2.3 反指标（做得好不等于指标高）

不追求时间线点击率（点击率高说明默认层没说清）；不追求 App 打开率（§2.6）；**不追求 L2 待确认条数**（L2 每天弹出即产品失败，§4.8）；不追求调参次数（频繁拖动方向性滑杆说明默认配比错了）。

### 3.0 区块总览

| 页面 | 区块 ID | 区块名 | 来源 |
|---|---|---|---|
| 今日 | `A-TD-01`…`A-TD-08` | 运行模式条 / 结论卡（三格）/ 实时能量流 / 今日时间线 / 需要你决定（L2 队列）/ 今日已发生·待发生 / 下一页入口 / 一键止损占位条 | §4.1 元素 1–7 + §9.3 |

以下每个区块按 目的 / 数据来源 / 展示元素 / 交互 / 状态变体 五项给出。状态变体的完整逐态矩阵见第 9 章，此处只列**设计上必须存在**的变体。

### 3.1 今日页区块

#### `A-TD-01` · 运行模式条

- **目的**：让用户随时能答"管家现在是不是在替我做主"（P7），并在第一时间知道**为什么不是全自动**。
- **数据来源**：`RunModeState.mode / since / reason / resumeCondition / heldBy / nextPlannedMode`。
- **展示元素**：模式名称文字（不用图标代替信息）：我在学习，只看不做 / 我建议，你决定 / 我在按你的规则自动安排 / 保守安排中 / 已暂停优化 / 人工处理中；进入时间"从 3 月 12 日起"；降级时必填原因句与恢复条件"电价数据恢复后我会自动回到自动安排"；接管时显示接管人"安装商张某正在处理"；"展开细节"入口（显示模式含义、上次变更记录、当前被限制的能力清单）。
- **交互**：点模式名就地展开，不用弹窗；降级态提供 `[去处理]`，跳转到导致降级的页面（数据失效 → 计划页可信度条；触碰红线 → 电池页；停电 → 异常页）。
- **状态变体**：影子期灰色条 + 结束日期；建议模式蓝色条；自动模式强调色条；保守降级琥珀条 + 原因 + 恢复条件；安全模式红色条 + 需谁处理；人工接管红色条 + 接管人 + 开始时间。

#### `A-TD-02` · 结论卡（三格）

- **目的**：承载 10 秒三问（2.1），本模块最高优先级区块。
- **数据来源**：`EnergyPlan.expectedNetEarning`（min / likely / max）、`baselineEarning`、`backupHoursTomorrow`、`plannedEfcUsed`；当日已过部分叠加 `DecisionLog.outcome` 与 `BatteryState`。
- **展示元素**：格一"今天省了多少"：主值 `€{likely}`，下方区间 `€{min}–{max}`，第三行"比出厂策略多省 €{差额}（预计）"；格二"停电够不够用"：主值"够你家基础用电约 {小时} 小时"，副行"明早 7 点前如果停电"；格三"电池累不累"：主值"相当于电池寿命的 {百分比}"，副行"今天电池动 {次数} 次"；每格右上"依据"入口（P6）；时间戳"计划生成于 17:42 · 数据更新 6 分钟前"。
- **交互**：点任一格就地展开该数字的构成（口径见第 8 章），不用模态弹窗；三格均可 Tab 聚焦，回车展开。
- **状态变体**：影子期标题前缀"如果按我说的做" + 一行"我只看不做，你家设备不受影响"；建议模式加"还没执行，等你点头"；降级加"我在用保守安排，收益会比计划低一些"；数据源失效时受影响格整格置灰 + "这个数暂时算不准"（不得用最后已知值冒充）；锁单时格三加锁形矢量图标；被安全覆盖时格一下方出现覆盖条。

#### `A-TD-03` · 实时能量流

- **目的**：用一图回答"此刻我家在发生什么"，是信任感的即时来源。
- **数据来源**：`E05 EnergyFlow`（光伏 / 电网 / 电池 / 家庭四节点 + 四条有向流量）、`BatteryState.timestamp`、`BatteryState.mode`。
- **展示元素**：四节点文字"屋顶太阳能 / 电网 / 电池 / 家里用电"；每条流向的人话功率"屋顶正在发 3.2 度电每小时"（不写 kW）；电池状态词"正在充电 / 正在放电 / 没用它 / 先留给太阳能"；数据新鲜度"12 秒前更新"，超阈值改为"数据可能不是最新"；一句总述"这会儿屋顶发的电够家里用，还有多的存进电池"。
- **交互**：悬停节点显示构成与时间戳；点电池节点跳电池页；点流向显示该方向今日累计量（"今天存进去 8 度"）。
- **状态变体**：加载中为四节点骨架 + 占位连线（不用旋转动画）；数据源失效整块置灰 + "家里的实时数据暂时取不到" + 已采取的降级策略；影子期加"这些只是给你看，我还没动过你的设备"；人工接管显示"人工处理中，实时优化已暂停"但保留数值并加边框标识；新装机显示"设备刚接入，正在采集第一组数据"。

#### `A-TD-04` · 今日时间线

- **目的**：让用户看见今天电池怎么走，并且**每一段都能被质疑**。
- **数据来源**：`EnergyPlan.slots`、`PricePoint[]`、实际执行序列、`PlanRevision`（修正痕迹）、`EnergyPlan.locked`。
- **展示元素**：横轴 24 小时刻度（00 / 06 / 12 / 18 / 24）；背景层电价曲线（带轴标签与单位）；上轨计划动作色块（高度表达功率）；下轨实际执行序列；修正痕迹"原 → 现"，原时段为虚线；锁单时段右上锁形**矢量**图标；"现在"竖线与标签；图例同时用颜色与图形编码。
- **交互**：点任一时段侧边抽屉展开 L1 一句话，抽屉内可进 F4 的 L2/L3；左右方向键在时段间移动、回车打开抽屉；点"现在"竖线附近跳 `A-TD-06` 对应行。
- **状态变体**：影子期下轨置灰 + "我没执行，这是给你的参考"；电价缺失时曲线区斜纹底纹 + "电价暂时取不到，我按最保守的方式安排"，动作块照常；锁单区间加锁形图标与浅底纹；被安全覆盖时对照显示原计划与现计划；人工接管整条转只读并加接管水印。

#### `A-TD-05` · 需要你决定（L2 队列）

- **目的**：把"人只在异常与需授权时进场"落成区块，并用"隐藏即不打扰"控制打扰频率。
- **数据来源**：`E27 PendingApproval`（提议 / 理由 / 影响 / 级别 / 过期时间）。
- **展示元素**：标题 + 数量；最多显示 1 条 + "还有 N 条"（其余折叠进协作页）；每条含提议（一句）、一句话理由、影响（收益与风险各一句）、过期处理"如果你不回答，我会按最保守的方式办"；按钮 `[同意]` `[不同意]` `[以后都这样]`；级别标签，L3 项只显示申请入口不提供直接执行。
- **交互**：点任一项进**全屏确认页**（不用模态，避免误触）；`[不同意]` 后必问"这次是例外，还是以后都这样？"（§8.5），本模块负责**不跳过这一步**；无内容时整块隐藏。
- **状态变体**：空（常态）整块不占位，这是**好状态**不是缺失；加载中不渲染，避免"加载中"的焦虑感；降级且队列为空时显示"我没有需要你决定的事，是我自己降级了，原因是……"；影子期提议加前缀"如果以后开启自动，我会……"；权限不足时按钮改为"查看"+"谁有权决定"。

#### `A-TD-06` · 今日已发生 / 待发生

- **目的**：给愿意深看的人一条紧凑流水账，也是日报的可见部分。
- **数据来源**：`PlanSlot[].status`、`DecisionLog.actionSummary`、`PlanRevision`。
- **展示元素**：每条一行五列——时间 `HH:mm`、动作（人话短句 ≤ 8 字）、原因摘要（`reason` 裁剪版）、状态标签（已执行 / 已修正 / 已放弃 / 待发生）、收益影响（已执行用实际、待发生用"预计"）；上半区"已经发生的"、下半区"接下来的"，中间一条分隔线。
- **交互**：点任一行打开与 `A-TD-04` 相同的侧边抽屉；"待发生"行右侧提供 `[不想这样]` 快捷入口进方向性调整。
- **状态变体**：今天刚开始时上半区显示"今天还没开始"，不渲染空表格；影子期"待发生"改"我建议"，"已发生"加注"你家设备当时是按老办法在跑"；数据源失效时实际执行列显示"取不到"，计划列照常；锁单时待发生行原因列追加"（你锁定了今天）"；被安全覆盖的受影响行状态标签为"我改了"。

## 4. 24 小时计划图的数据契约

### 4.1 通用画布与坐标

| 项 | 规则 |
|---|---|
| 时间范围 | 始终为**本地时间的完整一天** `00:00–24:00`，不是滚动 24 小时（便于形成固定阅读习惯） |
| 横轴 | 线性时间轴；主刻度 6 小时（00 / 06 / 12 / 18 / 24），次刻度 1 小时；时间一律为站点本地时间，不换算时区 |
| 纵轴 | 左轴电价，**必须显示单位** `€/度`；右轴以"够用几小时"为刻度，不使用百分比 |
| 三轨顺序 | 自上而下：A 电价 → B 动作 → C 电量，不可调换（先看价格，再看动作，最后看结果）；高度比 3 : 2 : 3 |
| 颜色与编码 | 单色阶 + 一个强调色；**任何信息不得只靠颜色传达**，必须叠加图案或文字编码 |
| 空值处理 | 缺失时段画斜纹占位，**禁止插值填充，禁止用上一时段的值延续** |
| 响应式 | 768px 以下三轨改为上下堆叠的单轨视图，横轴保留，悬停改点击 |

### 4.2 轨道 A · 电价曲线

**数据结构**：`PricePoint { at, pricePerKwh, currency, source, confidence }`；叠加用的 `GridFeeRule { tou, touSeries[], capacity, demand, controllableLoadDiscount, discountSeries[], requiresCurtailment }`。

**坐标映射**：`x = (t − 00:00) / 24h × 图宽`；`y = (price − yMin) / (yMax − yMin) × 轨道高`，其中 `yMin = min(价格序列) − 10% 带宽`、`yMax = max + 10% 带宽`。出现超过中位数 4 倍的尖峰时**不允许把其余点压到不可读**，改用断轴标记并在悬停层给真实值。负电价必须可读：轴下方留负值区，负价时段以斜纹底 + "这个时段用电还能拿钱"说明。曲线为折线，不做平滑插值（避免假精度）。叠加电网费时用虚线绘制在同一坐标系，图例注明"这条虚线是额外要付的输配电费用"，两条曲线共用左轴便于直接比对。

### 4.3 轨道 B · 计划动作

**数据结构**：`PlanSlot { start, end, action, socFrom, socTo, powerKw, reason, reasonDetail[], status, adjustedFrom, earningEur }`，其中 `action` 取 `grid-charge | discharge | idle | solar-priority | hold`，`status` 取 `planned | executed | revised | skipped | overridden`。

**坐标映射**：块左边界为 `start`、右边界为 `end`，最小可视宽度 6px（短时段不至于消失，但悬停层须给真实起止）；块高 `h = powerKw ÷ 站点最大充放功率 × 轨道高`（每站点各自归一化，不用绝对功率）。**方向编码**：充电类向上伸展，放电类向下伸展，`idle` 与 `hold` 为贴中线的窄条，`solar-priority` 为自中线向下的浅色斜纹区。**图案编码**（与颜色并行的第二通道）：`grid-charge` 45 度斜纹、`discharge` 实心、`idle` 空白细条、`solar-priority` 点阵、`hold` 截断线。相邻同类动作不做视觉合并（避免误读为一条长动作），但同 action 且相邻且无修正的连续块之间不画分隔线；`revised` 块右上加修正小三角，`overridden` 加换向标记。

### 4.4 轨道 C · 电量曲线

**数据结构**：由 `PlanSlot.socFrom` / `socTo` 串联成的折线点序列；起点取计划生成时刻的实际电量，终点为计划末态。

**映射规则**：`x` 与其余轨道对齐；`y` 用右轴，刻度以"够用几小时"标注（折算口径见 8.2）；电量百分比**不在默认视图出现**，深水区展开后才允许；**备电红线以下必须有水平参考线 + 人话标注**"再往下就不够你停电用了"，该参考线在任何状态下都不得隐藏；`hold` 段为水平实线、`idle` 段为水平点线（区分"有意不动"与"无事可做"）；若曲线穿越参考线，必须在穿越点加警示标记 + 悬停说明。

### 4.5 悬停提示内容契约（8 项，缺一不可）

| # | 内容 | 来源 | 人话要求 |
|---|---|---|---|
| 1 | 时段 | `start` / `end` | `02:00–04:00` |
| 2 | 电价 | `PricePoint` | "这会儿电价 €0.18 一度" |
| 3 | 电网费（开关打开时） | `GridFeeRule` | "另外还要付 €0.04 一度的输配电费用" |
| 4 | 计划动作 | `action` | "从电网买电充进电池" |
| 5 | 电量变化 | `socFrom` / `socTo` | "存进去 6 度电，够你家基础用电约 4 小时" |
| 6 | 该时段预期收益 | `earningEur` | "这一段预计帮你省 €0.42" |
| 7 | 原因一句话 | `reason` | 必须为因果关系（5.3） |
| 8 | 数据来源与更新时间 | `priceSource` | "电价来自 Nord Pool · 5 分钟前" |

补充：该时段若是**弃权机会**而非动作，第 4/5 项替换为"我没做这件事"+"我没做的原因"，第 6 项替换为"如果做了，理论上能赚 €{min}–{max}（预计）"；该时段被修正时追加第 9 项"原计划：02:30–04:00，我改了"，且不压缩前 8 项；浮层不得遮挡当前时段，靠右时段自动向左翻转；键盘焦点落在某时段时必须产生等价于悬停的**可读文本块**（读屏可获取），不能只有视觉浮层。

### 4.6 电价与电网费方向相反的高亮判定

**定义**：对每个时段 `t`，`P(t)` 为零售电价（`PricePoint`），`G(t)` 为电网费（分时输配电价 + 容量费/需量费的时段摊销 + 可控负荷减免，减免为负项），`E(t) = P(t) + G(t)` 为有效单价。

**判定三步（缺一不可）**：
1. **有效性前提**：`P` 与 `G` 均存在且时间戳新鲜度在阈值内。任一缺失则该时段标为"算不准"，不做高亮，只显示斜纹占位。
2. **方向判定**：比较相对当日中位数的偏离符号——`sign(P(t) − median(P))` 与 `sign(E(t) − median(E))` 不同即为候选；当 `|P(t) − median(P)|` 或 `|E(t) − median(E)|` 小于噪声阈值（示例 €0.01/度）时视为平坦，不判定，避免把无关紧要的差异渲染成告警。
3. **显著性判定**：按有效单价对全天时段排序，只有位次跨越超过阈值（示例：24 个时段中跨越 ≥ 8 位，96 个 15 分钟时段中跨越 ≥ 32 位）才高亮。**目的是避免每个时段都高亮——高亮一多就等于没有高亮。**

**呈现规格**：该时段加浅色底纹带 + 顶部文字"这里两条曲线打架"；文案固定为"这几个小时电价便宜，但输电配电的钱贵，加起来其实不划算"；反向情形（电价贵但网费有减免，合并后反而划算）文案为"这几个小时电价看着贵，但输电配电那边便宜，加一起其实还行"；点击高亮带显示 `P`、`G`、`E` 三个数值与各自来源。高亮时段**必须同时体现是否已被 Agent 避开**：已避开则归入 `A-PL-04` 的 `grid-fee-conflict` 弃权；未避开（例如与备电要求冲突）则必须解释为什么明知不划算还要做。**数量上限**：若高亮时段合计超过全天 25%，改为顶部一句总结"今天电价和网费方向差得比较多，我按加起来的实际价格来排"，避免视觉噪音。

### 4.7 粒度聚合与缺失处理

| 场景 | 规则 |
|---|---|
| 电价 15 分钟粒度 | 图上按小时聚合（价格取能量加权平均），悬停层保留 15 分钟明细 |
| 同一小时内动作变化 | 该小时块显示为分段混合块并标注"这一小时里换了做法"，悬停层给分段明细 |
| 电价 60 分钟、设备 15 分钟 | 粗粒度用于电价展示，细粒度用于动作与电量 |
| 数据缺失段 | 斜纹占位 + 文字"这段数据取不到"；**禁止插值、禁止沿用上一时段值**（§9.3） |
| 数据过期 | 该段显示为浅灰并标注"数据可能不是最新"，同时降级状态在 `A-TD-01` 与 `A-PL-08` 反映 |
| 跨日拼接 | 不做。计划图严格限定在本地自然日内，跨日连续计划由两张图表达 |

## 5. 动作 → 人话文案的生成规则

### 5.1 五种动作的定义

| `SlotAction` | 含义 | 与相邻取值的区分判据 |
|---|---|---|
| `grid-charge` | 从电网买电充进电池 | 有外购电量流入电池 |
| `discharge` | 电池放电供家庭使用 | 电池有电量流出 |
| `idle` | 无事可做：既不值得充也不值得放 | **不存在被主动放弃的机会**，只是没有机会 |
| `solar-priority` | 屋顶发的电优先给家里用，多余的存起来 | 核心是跟着光伏走，不主动买卖电 |
| `hold` | 有意不动：本来有机会，但我选择停住 | **存在被主动放弃的机会**，必须携带原因 |

> **`idle` 与 `hold` 的区分是硬规则**：`idle` 说明"没有值得做的事"，`hold` 说明"有值得做的事但我不做"。后者必须绑定一条 `ForgoneOpportunity`，否则数据校验不通过。

### 5.2 文案映射表

| `SlotAction` | 界面主文案 | 文案变体（按场景选择） | 附带说明行为 |
|---|---|---|---|
| `grid-charge` | **趁电价低，从电网买电存起来** | 深夜低价："趁这会儿电价最便宜，先把电存起来"；白天预充："白天先补一点，今晚太阳可能不够用"；极端低价含负价："这会儿用电不但不花钱，还有钱拿，我把它存起来" | 必须在"电量变化"列说明存了多少、够用多久 |
| `discharge` | **把电池里的电放出来给家里用** | 高价时段："这会儿电价贵，先用电池里的电，别买贵电"；满足家庭负荷："家里用电多，电池顶一下"；腾空间："先把地方腾出来，明天太阳出来好存" | 若同时逼近备电线，必须附"我留了 {X} 小时给你停电用" |
| `idle` | **这会儿什么都不用做** | 价格平淡："电不贵也不便宜，先不动它"；已到目标："电够了，先放着"；太阳能够用："太阳够用，不用花钱" | 无需绑定弃权项；但全天 `idle` 占比超 70% 时须在计划头解释"今天确实没什么可做的" |
| `solar-priority` | **先用屋顶发的电，多的存起来** | 晴天："白天用太阳发的，用不完的存起来"；多云："太阳不太稳，电池随时补上"；阴天："今天太阳指望不上，我按白天的预测安排" | 必须显示光伏预报区间与可信度词 |
| `hold` | **这段我先不动** | 低于门槛："赚得太少，不值得为它伤电池"；守住备电："留着电，万一下雨停电"；电池温度："电池这会儿太热或太冷，我不想折腾它"；预算不足："这个月的寿命额度用得差不多了"；用户锁单："你锁定了今天，我不动" | **必须联动 `A-PL-04`**，并给出"如果你希望我做，点这里" |

文案长度限制：主文案 ≤ 14 个汉字；原因列一句话 ≤ 30 个汉字，超出部分折叠到展开层。

### 5.3 "原因"字段的因果化要求

`PlanSlot.reason` 必须写成**用户可验证的因果关系**，结构为：**【触发条件（用户可感知）】+【我的动作】+【对你的好处（人话量）】**。禁止无因结论、循环论证与术语化压缩。

**五条正例**
1. "今晚 1 点到 3 点电价全天最低，我趁这两个小时把电存起来，够你家早上用 4 个钟头。"
2. "这段电价是今天最贵的，我先用电池里的电顶一下，这样你不用买贵电，一小时差不多省 4 毛。"
3. "电池现在有点热，我不想让它在这个温度下使劲，所以这两个小时先不动它。"
4. "这几个小时电价虽便宜，但输电配电那边贵，加一起反而不划算，所以我没充。"
5. "明天早上你出门前用电最多，我留了够用 9 小时的电，不会为了省这点钱把它用掉。"

**三条反例（必须被文案校验拦下）**
1. **术语化**："因 SOC 低于备电预留阈值，系统执行保守策略。"——用户读完不知道还剩多少电、够用多久。应改为："现在剩下的电不够你停电时用了，所以我先不放电。"
2. **循环论证 / 无因果**："这是算法计算出的最优时段。"——等于没说。应改为："这两个小时是今天电价最便宜的，所以选它。"
3. **只讲机制不讲好处**："执行电网侧需求响应指令，限制放电功率至额定值 50%。"——既暴露参数又没给用户好处。应改为："电网这会儿请我们少用点电，我配合了它，对你没影响，事后会有一笔奖励。"

**文案校验规则（原型期可自查）**：`reason` 超 40 个汉字判不合格；命中 SOC / DoD / EFC / kW / kWh / 额定 / 阈值 / 最优解 / 算法 判不合格；不含"因为 / 所以 / 趁 / 免得 / 为了 / 虽然"等因果或目的连接词需人工复核；不含"小时 / 度 / 毛 / 块"等用户可感单位判不合格；含"保证 / 确保 / 一定省"判不合格。

## 6. 弃权（Forgone Opportunity）规格

### 6.1 与 §6.4 弃权清单的映射

`E17.reasonKind` 的 8 种取值覆盖 §6.4 的 10 条理由，其中两处合并：

| §6.4 条目 | 映射 | 说明 |
|---|---|---|
| 1 预期净收益低于门槛 | `below-threshold` | — |
| 2 触碰或逼近备电预留 | `backup-edge` | — |
| 3 电池温度不利或健康度异常 | `battery-temp` | — |
| 4 电价与电网费方向相反 | `grid-fee-conflict` | — |
| 5 当地不允许或极不划算的上网行为 | `below-threshold` | **合并**：本质仍是"算下来不值得"，但文案必须点明是"卖回电网不划算"，用子原因区分 |
| 6 电网限功率或需求响应指令 | `outage-protect` | **合并**：都属于"外部约束下优先保供电"，文案用子原因区分 |
| 7 预报不确定性过高 | `uncertainty` | — |
| 8 家中留有需要供电的设备 | `outage-protect` | — |
| 9 循环预算余额不足 | `budget` | — |
| 10 用户已锁单 | `lock` | — |

> 合并理由：界面上"为什么不做的原因"超过 8 种后用户不再区分，只会当噪音。合并后靠子原因文案保持精度——例如同为 `below-threshold`，一条写"卖回电网的价格太低，扣掉损耗还亏"，另一条写"价差太小，赚的不够补电池损耗"。

### 6.2 八种原因的文案模板与界面呈现

| `reasonKind` | 文案模板（界面直接使用） | 界面呈现 | 覆盖按钮 |
|---|---|---|---|
| `below-threshold` | "凌晨 1 点到 3 点本来可以赚 €{值}（预计），但这点差价扣掉存取的损耗和电池折旧，不值得为它多跑一次。" | 卡片默认样式；展开后列三行构成——能赚多少 / 损耗与折旧多少 / 净下来多少 | 可用（L2 一键） |
| `backup-edge` | "下午 6 点到 8 点本来是放电的好时候，但那样放电，你家停电时就只剩够用 {X} 小时了，低于你定的 {Y} 小时。我没动。" | 带备电标识；展开显示"放电后的余量 → 你的要求线"对照 | 可用，但**必须走影响告知**：显示覆盖后的停电可用小时数，低于要求线时二次确认 |
| `grid-fee-conflict` | "这几个小时电价便宜，但输电配电的钱贵，加起来反而多花钱，所以我没做。" | 与 `A-PL-05` 高亮带联动，点击可跳到图上该时段 | 可用（L2 一键） |
| `battery-temp` | "电池现在{热/冷}（人话温度描述），这个状态下使劲用它会明显伤寿命，所以我让它先歇着。" | 带电池状态说明；展开给"温度回到合适区间后我会重新算" | 可用，但需说明"这么做可能让电池更快老化，你确定吗" |
| `budget` | "这个月为了护电池我给自己定了额度，现在已经用得差不多了。再做这次，剩下的额度就只有 {值}。" | 带预算进度条（人话刻度：还剩多少）；展开给"如果做，电池寿命大概多用掉 {值}" | 可用，但属**超额动用循环预算**，须走 L2 确认；若需突破预算上限则转 L3 申请（本模块只准备材料） |
| `lock` | "这段本来可以做点事，但你已经把今天的计划锁住了，我不动它。" | 置顶 + 锁形矢量图标；明确写"这是你自己锁的" | 可用；点击即"解除锁定并执行"，需二次确认并提示"解锁后我可能还会调整别的时段" |
| `uncertainty` | "这段时间的天气和电价我不太看得准（{预报变了 / 数据更新慢}），怕算错，所以先不动。" | 带可信度词"不太确定"；展开说明"等数据清楚了我再算一次" | 可用，但需告知"这样做有可能不划算，也有可能是笔好买卖" |
| `outage-protect` | "你家{s区域}最近停过 {N} 次电，我宁愿把电留着，也不为了这点差价把它用掉。" | 带保供标识，置顶优先级仅次于 `lock` | 可用，但**风险最高**：必须显示"如果这期间真的停电，你会少用 {X} 小时"，二次确认 |

**共同呈现要求**：① `A-PL-04` 至少展示 1 条（§4.2 硬要求、验收项 A8）；数据侧确实返回 0 条时须由后端显式回传"已核查无弃权"才允许显示空态文案。② 排序默认按"理论上能赚多少"降序，存在 `lock` / `outage-protect` / `backup-edge` 时这三类提到最前（安全性解释优先于金额）。③ 每条必须可展开，展开后至少给三项证据——时段、能赚多少（带区间）、不做的那条具体理由的依据来源与时间戳。④ **不使用红色**：弃权是"我主动选择不做"不是告警，仅 `outage-protect` 与 `backup-edge` 允许用琥珀色。⑤ 数字都带区间，"理论上能赚 €0.28–0.41（预计）"，不给单点。

### 6.3 "如果你希望我做，点这里"的覆盖流程

**步骤 1 入口**：每条弃权卡片右下角按钮，文案固定为 `[如果你希望我做，点这里]`；键盘可达、可 Tab 聚焦、有可见焦点环。

**步骤 2 全屏确认页（不用模态弹窗）**，必须包含五块内容：① 你希望我做什么（一句话复述该机会：时段 + 动作）；② 我原本为什么不做（原文照搬弃权原因，不弱化）；③ 如果做会有什么变化（三行对照：收益变化预计区间、停电可用小时变化、电池寿命消耗变化——**"省钱"与"保险"的代价必须同时出现**，不允许只展示好处）；④ 风险提示（按 `reasonKind` 差异化：`backup-edge` / `outage-protect` 显示"这会让停电时可用的时间从 {X} 小时降到 {Y} 小时"；`budget` 显示"这会让电池寿命额度多用掉 {值}"；`battery-temp` 显示"在这个温度下用电池，老化会快一些"；其余显示"这样做很可能不划算 / 我算不准"）；⑤ 两个按钮 `[就这一次]` `[以后都按我说的来]`（§8.5 强制分流，不可跳过）。

**步骤 3 分级处理**

| 情形 | 级别 | 处理 |
|---|---|---|
| 不触及任何红线（`below-threshold` / `uncertainty` / `grid-fee-conflict`） | **L2 一键** | 用户确认后当日生效，记为一次性例外 |
| 逼近或触碰备电线（`backup-edge` / `outage-protect`） | **L2 + 影响告知** | 确认后执行、留痕，并在当日日报明确记录"这是你要求做的" |
| 需超额动用循环预算（`budget`） | **L2 + 影响告知** | 同上；若需突破预算**上限**则转 **L3** |
| 需修改备电红线 / 最低电量 / 预算上限本身 | **L3 人工专属** | 本模块**不执行**，只生成申请材料并跳 F5 流程（Agent 只能建议和准备材料） |
| `lock` 类覆盖 | **L2** | 先解除锁定（二次确认），再执行 |

**步骤 4 结果反馈（不可省略）**：立即反馈"按你说的办了。这一段我改过来，撤掉的原因是……"；同步更新 `A-PL-02` 图上动作块（原弃权空心标记 → 实心动作块），并在 `A-PL-07` 生成一条"已告知"的修正记录；若用户选"以后都按我说的来"，生成规则变更任务（可能涉红线则走 L3），由 F4 完成分流留痕。

**步骤 5 留痕**：写入 `AuditEntry`（谁、何时、改了什么、为什么），任何覆盖都不得原地覆盖原记录（§7.4 第 6 条）。

### 6.4 弃权纪律

① 弃权不是沉默，弃权是必须解释的动作（§6.4 原文）。② 弃权记录与执行记录同等重要，不允许只存执行记录。③ 用户覆盖后 Agent **不得反复劝说**（§6.6 第 12 条）：告知一次风险即可，用户坚持就执行。④ 弃权项超过 5 条时默认只展开前 3 条 + "还有 N 条"，避免造成"我什么都没做"的错觉。⑤ 弃权文案不制造焦虑：不说"你错过了 €3.2"，只说"我看过了，没做，原因是……"。

## 7. 日内滚动修正（F3）规格

### 7.1 触发条件清单

| # | 触发源 | 判定 | 修正类型 | 级别 | 告知 |
|---|---|---|---|---|---|
| 1 | 电价曲线日内被修订（日前 → 日内更新） | 重叠时段价差超过门槛 | 重排动作时段 | 按 7.2 | 超阈值必须告知 |
| 2 | 电价数据源失效或恢复 | 新鲜度超阈值 / 恢复 | 切保守安排 / 恢复原计划 | L2 | **必须告知** |
| 3 | 光伏预报修正（云量变化、置信度下降） | 预报电量变化超阈值 | 调整充电量与光伏优先时段 | 按 7.2 | 超阈值必须告知 |
| 4 | 实际负荷偏离基线（大功率设备启动） | 实测功率持续偏离 `LoadSeries` 预测 | 缩短放电、提前补充 | 按 7.2 | 仅大偏离告知 |
| 5 | 光伏实际出力低于预测 | 出力偏差持续超阈值 | 减少白天依赖光伏的动作 | 按 7.2 | 超阈值必须告知 |
| 6 | 电池状态变化（温度越界、可用功率下降、健康度异常） | 触碰 `Guardrail` 系统强制项 | 停止相关动作 | L2 / L3 | **必须告知** |
| 7 | 用户手动操作设备 | 与计划冲突 | 让位给用户操作并重排 | L1 | 不告知（记日志） |
| 8 | 停电 / 电网限功率 / 需求响应指令 | 外部约束生效 | 立即切安全模式或限功率 | L3 | **立即告知** |
| 9 | 用户锁定当日计划 | `EnergyPlan.locked = true` | 仅安全原因可覆盖 | — | 覆盖时**必须告知** |
| 10 | 用户偏好 / 红线变更生效（L3 审批通过） | 新版生效 | 按新边界重算全天 | — | 告知"我会怎么变" |
| 11 | 市场策略包变更 / 全局熔断 | 版本变化或 `health = fused` | 切保守模式 | L2 | **必须告知** |
| 12 | 家庭画像被用户纠正 | 用户否认某条猜测 | 重算基线负荷与备电小时 | L1 | 不告知（记日志，日报提及） |
| 13 | 循环预算余额变化 | 余额不足以支撑后续计划 | 削减后续动作 | 按 7.2 | 超阈值必须告知 |
| 14 | 手动补录电价 | 数据源恢复的一种 | 重算当天剩余时段 | — | 告知"按你补的数据重算了" |

### 7.2 静默阈值规则

**静默修正**（不推送，仅写 `PlanRevision` 与日志）必须**同时满足**以下全部条件：① 当日预计净收益变化绝对值 ≤ **€0.20**；② 明早备用余量变化 ≤ **0.5 小时**；③ **动作类型序列不变**（不出现"原本充电改成放电"这类反转）；④ 时段边界移动 ≤ **30 分钟**且功率调整幅度 ≤ **20%**；⑤ **不影响任何弃权项**（不新增弃权，也不把已弃权的机会变成执行）；⑥ **未锁单**且不涉及任何 `Guardrail` 系统强制项；⑦ 不发生在 23:00–07:00 之间（该区间**可以执行**修正，但不得推送；非紧急内容推迟到 07:00 后并入日报）。

超阈值即视为**大偏差**，进入 7.3 的告知判定。**合并规则**：同日第 3 次及以上的静默修正，即使每次都在阈值内，也必须合并告知一次——"今天电价变了几次，我跟着微调了 3 处，都是小改动"，避免"静默"变成"隐瞒"。

### 7.3 必须告知的判定

| # | 判定 | 告知方式 | 文案必含 |
|---|---|---|---|
| 1 | 触碰或逼近备电预留边缘 | 推送（L2 请示）+ 计划页显著条 | 发生了什么 / 我做了什么 / 你需要做什么（或"你什么也不用做"） |
| 2 | 需超额动用循环预算 | 推送（L2 请示） | 同上 + 对电池寿命的影响 |
| 3 | 电价数据源失效 | 推送（L2 请示） | 同上 + "我按保守方式安排" |
| 4 | 当日预计净收益下降超过 €0.50 | 日报内（低优先） | "今天比原计划少赚了 €{值}，原因是……"（宁少报不多报） |
| 5 | 计划被安全原因覆盖 | 推送（L3 立即）+ 计划页覆盖条 | 同上 + 需要谁处理 |
| 6 | 锁单期间被覆盖 | 推送 | 同上 + "我动了你锁的计划，因为……" |
| 7 | 动作类型反转（充电改放电或反之） | 推送 | 同上 + 原因 |
| 8 | 单日修正次数 ≥ 3 | 日报 + 修正记录置顶 | "今天电价变得比较频繁" |
| 9 | 停电、电池告警、异常跳变 | 多通道立即通知 | 同上 + 当前状态 |
| 10 | Agent 自己不确定（数据不足） | 计划页声明 + 日报 | "我不确定，所以我选了保守的做法" |

**不告知**（记日志即可）：常规计划内动作、阈值内的静默修正、次日计划的常规生成、画像的日常更新。**通知纪律**：23:00–07:00 禁止推送非紧急通知（§4.12）——落在该区间的 L1/L2 告知推迟到 07:00 后并入早晨简讯，L3 紧急不受此限。

### 7.4 修正后时间线如何呈现"改了什么"

**原则：只呈现差异，不呈现两份完整计划的对照**（两份对照会让用户看不出重点）。

**呈现五要素**：① **顶部说明条**（出现在 `A-PL-06` 与 `A-PL-01` 顶部，并在今日页 `A-TD-03` 下方一行摘要），固定句式"我改了这个计划，因为……"+ 影响一段 + 是否需要用户做什么；② **图上幽灵对照**：原时段以虚线幽灵块保留在轨道 B、新时段为实心块，两者之间画细连接线表示"从这里挪到了那里"；③ **单行差异文案**（出现在 `A-PL-03` 与 `A-PL-07`）：格式为"原 `02:00–04:00` 充电 → 现 `01:00–03:00` 充电"，**不使用左右双图对比**；④ **修正记录卡**每条含五字段——时间、原因（人话）、幅度（人话）、类型（静默 / 已告知）、对三问数字的影响；⑤ **影响回写**：修正后立即重算并更新 `A-TD-02` / `A-PL-01` 的三问数字，数字旁短暂标注变化方向（"比原计划少赚 €0.3"），不做闪烁动画（尊重 `prefers-reduced-motion`）。

**禁止项**：禁止用删除线表示"原计划作废"却不给新计划（用户会以为计划被破坏）；禁止把修正写成技术事件（"重新优化完成"）；禁止默认展开超过 5 条修正记录（超出折叠）；禁止在修正说明中使用"重新计算""重新调度""算法调整"这类词。

### 7.5 锁单与安全覆盖的优先级顺序

多个约束同时作用时，按以下顺序**从高到低**裁决，高优先级无条件压制低优先级：

| 顺序 | 约束 | 说明 |
|---|---|---|
| 1 | **硬件与安全强制** | 电压、保护阈值、并网参数、设备自我保护、电网限功率与合规约束；Agent 永不可触碰（§1.6、§9.2） |
| 2 | **人工接管（Manual Hold）** | 接管期间 Agent 完全静默，不执行任何优化动作（§5.3 硬规则 2） |
| 3 | **安全模式** | 停止一切优化，交回设备默认行为 |
| 4 | **备电预留红线** | 不可协商项，任何优化不得侵占（§6.6 第 2 条） |
| 5 | **用户锁单** | 用户明确意志；锁单期间**只有第 1–4 类约束可以覆盖**，且**必须告知** |
| 6 | **循环预算上限** | 硬预算；余额不足则不执行并说明（§6.3 第 4 条）；可被 L2 临时突破，不得静默突破 |
| 7 | **用户偏好与方向性调整** | 省钱 / 保险 / 多留备电的配比 |
| 8 | **经济性优化** | 收益最大化，**永远排在最后** |

**三条关键裁决规则**：① **安全覆盖锁单必须告知**——锁单不阻断安全动作，但覆盖后必须按 7.3 第 6 条推送并在计划页显示覆盖条，默认文案"我动了你锁的计划，因为{安全原因}。等它过去我就按你锁的来"。② **锁单 + 预算冲突**——若用户锁定的计划本身超出循环预算上限，在锁单生效**前**提示并需要 L2 确认（"这张表里有一次动作会让电池多用掉 {值}，比你定的额度多一点，还锁吗？"），用户坚持则留痕执行并在电池页显示预算超支标记。③ **安全动作与用户意愿冲突时**——即使逻辑上更优也不能跳过第 1–4 类，Agent 必须先执行安全动作然后**立即解释**（§6.7 末尾：先照做，再把风险和理由讲清楚）。

**恢复顺序**：约束解除后 Agent 必须主动汇报"我恢复了，接下来我会这样做"，且**不直接跳回全自动**——按 §5.3，从 Safe 先回到 Conservative，需用户明确确认后才回到 Auto。

## 8. 三问数字的计算口径

> 业务级口径描述，不涉及代码实现。三个数字的对外展示都必须满足：带时间戳、带区间、可点开看构成、不出现裸术语。

### 8.1 预计净收益（含区间）

**主展示值** `expectedNetEarning.likely`；**必须同时展示区间** `min`–`max`，且 `min < likely < max` 严格成立。

**输入字段**：电价曲线 `E13 PricePoint[]`（各时段买卖单价）；电网费规则 `E14 GridFeeRule`（输配电费、容量费/需量费、可控负荷减免）；计划动作序列 `E16 PlanSlot[]`（各时段充放电量与方向）；光伏预报 `weather.solarForecastKwh` + `solarConfidence`（自用替代量）；家庭基础负荷 `E08 LoadSeries` + `E06 HouseholdProfile`（自用量与被替代的购电量）；往返效率（对用户表述为"存进去 100 度，取出来大概 90 度"，用于扣减）；电池折旧单价（电池参数 × 用户护电池强度）；基线收益 `baselineEarning`（出厂策略，用于算差额）。

**算式（业务级，遵循 §6.2 唯一口径）**：净收益 = 光伏自用节省 + 低价充电节省 + 高价放电节省 + 电网费规避 − 往返效率损失 − 电池循环折旧 − 税费与上网费用影响。

**区间生成（三情景法）**：悲观 `min` 取电价不利侧 + 光伏预报下沿 + 家庭负荷画像上沿（用电多则自用少）；中性 `likely` 取当前电价曲线 + 光伏预报中值 + 负荷画像均值；乐观 `max` 取电价有利侧 + 光伏预报上沿 + 负荷画像下沿。

**纪律**：① 区间宽度不得为 0，三项不确定性都很小时取 ±5% 作为最小带宽并在展开层说明"这次误差很小"；② 不得人为收窄区间以获得好看的数字；③ **只显示净收益**，毛收益仅在看构成的展开层作为计算过程出现（§7.4 第 4 条）；④ 与出厂策略的差额必须与净收益同时出现且注明"预计"；⑤ 当日已过部分以 `DecisionLog.outcome.actualEur` 为已发生值、剩余时段用计划值合并后仍须给区间，并标注"已发生 €X，接下来预计 €Y"。

### 8.2 明早备用余量（小时）

**主展示值** `backupHoursTomorrow`，单位**小时**，界面文案"够你家基础用电约 {X} 小时"。**百分比形式默认不出现在界面**，仅深水区展开后允许。

**输入字段**：计划末态电量（由 `PlanSlot[]` 推导的次日日出前电量，作分子基础）；用户要求的停电可用时长（`Guardrail` 中"停电时够用多久"，4/8/12/自定义小时，作对照线与判据）；停电时的基础负荷组合（`HouseholdProfile` 中"停电时你最需要保证什么"——冰箱 + 照明 + 网络及医疗设备等附加项，作折算分母）；设备可用电量与功率受限（`BatteryState.usableKwh`、温度导致的降功率，作折减）；备电预留红线（不可动用的保留量）。

**算式（业务级）**：明早备用余量（小时）=（次日日出前的可用电量 − 不可动用的保留量 − 温度或保护导致的折减量）÷ 停电基础负荷（平均功率，取自用户勾选的必须保证设备组合）。

**规则**：① 分子必须是**次日日出前**（或用户设定的早晨时刻）的电量，不是此刻电量——用户问的是"明早"；② 分母使用**用户勾选的停电必须保证设备组合**，不是全天平均负荷，用错会让用户误判；③ 结果**向下取整到 0.5 小时**（宁可少说不可多说）；④ 不足 1 小时显示"不到 1 小时"并追加建议"要不要我多留一点电给停电用"；⑤ 与用户要求线的对照必须可见——"你要求 8 小时，我留了 9 小时"，达标用中性色，不达标时该数字必须有明确标识（这是本产品最不能失守的一条线）；⑥ 因次日早晨负荷有波动，展示可用"约 {X} 小时（{X−0.5}–{X+0.5} 小时）"，但对外主值取最保险的一侧。

### 8.3 本次动用循环（等效满循环）

**主展示值** `plannedEfcUsed`，界面文案"相当于电池寿命的 {Z}%"。**不出现"等效满循环""EFC""循环次数"等术语**，深水区展开后允许显示"用掉 {N} 次满充满放"。

**输入字段**：各时段充放量（`socFrom` / `socTo` + 电池容量，用于算放电深度）；动作类型（仅放电类计入）；往返效率（修正实际放电量）；质保循环上限 `warrantyEfcLimit`（换算寿命百分比的分母）；循环预算余额 `E22 CycleBudget`（月 / 年两条，用于预算校验与过半提示）；用户护电池强度（影响预算默认值与文案）。

**算式（业务级）**：本次动用循环 = Σ（每个放电动作的放电电量 ÷ 电池额定容量）；展示值 = 本次动用循环 ÷ 质保循环上限 × 100%。

**规则**：① **只有放电计入循环消耗**（放电深度累加即等效满循环的行业近似），充电不单独计入，其代价已通过往返效率损失体现在收益口径中（8.1）；② 展示保留两位有效数字（如"0.02%"），不得出现"0.0%"这类看起来是零的结果，小于最小可显示值时写"几乎可以忽略"；③ 同时显示与预算的关系（来自 `CycleBudget`）——"这个月你给自己定的额度还剩 {值}，今天用掉的是其中一小部分"；④ 预算消耗过半时（`warningThreshold`）本数字旁必须出现说明条，让用户有心理准备而不是月底突然降级（§6.3 第 5 条）；⑤ 因实际放电量受负荷波动影响，展示可用"约"并给 ±10% 带宽，**不得为了让数字好看而下调**；⑥ 记账数据必须可作为质保争议证据（记录温度、深度、次数），界面展示值与内部记账值必须一致，不得两套口径（§6.3 第 7 条）。

### 8.4 三个数字的共同纪律

① 可回溯——每格都能点开看到构成、输入来源与时间戳（P6）。② 带区间——预测值一律给区间，单点值只用于事后回看（§7.4 第 3 条）。③ 不出现裸术语——SOC / DoD / EFC / kW / kWh 在默认层一律不出现。④ 不承诺——不出现"保证省 XX 元"（§4.0 文案规则 3）。⑤ 宁少报不多报——不确定时一律取保守侧（§4.6 诚实原则 3）。⑥ 数据缺失时不假装——任一输入缺失则该格显示"暂时算不准"并说明原因，不得用最后已知值顶替（§9.3）。⑦ 勾稽一致——今日页与计划页的同名数字口径完全一致，不得出现两页数值不同。

### 9.3 状态通用规则与文案

**加载中**：骨架屏行高与列宽必须与最终内容一致，禁止布局跳动；不用旋转 spinner 表示"在努力"；超 8 秒未返回追加"网络有点慢，稍等一下"；超 30 秒显示"暂时没取到" + `[重试]`，不无限等待。

**空数据**：必须回答"为什么是空的"+ 一个明确的下一步动作。例外——`A-TD-05`（L2 队列）为空是**好状态**，整块隐藏即可；`A-PL-04`（弃权栏）**不允许真空**，须由后端显式确认"已核查无弃权"才允许显示空态文案。

**降级运行**：顶部必须有模式标识 + 原因 + 恢复条件（由 `A-TD-01` 承担全局展示责任，任何页面都能看到）；文案不得使用"系统异常""服务不可用"这类技术说法，必须说人话（"电价数据断了，我改用最保守的方式安排"）；降级期间**不允许隐藏任何查看路径**（用户仍可看完整计划、修正记录、弃权栏）。

**数据源失效**：明确标注"该数据暂不可用"并显示系统已采取的降级策略（§4.0）；**不得用最后已知值冒充实时值**，必须显示历史值时须显式标注"这是 {时间} 的数据，不是现在的"；失效本身若属 L2 触发条件，必须走 7.3 告知流程。

**影子期**：全站文案替换规则——凡涉及"我做了什么"一律改为"如果按我说的做"或"我建议"；三问数字照常展示但必须标注为假设值；不得使用"省了多少"的既成事实语气；影子期结束日期必须可见且与引导页一致；**不得产生任何实际调度动作，界面上不得出现"已执行"状态**。

**已锁单**：锁形标识必须使用**矢量图标而非 emoji**，出现在结论卡、时间线锁定区间、计划头、动作表四处；锁定后 Agent 只在**安全原因**（优先级 1–4）下覆盖且覆盖必须告知；锁定期间 `A-PL-07` 显示"没有修正"，被覆盖时显示该次修正并说明原因；解锁必须二次确认并提示"解锁后我可能还会调整别的时段"。

**被安全覆盖**：覆盖处必须显示"我改了这个计划，因为……"（§4.2 关键交互）；文案为三段式——发生了什么（人话）/ 我做了什么 / 你需要做什么（或"你什么也不用做"）；覆盖必须出现在三个位置——`A-TD-03` 下方摘要、`A-TD-06` 受影响行、`A-PL-06` 顶部完整说明条；恢复后由 Agent 主动汇报"我恢复了，接下来我会这样做"（§5.3），且**不直接回自动模式**，需用户确认（§5.3 硬规则 3）。

**权限不足**：明确标注该操作属于 L2 / L3，给出"谁有权做"与发起路径（§4.0）；L3 操作**只提供申请入口**，不提供直接执行（Agent 只能建议和准备材料）；安装商角色**不能**直接修改客户红线，只能发起申请或引导客户自行操作（§4.11 硬约束）；权限不足的按钮不得完全消失（会让用户以为功能不存在），而是置灰 + 说明。
