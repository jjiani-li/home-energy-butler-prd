# 拆解文档 01 · 信息架构与导航规格

> 上游依据：`docs/prd/00-总PRD-沃太家庭能源管家Butler-v2.0.md`（第三章 信息架构与核心用户旅程、第四章 页面级需求规格、第五章 运行状态机、第十一章 MVP 范围与验收标准）
> 本文性质：把总 PRD 的"有哪些页面"落成"路由、导航、状态、跳转、验收"五件事的界面契约。不重复业务立场与算法口径，只定义开发可直接实施的界面规则
> 术语与文案约束沿用总 PRD §4.0 与附录 A：界面禁出现 SOC / DoD / EFC / 裸 kW；全文禁 emoji

## 1. 拆解原则

### 1.1 这份拆解补的是哪一段空白

总 PRD 第三章给出 12 个页面与 4 个一级导航分区，第四章给出每页的目标与元素，但两者之间仍缺一段可执行的东西：用户点一下到底去哪、一个页面到哪结束、降级时哪些区域必须变、同一个数字在几个页面出现时是否长得一样。本文只解决这一类问题。

### 1.2 一级导航与二级导航的判据

| 编号 | 判据 | 具体含义 | 自检方法 |
|---|---|---|---|
| J1 | 场景归组，不按数据对象归组 | 一级项是一类"用户为什么打开 App"的场景，不是一类数据实体 | 能否用一句"我要……"覆盖该分区全部二级项，能则成立 |
| J2 | 数量恒定 | 一级项固定 4 个，不随运行模式、用户角色、所在市场增减 | 新需求若要求加一级项，必须先从现有 4 项中移除一项 |
| J3 | 二级项上限 4 个 | 单分区内二级项不超过 4 个，侧边栏不允许出现滚动才能看全 | 超过 4 个即为分组失败，需重新归组 |
| J4 | 层级深度不超过 3 层 | 一级 → 二级 → 详情，详情页不得再挂下一级列表页 | 从任一页面到任一数据不超过 2 次点击 |
| J5 | 可独立指向的视图给独立路由 | 凡会被推送、外链、安装商后台直接引用的视图，一律独立路由，不做成折叠区 | 安装商能否发一个链接给客户直接定位到该视图 |

四个一级分区的场景归属：

| 一级分区 | 用户的那句话 | 二级项 |
|---|---|---|
| 今日 | 我要知道我家今天怎么样 | 今日 |
| 计划 | 我要看管家打算做什么，以及它已经做过什么 | 计划、决策、异常 |
| 设备 | 我要看我家这套系统本身是什么状态 | 家庭、电池、市场 |
| 账户 | 我要看结果、改规则、找人处理 | 收益、协作、安装商、设置 |

### 1.3 页面粒度的判据

| 编号 | 判据 | 具体含义 |
|---|---|---|
| G1 | 一屏一结论 | 首屏只承载一个可独立成立的人话结论。两个互不依赖的结论拆页；一个是另一个的展开则不拆 |
| G2 | 四态可独立定义 | 能独立定义加载 / 空 / 降级 / 权限四态的才够格成页；无法独立定义者（图例、说明块）降级为页内模块 |
| G3 | 操作与留痕同页 | 涉及 L3 的变更入口与其审批状态、留痕必须落在同一页面内，不允许一次操作跨三个页面 |
| G4 | 责任主体分路由 | 家庭侧页面与渠道/运营侧页面必须不同路由，靠角色可见性切换，不混排在同一页面 |
| G5 | 锚点与子路由的判定 | 见下表 |

| 情形 | 采用 | 实例 |
|---|---|---|
| 可被独立深链、有独立四态、会作为跳转矩阵的目标出现 | 子路由 | `/decisions/:decisionId`、`/incidents/:incidentId` |
| 只是同一结论的向下展开、无独立四态、离开上下文即失去意义 | 页内锚点 | `/plan#forgone`、`/battery#budget` |
| 硬规则 | 锚点变化**不改变**二级导航高亮；子路由变化**改变**二级导航高亮 | — |

### 1.4 与总 PRD 的两处显式取舍

**取舍一：建议模式标识不引入第二个强调色。** 总 PRD §5.1 描述建议模式为"蓝色条"，但 §3.2 规定"仅保留一个强调色，红/琥珀只用于语义告警"。本文按 §3.2 执行：建议模式用中性色 + 1px 虚线边框表达"计划尚未生效"，蓝色不进入系统色板。理由：单强调色是"管家正在为你工作"这一信号的独占语义，多一个颜色就稀释一次。

**取舍二："一键回退出厂策略"落地为一次模式迁移，不新增第七个模式。** 总 PRD §5.1 的"保守模式（自发自用 + 备电优先）"与 §9.4 的"出厂策略"语义等价。回退动作定义为：迁移到 `conservative` + 写入一条 L2 留痕 + 通知安装商后台，不改动历史数据与收益记录。

### 1.5 路由命名与守卫规则

1. 路径一律英文小写、以短横线分隔，不使用下划线、驼峰与中文。
2. 列表页的路由不带参数，筛选条件走查询串（`?level=L2`）；详情页的路由带 ID（`/decisions/:decisionId`）。
3. `/onboarding` 本身不渲染内容，访问即 302 到 `/onboarding/ask`。
4. **引导守卫**：引导未完成时，访问除 `/settings#privacy`、`/settings#about`、`/onboarding/*` 之外的任何路由，一律重定向到 `/onboarding/ask`，并在引导完成后回到原目标路由。
5. 未知路径一律渲染 404 状态块（复用 §4.5 的权限不足模板，文案改为"这个地址不存在"），不静默跳回首页。

## 3. 导航规格

### 3.1 侧边栏结构

宽 236px（档位 M 折叠为 64px），固定不滚动；仅二级列表区在超出时可滚动（正常不会触发，因 J3 限制）。顺序固定，不随使用频率自动重排——位置记忆是降低认知负担的基础设施。

```
[品牌区 56px]  沃太家庭能源管家                          [版本号]
[分组标题]  今日
  今日        /today        当前项：2px 强调色左标尺 + 图标文字转强调色 + 字重 500
[分组标题]  计划
  计划        /plan
  决策        /decisions
  异常        /incidents    未闭环事件数 > 0 时右侧显示计数徽标
[分组标题]  设备
  家庭        /household
  电池        /battery      循环预算过半时，左侧出现琥珀色 1px 竖线
  市场        /markets      仅角色 = 安装商 / 运营 时渲染
[分组标题]  账户
  收益        /reports
  协作        /collaborate  L2 待确认数 > 0 时右侧显示计数徽标
  安装商视图  /installer    仅角色 = 安装商 / 运营 时渲染
  设置        /settings
[底部区]  角色切换器（业主 / 安装商 / 沃太运营）｜ 数据口径说明 → /settings#about
```

分组标题为 11px、字距 +0.06em、颜色 muted，**不可点击、不参与 Tab 序列**，仅作视觉分区。

### 3.2 图标语义（矢量图标描述，禁止 emoji）

统一规格：20×20 viewBox、1.5px 线宽、直角端点、无填充、单色（默认 ink-3，当前项转强调色）。当前项**不使用彩色填充图标**，只通过颜色与左标尺表达状态。

| 导航项 | 图标语义描述 | 想表达的意思 |
|---|---|---|
| 今日 | 一条水平时间轴，轴上一个实心圆点位于中点偏左 | 此刻所在的时点 |
| 计划 | 一条 24 格刻度条，其中连续三格被填充为实心 | 被安排好的时段 |
| 决策 | 自同一节点分出两条路径，一条实线一条虚线 | 显式选择，以及被放弃的分支 |
| 异常 | 一个等边三角形轮廓，内部一条竖直短线 | 中断与偏离 |
| 家庭 | 房屋外轮廓，内部一条折线（负荷曲线） | 住在房子里的用电行为 |
| 电池 | 矩形外框，内部两格填充，右上角一个短端子 | 设备实体本身 |
| 市场 | 一个正圆，内含两条经线与两条纬线 | 地区与规则差异 |
| 收益 | 三根依次升高的竖直条，底部一条基线 | 对照与增量 |
| 协作 | 两条并列竖轨，中段以一个双向箭头连接 | 人机之间的交接点 |
| 安装商 | 三栋并列的简笔建筑轮廓，最左侧一栋加内边框 | 多客户列表中被选中的那一个 |
| 设置 | 两条水平滑杆，滑杆上各有一个刻度点 | 可调参数 |

引导（`/onboarding`）不在一级导航内，无导航图标。

### 3.3 顶栏

高 56px，固定吸顶，1px 下边框表达层级（不用投影），内容分三段。

| 位置 | 内容 | 规则 |
|---|---|---|
| 左段 | 面包屑（见 §3.4） | `/today` 时替换为应用名"沃太家庭能源管家" |
| 中段 | 全局运行模式条（见 §4.1） | 常驻不可关闭；最窄 220px；档位 S 及以下仅显示模式名 |
| 右段 | 数据新鲜度微标签、角色切换器、溢出菜单 | 溢出菜单第一项为"一键回退出厂策略"（见 §4.2） |

### 3.4 面包屑规则

1. 最大 3 段：`一级分区 > 页面 > 详情`；超过 3 段即层级设计错误，回到 J4 重新判定。
2. `/today` 不显示面包屑，显示应用名。第二级页面（如 `/plan`）只显示单段`计划`，不写`计划 > 计划`。
3. 详情页第三段使用**对象的人类可读名称**，不使用 ID。
   例：`/decisions/:id` → `计划 > 决策 > 09-14 夜间充电`；`/incidents/:id` → `计划 > 异常 > 停电导致备电切换`；`/markets/:id` → `设备 > 市场 > 德国`。
4. 末段（当前页）不可点击、颜色 ink；前序段可点击、颜色 ink-3。
5. 档位 S 及以下折叠为"返回箭头 + 当前页名称"，返回箭头指向父级路由。

### 3.5 当前项高亮规则

| 对象 | 高亮条件 | 高亮形态 |
|---|---|---|
| 一级分区项 | 当前 URL 路径前缀命中该分区内任一路由 | 2px 强调色左标尺 + 图标与文字转强调色 + 字重 500 |
| 二级导航项 | 当前 URL 的 path 精确匹配该二级项路由 | 2px 强调色左标尺 + 字重 500；不使用背景填充 |
| 详情页 | 高亮其父列表项（`/decisions/:id` 高亮"决策"） | 同二级导航项 |

硬规则：

1. **hash 变化不改变高亮。** 从 `/plan#head` 滚到 `/plan#forgone` 不产生高亮变化。
2. 任一时刻有且仅有一个一级项与一个二级项处于高亮态。
3. 角色切换导致当前页不可见时（例如运营角色停在 `/markets` 后切回业主），页面不动，导航高亮置空，页面顶部提示"当前角色无法查看本页，请切换角色"并附切换按钮。
4. 键盘焦点环与高亮是两套独立视觉：焦点环为 ink 色 2px 外描边 + 1px 偏移，高亮为强调色左标尺；两者可同时出现，不得互相替代。

### 3.6 移动端折叠规则

触发条件是**布局宽度小于 1024px**，不是设备类型判定。

| 元素 | 宽度 < 1024px | 宽度 < 768px |

### 3.7 键盘导航规则

**Tab 焦点序列（固定顺序）**

1. 跳转链接"跳到主要内容"（仅获得焦点时可见，位于页面最顶部）
2. 顶栏左段 → 中段（模式条，`Enter` 打开模式详情）→ 右段（数据新鲜度、角色切换器、溢出菜单）
3. 侧边栏（跳过链接 → 各二级项 → 角色切换器）；侧边栏在 Tab 序列中只占**一个停靠点**，进入后按 `↓` 在二级项间移动，`Esc` 退出回到顶栏
4. 主内容区（按视觉阅读顺序）
5. 页面级主要操作按钮
6. 页脚

**快捷键**（统一 `g` 前缀，避免与输入框冲突；不使用单字母直达）

| 快捷键 | 行为 |
|---|---|
| `g` 然后 `t` / `p` / `d` / `i` / `h` / `b` / `r` / `c` / `s` | 依次跳转 `/today`、`/plan`、`/decisions`、`/incidents`、`/household`、`/battery`、`/reports`、`/collaborate`、`/settings` |
| `/` | 聚焦当前页面主列表的筛选/搜索输入框（页面无筛选框时不响应） |
| `?` | 打开快捷键帮助浮层 |
| `Esc` | 关闭最上层浮层 / 抽屉 / 侧边详情；无浮层时不响应 |

**硬规则**

1. 输入框获得焦点时全部 `g` 前缀快捷键失效，仅保留 `Esc`。
2. 路由跳转完成后焦点必须落在目标页面的 `h1`（`tabindex="-1"`）上并触发一次焦点播报。
3. 图表类交互区域（今日时间线、24 小时计划图）必须可用方向键在时段间移动，`Enter` 打开侧边抽屉，`Esc` 关闭并**把焦点还给触发时段**。
4. 任何交互元素不得移除可见焦点环；全局样式中禁止出现 `outline: none`。

### 4.1 全局运行模式标识（6 种模式）

**顶栏模式条规格**：高 32px，左侧 8px 实色块，右侧依次为模式名（13px，字重 500）+ 原因摘要（12px）+ 可点击区（点击跳转 `/collaborate#matrix`）。

| 模式 | 内部值 | 色块语义 | 模式名文案（固定，任何页面不得改写） | 显示原因 | 主内容顶部提示条 |

| 建议模式 | `advisory` | 中性深灰 + 1px 虚线边框 | 我建议，你决定 | 否 | 不出现 |

| 安全模式 | `safe` | 危险红 | 我已停止优化，设备回到硬件默认 | 是 | 出现，含原因、需要谁处理、进展入口 |

| 页面 | 出现形式 |
|---|---|
| `/today` | 顶栏模式条 + `#mode` 区块重复一次完整版（含进入时间）；降级模式下额外出现主内容顶部提示条 |
| `/plan` | 顶栏模式条 + `#head` 内一行限定语：影子期显示"这是一份建议，我不会真的执行"，安全模式显示"本页计划已失效"，其他模式不显示 |

### 4.2 全局「一键回退出厂策略」入口

| 入口 | 位置 | 形态 |
|---|---|---|
| 主入口 | `/today`，`#conclusion` 结论卡正下方、`#mode` 右侧 | 次级按钮（1px 边框、非实心），文案"回退出厂策略" |
| 常驻入口 | 顶栏右段溢出菜单第一项 | 菜单项，全站任意页面可达 |
| 二次入口 | `/settings#automation` 第一项 | 区块行，右侧显示当前模式只读值 + 操作链接 |
| 安装商侧 | `/installer/:customerId#tools` | 工具按钮，须在客户上下文内 |

**交互契约**

1. 点击后进入**全屏确认页**，不使用模态弹窗（高影响操作，避免误触与误关）。
2. 确认页为三段固定结构：会发生什么`管家将停止一切优化，电池回到出厂的自发自用优先策略。`／不会发生什么`历史数据、决策日志与收益记录全部保留；你也可以随时重新开启管家调度。`／如何恢复`在"设置 - 自动化"里重新开启，或点这里现在恢复。`
3. 确认方式：在输入框中输入"出厂策略"四个字后 `[确认回退]` 才可点击。不使用长按（长按在键盘端不可达）。
4. 执行结果：模式迁移到 `conservative`，`resumeCondition` 写入"在设置里重新开启管家调度"，写入一条 L2 留痕（操作人、时间、原因），并通知安装商后台。
5. 执行后跳转 `/today`，模式条与结论卡在同一渲染帧内更新。
6. 回退**不影响**历史数据与收益记录；该月报告中标注发生过一次人工回退。

### 4.3 数据新鲜度与时间戳呈现规则

**统一格式**：同日 `HH:mm`；跨日 `MM-DD HH:mm`；报告与文档 `YYYY-MM-DD`；微标签可用相对时间`刚刚`/`N 分钟前`/`N 小时前`。时区为用户本地时区，24 小时制，不使用 AM/PM，数字等宽对齐。

| 数据族 | 实体 | 正常周期 | 新鲜（不提示） | 陈旧（提示） | 失效（置灰并降级） |
|---|---|---|---|---|---|
| 实时状态 | `BatteryState`、`EnergyFlow` | 5 秒 | ≤ 30 秒 | > 30 秒且 ≤ 5 分钟 | > 5 分钟 |
| 价格曲线 | `PricePoint`、`GridFeeRule` | 小时级 | ≤ 30 分钟 | > 30 分钟且 ≤ 2 小时 | > 2 小时 |
| 预报 | 天气与光伏预报 | 6 小时 | ≤ 6 小时 | > 6 小时且 ≤ 24 小时 | > 24 小时 |
| 计划 | `EnergyPlan`、`PlanRevision` | 每日 + 事件驱动 | ≤ 24 小时 | — | 计划日期早于今日即为过期 |
| 画像 | `HouseholdProfile` | 每日 | ≤ 7 天 | > 7 天且 ≤ 30 天 | > 30 天 |
| 报告 | `EarningsReport` | 每月 | 标注"截至 YYYY-MM-DD" | — | — |

- **陈旧呈现**：数值前加半角中点前缀 `·`，数值颜色降为 ink-3，同一行右侧显示微标签`已 N 分钟未更新`（11px，琥珀）。工具提示：`这是最近一次有效值，不是当前值。`
- **失效呈现**：整个区块置灰，顶部固定一行`该数据暂不可用`，其下必须紧跟一行**已采取的降级策略**，例如`我已切到保守策略，优先保证光伏自用与停电备用。`不得用最后已知值冒充实时值（总 PRD §4.0）。
- **位置规则**：每个数据区块右上角显示`更新于 HH:mm · 来源名称`；来源名称使用用户能懂的说法（`零售商电价`、`本地天气`、`电池自身`），不用接口名；报告类页面的时间戳放在副标题，不在每个区块重复；时间戳永远可点击，展开数据来源与更新记录（P6）。

### 4.4 页面标题与副标题的文案公式

- 禁止清单：禁止"欢迎回来""你好"这类无信息量问候；禁止用问句代替结论（不写"今天省了多少？"）；禁止 SOC / DoD / EFC / kW / kWh 裸术语；禁止"保证""一定"。

## 6. 响应式断点规格

断点用 CSS `min-width` 媒体查询实现，不使用 JavaScript 监听宽度（避免布局抖动）。

| 档位 | 宽度范围 | 侧边栏 | 栅格 | 内容宽度 | 图表 | 表格 |
|---|---|---|---|---|---|---|
| L | ≥ 1440px | 常驻 236px，图标 + 文字全展开 | 12 列，间距 24px | 1200px 居中 | 计划图 16:5，横轴每 2 小时一刻度、每 6 小时一主刻度 | 显示全部列，行高 36px，每页 20 行分页 |
| M | 1024–1439px | 常驻 64px 仅图标；hover / 聚焦时浮层展开 236px | 12 列，间距 16px | 1024px，内边距 32px | 计划图 16:6，横轴每 3 小时一刻度 | 按列级裁剪（见下） |
| S | 768–1023px | 移除，改为顶部汉堡 + 右侧抽屉（280px） | 8 列，间距 16px | 无上限，内边距 24px | 4:3；当天时间线仅显示 6:00–24:00，其余横向滚动（滚动条可见） | 一律转为行卡片（见下） |
| 补充 | < 768px | 移除，改为底部标签栏（56px）+ 右侧抽屉 | 4 列 | 无上限，内边距 16px | 计划图折叠在"看时间轴"按钮后，默认只渲染动作表与弃权卡 | 单列卡片，键值对上下两行 |

**档位 M 的表格列级裁剪规则**：所有表格列预先标注级别——0 级（必须保留）、1 级（可裁剪）、2 级（优先裁剪）。按 2 级 → 1 级顺序移除，被裁剪列的内容以"展开行"形式在行下方呈现。任一表格至少保留 0 级列：第一列（对象名）、结论文本列、操作列。已定级别：决策日志 0 级 = 时间 / 动作 / 收益影响，1 级 = 是否被推翻，2 级 = 是否被接管；市场列表 0 级 = 市场名 / 电价机制 / 健康状态，1 级 = 活跃用户数，2 级 = 策略包版本。

**档位 S 及以下的行卡片规格**：每张卡片为"对象名（加粗，占满宽）+ 两列键值对（键左，值右对齐）+ 操作按钮区"，卡片间距 12px；列表顶部保留筛选条并新增"排序"下拉；页面不出现横向滚动。

**其余分档规则**：一、档位 M 的结论卡改为 6 列 + 6 列 + 12 列两行排布（三格各 4 列会导致数字与文字换行），页面标题与副标题左对齐于第 1 列。二、档位 S 的结论卡改为单列纵向堆叠，每格占 8 列。三、档位 S 及以下的侧边抽屉改为从底部升起的面板（高 60vh），因为点击时段后右侧空间不足。四、档位 < 768px 时，详情页（`/decisions/:id`、`/incidents/:id`、`/markets/:id`、`/installer/:customerId`）隐藏底部标签栏，改为顶栏返回箭头；与安全区重叠时容器增加 `env(safe-area-inset-bottom)` 底部内边距。

**跨档位硬规则**

1. 任一档位下 `h1` 与副标题必须完整可见，最多换行 2 行，超出则截断加省略号并把完整文案保留在 `title` 属性中。
2. 任一档位下不得出现页面级横向滚动容器，仅图表与时间线内部允许横向滚动。
3. 缩放窗口时不得出现内容重叠、元素消失、焦点丢失。
4. 布局变化不改变页面状态：筛选条件、展开状态、表单内容在缩放后必须保留。
