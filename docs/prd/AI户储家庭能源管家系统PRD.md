## 一、背景与目标

### 1.1 行业背景：户储的价值逻辑正在换挡

户用储能行业过去几年的增长主要靠**补贴 + 高电价 + 停电焦虑**三件事驱动：家庭装一套光伏加电池，白天存电晚上用，靠自用率的提升就把钱赚回来。这套逻辑的特点是——**不需要用户做太多决策**，"自发自用优先"这个出厂默认策略就能兑现大部分价值。

现在这三件事都在变：

- 补贴在退坡（德国、澳洲、英国等主要市场的户用补贴陆续收紧或改为贷款贴息），**"装了就赚"的确定性下降**；
- 固定零售电价合同被**动态电价合同**替代的趋势明显（德国、北欧、英国、西班牙、澳洲等地零售商已大规模提供小时级甚至 15 分钟级变动的电价），**电价从一张静态表变成了一条曲线**；
- 储能硬件同质化，电芯、逆变器功率、容量档位的差异越来越小，**价格战压缩了硬件毛利**。

结果是一个结构性变化：**户储的收益来源，从"硬件本身"转移到了"电池每天怎么用"上。**

同一套光伏 + 电池，在不同调度策略下，年度收益差距可以很大；而大多数家庭的电池，今天跑的还是三年前写死的出厂策略。这才是户储行业下一个真正的价值洼地。

### 1.2 沃太能源的业务处境

沃太能源（Alpha ESS）是国内较早出海的户用储能企业之一，总部位于江苏南通，以**欧洲市场为起点**建立起户用储能业务，品牌在海外的认知度高于国内。

**业务结构（公开口径概览）**：以户用储能系统为主，产品形态为"电池 + 逆变器"的一体化储能机（SMILE 系列等），配套自有的 App 与云平台完成监控、报表与固件升级；同时延伸至工商业储能与便携储能。

**目标市场与渠道**：德国、英国、意大利、澳洲、南非等为主要海外市场，销售以**海外经销商 + 本地安装商**为主，属于典型的技术型品牌出海路径——产品力强、渠道依赖重、直面终端消费者的触点较薄。

**既有能力**：沃太的强项在硬件与系统集成——电池、逆变器、BMS、云平台是自己的，数据闭环掌握在自己手里。这意味着**"读懂电池状态"这件事，沃太比任何第三方软件公司都有优势**：SOH、温度、单体温差、历史循环，这些数据别人拿不到。

**既有缺口**（也是本项目的立项理由）：
1. App 的能力停留在**监控 + 报表 + 手动设置**。用户能看见，但不能省心。
2. 调度策略**出厂固定，或由用户手设时段**。一旦用户的电价合同从固定价变成动态价，App 里那套"谷电充电时段"就基本失效了。
3. 面对**两套完全独立的价格信号**（零售商的动态电价 + 电网公司的电网费机制），产品没有能力把它们合并考虑。
4. **决策是黑盒**。用户不知道电池为什么半夜在充电，于是不敢开自动，或者开了又关掉。
5. 海外市场规则差异大，每进一个新市场都要重新做一套策略，**反应慢**。

### 1.3 竞争格局与空位

赛道上的玩家可以分成四类，各有明显短板：

| 类型 | 代表 | 现有做法 | 短板 |
|---|---|---|---|
| 整车厂式硬件巨头 | Tesla（Powerwall 的时间电价模式、风暴预警）、华为 FusionSolar | 有自动调度，但**规则化、模式少**，用户只能在几个固定模式里选 | 调度逻辑不透明，用户无法干预细节；通常绑定自家生态 |
| 传统逆变器/储能厂商 | sonnen、GivEnergy、SolaX、Fronius、SMA、GoodWe、Growatt、Enphase、Anker SOLIX | 多数为**固定模式 + 手设时段**；动态电价能力参差不齐，往往先支持本国或单一零售商 | 需要用户自己搞懂电价规则；跨市场适配慢 |
| 纯软件/新零售侧玩家 | Tibber、Octopus（Intelligent Flux 等）、Amber（SmartShift）、Evergen、Kaluza、Lunar 等 | 算法能力强，**自动调度做得好** | 只服务自家客户、**锁定单一零售商**；拿不到电池底层健康数据；不掌握硬件 |
| 聚合商 / VPP | sonnen 的 VPP 类业务、各类聚合商 | 以电网服务收益为主 | 收益归聚合商，家庭感知弱；用户几乎不参与决策 |

**空位很清楚**：

> 没有人同时做到 **跨零售商的动态电价调度 + 电网费第二信号 + 电池寿命护栏 + 可解释决策 + 多市场快速复制**。

软件方有算法没硬件数据，硬件方有数据没算法意愿，零售商只服务自家客户。而这恰好是沃太的位置——**硬软件一体、数据闭环自有、渠道覆盖多市场**。

同时要清醒地看到：**这是一个"信任门槛高于技术门槛"的产品**。用户不会因为"用了 AI"就把电池交给一个黑盒。竞品翻车的典型场景就是"自动模式半夜突然充电，用户一脸懵，第二天关掉功能"。所以本产品的核心难点不是算得准，而是**让人敢用、看得懂、随时能接管**。

### 1.4 问题定义（一句话）

> 帮一个装了光伏和电池的家庭，在"想省钱、怕停电、怕电池早衰减"三个互相冲突的诉求之间，**每天自动做出最优的充放电安排，并让用户看得懂、管得住、随时能推翻**。

### 1.5 产品目标

**业务目标（对沃太）**
1. 让智能调度成为沃太户储产品的**差异化卖点**与**软件/服务收入来源**，把一次性的硬件生意变成持续的服务关系。
2. 让"进入一个新的动态电价市场"从"改固件、等半年"变成"**云端配置策略包、几周上线**"。
3. 把**售后与渠道服务成本降下来**——安装商不再充当客户的人工调度员。
4. 沉淀家庭用能画像与调度记录，为将来参与**需求响应 / 虚拟电厂**积累可信的调度能力与用户授权基础。

**用户目标（对家庭）**
1. 电费账单**实打实地下降**，且用户能看懂省在哪。
2. 停电时**电一定够用**，不是"运气好还有电"。
3. 电池**不因为套利被过度使用**，质保期内的健康度可控。
4. **不用每天看 App**、不用研究电价规则——越少操心越好。

**成功指标（概览，详见第九章）**

| 层级 | 指标 | 目标（首年，示例） |
|---|---|---|
| 北极星 | 自动模式下，每户每月**可验证净收益** | 显著优于出厂策略，且逐季提升 |
| 护栏 | 备电失守次数（停电时低于用户预设备电） | **0** |
| 护栏 | 用户推翻 Agent 决策的比例 | 首月 < 20%，稳定期 < 5% |
| 护栏 | 循环预算超支率 | 0（超支必须自动降级） |
| 信任 | 自动模式 90 日留存率 | ≥ 70% |
| 渠道 | 因调度相关问题产生的客服工单量 | 相对基线下降 |

### 1.6 非目标（本期明确不做）

为避免范围蔓延，以下内容**不在本期范围内**：

1. **不做电力交易业务**。Agent 只做家庭侧的自用优化，不代替用户签合同、不对外售电、不参与需要资质的市场交易。参与需求响应/VPP 属于后续独立项目，需另行解决资质与合作伙伴问题。
2. **不做硬件的安全参数自动修改**。电压、保护阈值、并网参数等安全相关设置，Agent 永不可触碰。
3. **不做跨用户的策略自动变更**。所有影响多个家庭的规则调整，必须由人批准后发布。
4. **不做智能家居全屋控制**。热泵、EV 充电桩等只作为"可观测、可建议"的对象，本期不直接控制；将来作为联动扩展。
5. **不做收益承诺**。产品对外不得出现"每月保证省 XX 元"的表述。

## 二、用户与痛点

### 2.1 用户角色地图

这个产品有个容易搞错的地方：**掏钱的人、用的人、被麻烦的人，是三个不同的角色。**

| 角色 | 是谁 | 关心什么 | 在本产品中的位置 |
|---|---|---|---|
| **家庭业主（主人）** | 装了沃太系统的家庭决策人 | 这个月电费多少、停电怕不怕、这机器会不会坏 | **付费与授权主体**，Agent 的"委托人" |
| **家庭其他成员** | 配偶、老人、孩子 | 别半夜跳闸、别把电用光 | 体验相关方，**不应被要求学习任何规则** |
| **安装商 / 经销商** | 本地安装与售后伙伴 | 客户别老打电话、别投诉、能不能多卖点 | **隐性关键用户**，Agent 的推广放大器与一线接管人 |
| **沃太服务与运营团队** | 售后、技术支持、策略运营 | 工单量、告警处置、市场规则更新 | **Agent 的"上级"与立法者**，异常裁决人 |
| **电网公司 / 零售商 / 聚合商** | 电力侧商业对手方 | 可调节容量、削峰效果 | 未来价值交换对象，本期只做规则遵从 |

**结论：产品表面服务家庭业主，实际必须同时服务安装商。** 安装商如果觉得这套 Agent 会给他增加麻烦，他会在客户面前把它关掉。因此"**减少安装商的工作量**"和"**让家庭业主省心**"必须同时成立。

### 2.2 As-Is：今天一个家庭的真实流程

这是本项目最需要看清的部分。今天的过程大致如下：

1. **签约阶段**。家庭在零售商那里选了一个电价产品。很多市场现在推的是动态电价（小时级或 15 分钟级波动），但用户签的时候**基本不理解这意味着什么**，往往是被"平均更便宜"吸引。
2. **安装阶段**。安装商把沃太系统装好、并网、调试、开通 App。**调度策略在这一步就定死了**：安装商在几个预设模式里选一个（自发自用优先 / 谷电充电 / 备电优先 / 自定义时段），或者干脆用出厂默认。这一步通常只花几分钟，**没有人真正了解这家的用电习惯**。
3. **摸索阶段**。用户过了几周发现电费没省多少，于是自己进 App，看到一个"充电时段"的设置项，凭感觉填两三个时段（例如"凌晨 2 点到 5 点充电"）。填完就再也没改过。
4. **失效阶段**。情况一变，整套设置就作废了：
   - 冬夏日照变化，光伏发不出来，原来"白天存电"的计划空转；
   - 换了电价合同，或者零售商的电价波动区间变了，原来的充电时段不再是低价时段；
   - 家里添了电动车，晚上充电负荷变了；
   - 电网费机制变了（峰段划分调整、容量费出台）。
   **没有人会主动回来重设这些参数。**
5. **投诉或放弃阶段**。用户发现账单不对劲，打电话给安装商。安装商远程看一眼，也不知道该怎么调，只能建议"你把它切回自发自用吧"。**智能功能被关掉**，电池退化成一个"白天存、晚上放"的普通电池，卖掉它的商业理由也就没了。

**这条流程的致命之处**：整套系统的价值兑现，卡在一个**用户既没能力、也没意愿、也没时间**去完成的日常决策上。而且这个决策一旦定错，**没有任何人会收到反馈**——直到用户发现账单不对。

### 2.3 痛点清单

**A. 认知负担类——用户根本算不过来**

- 动态电价是**小时级甚至 15 分钟级**的曲线，一天几十上百个价格点。人脑无法判断"今晚该不该充、充几个小时、充到多少"。
- **电价便宜 ≠ 值得充电**。要把收益算清楚，必须同时考虑电池的往返效率损失、充电功率限制、以及这些电量本来能不能留给光伏。
- **第二套信号没人管**：电网费（分时输配电价、容量费、需量电费、以及部分市场的可控负荷网费减免档位）与零售电价是**两条独立的曲线**，方向可能相反——零售电价便宜的时段，电网费未必便宜；有时为了拿到网费减免，反而要接受电网的限功率控制。**现有产品完全不处理这个信号。**
- 用户看不懂 App 里的数字。SOC（荷电状态）、kW、kWh、循环次数——这些术语对普通家庭是噪音。

**B. 经济性损失类——每年都在悄悄漏水**

- **默认策略本身就是收益下限**。"自发自用优先"在动态电价市场里会把最有价值的时段白白错过。
- **反向套利**：用户凭感觉设的充电时段，很可能落在高价时段，等于**主动买贵电**，而且还要额外付出循环损耗。
- **毛收益当净收益**：宣传里的"价差 × 电量"是毛数，扣掉往返效率损失（示例约 10%）、电池折旧、税费之后会明显缩水。产品如果按毛数承诺，迟早被用户当面对账。
- **买贵电充、又在低价时段放电**：缺乏整体视野的策略经常自己和自己打架。

**C. 风险失控类——省的钱不够赔的**

- **备电被套利抽干**。为了赚价差，电池在傍晚被放到很低的电量。如果当晚停电，家庭连冰箱都保不住。**这是本产品最不能犯的错**。
- **频繁浅循环导致衰减**。每天多跑一次套利循环，看起来不深，但一年下来是几百次额外的等效满循环。省下的电费，可能不足以覆盖电池提前衰减带来的损失与质保争议。
- **责任真空**。电池是沃太的，电价是零售商的，网费是电网公司的，调度是算法做的。**出了问题，用户只会找沃太。** 这个责任必须提前用产品设计接住。
- **停电正好发生在电池空的时候**——这种"运气不好"发生一次，用户对整个品牌的信任就没了。

**D. 服务成本与信任类**

- **安装商被迫当人工调度员**。客户打电话来问"为什么昨天半夜在充电"，安装商答不上来，只能远程改参数，反复几次就成了长期负担。
- **黑盒调度无法解释**。用户看不到"为什么"，就不敢开自动；开了自动又因为一次看不懂的动作而关掉。
- **新市场适配慢**。每个国家的电价机制、网费规则、上网限制都不同，靠固件迭代根本跟不上市场变化。

### 2.4 需求本质：这是一道"三约束权衡题"，而人的角色要重新定义

把所有痛点收敛一下，本质只有一个：

> 同样是 1 kWh 电池电量，它有三种互相排斥的用途——**卖掉赚价差、留着备用、省下来不消耗寿命**。三者不可兼得，必须取舍。

| 用途 | 收益形式 | 代价 |
|---|---|---|
| 套利（充低放高） | 直接的电费节省 | 消耗循环寿命 + 占用备用电量 |
| 备电（留着不用） | 停电时的保险价值 | 放弃当期套利收益 |
| 护电池（少动） | 延缓衰减、保住质保 | 放弃当期套利收益 |

**只有当前者的收益明显大于后两者的代价时，才值得动手。** 这个判断每天都要重做一次，因为电价、天气、家庭计划每天都在变。

由此推出本产品的**核心设计立场**：

> **用户不是每天的操作员，而是规则的立法者。**
> 用户定的是边界和偏好（我要多省心、停电要够用多久、电池我用得省一点），Agent 负责在边界内每天自动执行，并把每一次判断讲清楚。人只在**异常**和**周期性复核**时进场。

这一句是后面所有功能设计与协作机制的根据。

### 2.5 用户分层与优先级

不同用户对"自动"的接受度差别很大，产品必须分层，而不是一套默认值打天下。

| 分层 | 画像特征 | 核心诉求 | 对 Agent 的期待 | 优先级 |
|---|---|---|---|---|
| **省心型（主力）** | 双职工家庭、有孩子、不折腾技术 | 别让我操心，账单别涨，停电别慌 | 全自动 + 定期告诉我结果 | **P0** |
| **省钱型（先锋）** | 对电价敏感、会主动研究、可能已经是动态电价用户 | 把每一分价差榨干 | 自动执行 + 我要能看细节、能调参数、能质疑 | **P0** |
| **保守型** | 高龄用户、有医疗设备/居家办公、第二住宅 | 可靠性第一，省不省无所谓 | 只给我建议，我自己按，别自己动 | **P1** |
| **离网/弱网地区用户** | 南非等电网不稳定市场 | 停电是常态，备电是刚需 | 优先保供电，套利是次要目标 | **P1**（市场差异化产品） |

**设计含义**：
- 默认档位要面向"省心型"——**默认值必须保守、默认解释必须人话、默认不打扰**。
- 但必须给"省钱型"留出**深水区**：能看到每一次决策的完整依据，能推翻、能锁单、能改红线。这批人是口碑的源头。
- "保守型"只需要一个开关：**只建议，不执行**。这个开关必须在首次引导里就能看到，不能藏在三层菜单下。

## 三、产品定位与价值主张

### 3.1 一句话定位

> **沃太家庭能源管家（Butler）**——一个住在 App 里的家庭能源调度 Agent：它学会你家的用电和发电规律，读懂电价与电网费两条曲线，在你划定的红线内自动安排每天的充放电，并告诉你每一步为什么这么做。

### 3.2 三代做法对比

| 维度 | 第一代：出厂固定 | 第二代：用户手设时段 | **第三代：管家 Agent** |
|---|---|---|---|
| 谁做决策 | 厂商写死 | 用户凭感觉 | **Agent 每天算，用户定边界** |
| 输入信号 | 无 | 用户填的几个时段 | **电价曲线 + 电网费 + 天气 + 家庭画像 + 电池健康 + 用户偏好** |
| 适配变化 | 不适应 | 用户自己回来改 | **自动跟随，规则变化时提醒用户** |
| 备电保障 | 静态设定 | 静态设定 | **动态预留，且绝不被套利侵占** |
| 电池寿命 | 无意识 | 无意识 | **循环预算记账，超支自动降级** |
| 用户理解 | 不需要 | 以为自己懂 | **每步可解释，主动说明"我为什么没做那件看似赚钱的事"** |
| 服务成本 | 低（但价值也低） | 高（安装商被反复咨询） | **低，且安装商可一键查看决策日志** |
| 新市场 | 改固件 | 改固件 | **云端策略包配置** |

关键差异不在"自动化程度"，而在**两件事**：
1. **信号融合**——把电价和电网费放在一起算，而不是各管各的；
2. **可解释**——让用户看得懂，才敢长期用。

### 3.3 产品形态与入口

- **主入口**：沃太 AlphaESS App 内新增的"管家"Tab（不是新做一个 App，避免用户装第二套软件）。
- **次要入口**：安装商/经销商侧后台的"客户管家视图"——可以查看某位客户的当前策略、红线设置、近期决策日志与异常记录，用于远程支持。
- **推送通道**：App 通知 + 邮件（月度报告）。**不默认使用短信/电话**，避免打扰。
- **物理侧**：调度执行通过逆变器与电池既有通道完成，用户无需理解。

## 四、Agent 核心功能

### 4.1 能力地图

### 4.2 F1 · 家庭画像与习惯学习

**要解决什么**：Agent 必须知道"这家人是怎么生活的"，否则再好的算法也是瞎猜。

**学什么**：
- **基线负荷**：家里一天 24 小时的基础用电曲线，区分工作日 / 周末 / 假期、夏季 / 冬季。
- **大功率柔性负荷**：热水器、热泵、洗碗机、洗衣机、EV 充电桩——它们通常在什么时段启动、持续多久、能不能挪。
- **光伏发电特征**：朝向、遮挡、季节差异、阴天表现。
- **家庭作息**：大概什么时候有人在家、什么时候全家外出、是否长期空置。
- **停电风险画像**：所在区域的历史停电频次与时段（决定备电策略的保守程度）。

**怎么学**：
1. **冷启动三问**（见第六章 T1）——不要求用户填数据，只问偏好。
2. **影子期观察**（建议 2–4 周）——Agent 在这个阶段**只出计划、不执行**，同时对照实际情况校准画像。
3. **持续在线校正**——每次实际执行与实际用电的偏差都成为画像的证据。

**交付物：一张"家庭用能画像卡"**，用大白话写给用户看，并且**必须可被用户纠正**。例如：

> **你家的用电画像（供你核对）**
> - 平日上午 9 点到下午 5 点基本没人在家，基础用电约 0.3 kW
> - 热水器通常在晚上 21:30 之后启动，每次约 1.5 小时
> - 周三和周日晚上有电动汽车充电，大约需要 12 kWh
> - 你家屋顶冬天下午 3 点后基本发不出电
> - 你所在的区域过去一年停电 3 次，都发生在夏季傍晚
>
> **有哪里说得不对吗？** [全部正确] [我要修改]

**设计要点**：
- **可纠正性是建立信任的第一个动作**。让用户在第一天就体会到"它能被我说了算"，而不是"它在替我决定"。
- 画像卡**不展示专业术语**，不出现 kW 之外的单位；SOC 一律翻译成"够用几个小时"。
- 画像分为"确定的事实"（如热水器时段）和"猜测"（如"你家可能周末外出"），**必须视觉区分**，猜测要允许用户一键否认。

---

### 4.3 F2 · 每天一张"能源计划表"（核心交付物）

**要解决什么**：把"今天电池该怎么用"这个没人算得过来的问题，变成一张一眼能看懂的表。

**输入（业务语言描述）**：
次日电价曲线 → 次日电网费/网费减免规则 → 天气与光伏发电预报 → 家庭画像 → 当前电量与电池健康状态 → 用户设定的偏好权重与红线 → 已知的家庭日程（如"周三晚上要充车"）。

**输出：一张 24 小时计划表**。示例（数字为示意）：

> **明天（周四 · 阴转晴）的能源计划**
>
> 预计净收益：**€1.86**　·　明早备用余量：**62%**（约够用 9 小时）　·　本次动用循环：**0.42 次**
>
> | 时段 | 做什么 | 电量变化 | 原因 |
> |---|---|---|---|
> | 01:00–03:20 | 从电网充电 | 28% → 74% | 全天电价最低的两小时（€0.11/kWh），且此时段电网费为低谷 |
> | 03:20–07:00 | 待机 | 保持 74% | 没有更便宜的时段了，继续充不划算 |
> | 07:00–09:00 | 放电供家用 | 74% → 58% | 早高峰电价 €0.34/kWh，放电收益最高 |
> | 09:00–16:00 | 光伏优先自用 | 58% → 88% | 预计发电 21 kWh，白天自用最划算 |
> | 16:00–21:00 | 保留为主，少量放电 | 88% → 62% | 晚间电价高，但**你设定的备电底线是 60%，所以只放到这里** |
> | 21:00–24:00 | 待机 | 保持 62% | 保持备电，不再套利 |
>
> **我主动放弃的机会**：今晚 22:00 有一个 15 分钟的价格尖峰（€0.52/kWh），理论上可以放电多赚 €0.30。但按你家的历史用电，每晚 22:00 后热水器会启动，如果把电放掉，热水器会用更贵的电，反而多花 €0.12。所以我没有放。
>
> [接受这个计划]　[我要调整]　[明天按老办法来]

**设计要点**：

1. **计划表必须能回答三个问题**：明天赚多少、停电够不够用、电池累不累。这三个数字要在最显眼的位置。
2. **"我主动放弃的机会"是这张表最有价值的一栏**。用户对 Agent 最大的怀疑不是"它做了什么"，而是"它为什么没做那件明显赚钱的事"。**主动坦白放弃项，比解释已做项更能建立信任。**
3. **每个动作必须给一句人话理由**，且理由要落到用户能理解的因果关系上（"因为热水器会启动"比"因为负荷预测冲突"好一万倍）。
4. **电量变化用百分比 + 直观后果表达**，"62%（约够用 9 小时）"比"62% SOC"有用。
5. **计划是"一天一张"的节奏**，不是实时刷新。用户需要一个稳定的对象去查看和质疑，而不是一条永远在动的曲线。

---

### 4.4 F3 · 日内滚动修正

**要解决什么**：日前计划一定会有偏差，但不能一变就通知用户。

**典型触发场景**：
- 电价曲线更新（日前市场 → 日内市场，例如北欧、德国部分地区的日内价格会重算）；
- 光伏实际发电明显高于或低于预报（阴云比预报厚）；
- 家庭临时变故：全家突然外出、提前回家、临时插上电动车；
- 极端天气或停电预警；
- 电网发出限功率/需求响应指令。

**处理原则**：
1. **小偏差静默修正**。修正幅度在阈值内（例如对当日净收益影响小于某个小额阈值），Agent 直接调整，**不通知**，只在当晚的日报里提一句。
2. **大偏差主动告知**。当修正会明显改变当日收益，或需要触碰备电预留边缘时，**必须通知并说明原因**。
3. **用户可"锁单"**。用户可以锁定某一天的计划，Agent 当天不得再改，只有在安全原因（停电预警、电池告警）下才可覆盖，且覆盖必须告知。
4. **修正不能绕过护栏**。任何滚动修正都在 F5 的边界内进行。

**为什么重要**：如果每次修正都推送，用户会很快关掉通知；如果完全不告知，用户又会觉得"它偷偷做事"。**阈值化的通知策略是这个功能的核心产品决策，而不是算法问题。**

---

### 4.5 F4 · 决策解释

**要解决什么**：把黑盒变成白盒，这是"用户敢不敢开自动"的唯一决定因素。

**解释分三层，由浅入深**：

| 层级 | 面向谁 | 内容 | 呈现方式 |
|---|---|---|---|
| **L1 一句话** | 所有用户 | "今晚 1:00–3:20 充电，因为这是全天最便宜的两小时，预计省 €1.86，明早仍留 62% 备电。" | 首页卡片、推送通知 |
| **L2 展开** | 想弄明白的用户 | 为什么是这两个小时？其他时段为什么不选？电网费怎么算进去的？我放弃了什么？ | 计划详情页 |
| **L3 深挖** | 省钱型用户、安装商 | 与上周对比、与"什么都不做"对比、与"理论最优"对比；历史决策日志；每次动作的事后结果 | 历史与日志页，可导出 |

**四条硬规则**：

1. **每个自主动作都必须能回答"为什么"**。如果 Agent 无法说清理由，这个动作就不该自主执行。
2. **必须主动披露放弃项**（见 F2）。不允许"只报喜"。
3. **必须表达不确定性**。凡是基于预报的结论，一律使用"预计"并给出区间（"预计省 €1.86，区间 €1.40–2.20"）。**不允许把预测说成事实。**
4. **必须能说"我不知道"**。数据缺失或模型不确定时，Agent 应当声明"这个时段的判断不可靠，我采用了保守策略"，而不是编一个理由。**编造理由是最严重的信任事故。**

**被推翻之后怎么做**（关键分流）：

用户推翻一个决策时，Agent 必须问一句：

> **这次是例外，还是以后都这样？**
> [就这一次]　[以后都按我说的来]

- 选"就这一次"→ 记为一次性例外，**不修改规则**；
- 选"以后都这样"→ 进入规则变更流程，若涉及红线变更则走 L3 审批（见第六章）。

**这个分流动作是整个 Agent 学习机制的关键**。绝大多数"智能产品"的失败都是因为把用户的一次临时操作当成了永久偏好，从此越用越偏。

---

### 4.6 F5 · 护栏引擎（产品的责任边界）

**要解决什么**：Agent 再聪明也会算错。**护栏不是优化的一部分，是产品的法律与道德底线。**

**护栏清单**（Agent 在任何情况下不可逾越）：

| 护栏 | 内容 | 用户可调 | 说明 |
|---|---|---|---|
| **备电预留** | 保留足够的电量应对停电，用"够用几小时"表达 | ✅ 用户主控 | 硬约束，任何套利不得侵占 |
| **最低电量红线** | 电池不得低于某个电量水平 | ✅ | 防止深度放电加速衰减 |
| **最高电量上限** | 电池不充满，给次日光伏留空间 | ✅ | 对光伏家庭常有用 |
| **循环预算** | 每月/每年允许消耗的等效满循环次数 | ✅（需确认） | 超支自动降级为保守模式 |
| **收益门槛** | 单次套利的预期净收益必须超过门槛才执行 | ✅ | 防止"为几毛钱伤电池" |
| **温度与功率保护** | 低温/高温/电池告警时禁止大功率充放 | ❌ 系统强制 | 安全项，不可配置 |
| **电网指令遵从** | 电网限功率、需求响应指令优先于套利 | ❌ 系统强制 | 合规项 |
| **安全参数** | 电压、保护阈值、并网参数 | ❌ **Agent 永不可触碰** | 完全在系统之外 |

**触发后的行为（统一且不可协商）**：
1. 立即退出优化模式，切回**安全默认策略**（自发自用 + 备电优先）；
2. 生成一条"事故简报"（见 F7）；
3. 按严重度通知相应角色；
4. 在日报中明确告知用户"我因为 X 原因降级了，你什么也不用做，等恢复后我会自动接回"。

**设计立场**：护栏的默认值必须**保守**，宁可少赚。第一年的目标不是把收益榨到极限，而是让所有用户相信"它不会害我"。**收益可以在第二年调优，信任只有一次机会。**

---

### 4.7 F6 · 收益归因与报告

**要解决什么**：用户需要一个**可验证的结果**，否则所有解释都只是说法。

**月度报告的四栏对照**（核心设计）：

| 对照对象 | 本月电费 | 差额 | 说明 |
|---|---|---|---|
| 什么都不做（没有光伏和电池） | €185 | — | 基准 |
| 出厂默认策略 | €121 | 省 €64 | 硬件本身的价值 |
| **管家 Agent 调度** | **€108** | **再省 €13** | **本产品创造的价值** |
| 理论最优（事后回看） | €101 | 还有 €7 空间 | 诚实披露上限 |

**拆解来源**：
- 光伏自用节省 €XX
- 低价时段充电节省 €XX
- 高价时段放电节省 €XX
- 电网费（网费减免/避免容量费）节省 €XX
- **效率损失 −€XX**
- **电池循环折旧 −€XX**
- **净收益 €XX**

**三条诚实原则**（不可妥协）：

1. **必须计入效率损失与电池折旧**。只报毛价差是欺骗，会在用户对账时崩塌。
2. **必须披露与理论最优的差距**。承认"我还能做得更好"，比声称"已最优"更能赢得长期信任。
3. **宁少报不多报**。首月报告如果比用户的实际感受偏高，用户会永久性地怀疑所有后续数字。

**延伸**（V1 末）：报告里增加一句**合同体检**——"按你家的用能特征，你当前的这份电价合同已经不是最优选择，另一类合同可能更适合你"。这是从"调度工具"走向"能源顾问"的第一步，也是未来的商业机会点。

---

### 4.8 F7 · 异常兜底与接管

**要解决什么**：人和 Agent 交接最怕的是"人工从零开始查"。必须有一个标准交接物。

**能识别的异常**：
- 停电 / 断电 / 并网状态异常
- 电池告警：温度异常、单体温差过大、绝缘告警、SOH 异常下降
- 设备离线：逆变器失联、通信中断
- 数据源失效：电价数据拉不到、预报服务不可用
- 收益异常：连续多日净收益显著低于预期
- 画像漂移：家庭用电模式发生结构性变化

**分级处置**（每一级都规定"谁来处理"）：

| 级别 | 判定 | Agent 动作 | 通知谁 | 时限 |
|---|---|---|---|---|
| **L0 静默** | 小偏差、瞬时抖动 | 静默修正，记日志 | 无 | — |
| **L1 告知** | 收益异常、画像漂移、循环预算过半 | 继续运行，记入日报 | 用户（日报/周报内） | 24 小时内 |
| **L2 请示** | 需触碰备电预留边缘、需超额动用循环预算、电价数据源失效 | **降级为保守模式**，等待确认 | 用户（推送）+ 安装商（后台可见） | 同步 |
| **L3 紧急** | 停电、电池告警、SOC 异常跳变、安全相关 | **立即切安全模式**，停止一切优化 | 用户 + 安装商 + 沃太售后 | 立即 |

**交接物规范：事故简报**。Agent 生成的简报必须包含：

1. **发生了什么**（时间线，人话叙述）
2. **我的判断与依据**（当时的电价、天气、房间状态）
3. **我做了什么**（已执行的处置）
4. **现在的状态**（当前电量、备电可用时长、设备状态）
5. **建议动作**（我建议你怎么做）
6. **需要谁决策**（用户 / 安装商 / 沃太售后）

**为什么这是人机协作的核心**：有了简报，安装商接到客户电话时不必从零排查；沃太售后处理告警时能直接看到上下文。**这个交接物直接决定了本产品是降低还是抬高服务成本。**

---

### 4.9 F8 · 多市场策略包

**要解决什么**：沃太卖到多个国家，每个市场的电力规则都不同。如果每次都改固件，产品永远追不上市场变化。

**产品化思路**：把"市场规则"与"调度逻辑"分离，做成可配置的**市场策略包**。每个策略包定义：

- 电价机制：固定价 / 分时 / 动态（小时级 / 15 分钟级）/ 阶梯
- 电网费机制：是否分时、是否有容量费/需量费、是否有可控负荷减免档位及其代价（是否要接受电网限功率）
- 上网规则：是否允许余电上网、上网费率、是否划算、是否有限制
- 是否有需求响应 / 容量市场机会
- 该市场的补贴与合规约束
- 当地的典型家庭参数与默认红线（例如弱电网地区的默认备电更高）

**业务价值**：上新市场从此是**运营配置工作**，不是研发排期工作。这是沃太相对纯软件方和慢速硬件方的核心速度优势。

**运营要求**：必须有专人（策略运营）持续跟踪各市场的规则变化，并在规则变更时触发"存量用户策略复核"提醒。**这是本产品的隐性成本，立项时必须配人力。**

---

### 4.10 F9 · 主动建议（V2，顾问模式）

**要解决什么**：从"管每天的调度"扩展到"管家庭的能源决策"。

举例：
- 你的电价合同不适合你的用能特征，建议更换类型；
- 你的屋顶还有可加装空间，加装后年度收益预计增加多少；
- 你的热水器时段可以挪到低价时段，不用动电池就能省钱；
- 你这块区域的停电风险上升，建议把备电预留从 6 小时提高到 9 小时；
- 你的电池健康度下降速度高于同期机型，建议检查散热环境。

**边界**：一律只**建议**，不执行、不代签、不承诺。涉及钱和合同的建议必须标注"仅供参考，不构成推荐意见"。

---

### 4.11 Agent 自主边界之外（必须人工的事）

以下事情**Agent 只能建议或准备材料，不能自主执行**：

- 修改备电预留、最低电量红线、循环预算上限（属 L3，见第六章）
- 调整"省钱 / 备电 / 护电池"的权重
- 启用需求响应、参与任何形式的电力市场交易
- 接入新的电价产品 / 变更零售商
- 任何涉及质保承诺、安全参数、并网参数的变更
- 对客户投诉的最终答复
- 影响多个家庭的策略变更（必须人工批准后统一发布）
- 超出既定范围的任何"创新"动作

**为什么要把这条写进 PRD**：Agent 产品的最大风险不是它做得不好，而是它**做了没人授权它做的事**。自主边界必须在文档层面写死。

### 4.12 优先级与迭代节奏

| 阶段 | 交付 | 目标 |
|---|---|---|
| **MVP** | F1（轻量）+ F2 + F4 + F5 + F7（基础） | 单个市场（建议德国）跑通"影子 → 建议 → 自动"完整链路，验证用户是否敢用 |
| **V1** | F3 + F6 + F8 + 画像深化 | 提升收益、接入多市场、把收益证明做扎实 |
| **V2** | F9 + 需求响应联动 | 从调度工具变能源顾问，探索第二收入曲线 |

**关键节奏判断**：MVP 阶段**不追求收益最大化**，追求**"用户敢开通自动模式并留住"**。收益是 V1 的事。

---

## 五、人机协作机制

> 这是本产品的灵魂章节。功能可以被抄，协作机制决定了用户会不会长期留下来。

### 5.1 四条协作原则

1. **人定边界，Agent 在边界内自主。**
   人不参与日常执行。每一次"让用户点一下"都是在消耗他的耐心，必须证明这个点击的必要性。

2. **一切自主决策可解释、可回溯、可推翻。**
   决策日志对用户永久开放。任何一个动作，用户都有权问"为什么"，并且能得到答案。

3. **Agent 只对"钱和舒适"负责，绝不替人做承诺。**
   不签合同、不承诺收益、不改变质保、不代替用户与电网或零售商交涉。

4. **不确定时降级，而不是冒险。**
   宁可少赚，不可失责。任何拿不准的情况，退回安全模式。

### 5.2 权限分级矩阵（核心工具）

把所有的操作分成三级，这是整个协作机制的操作化载体。

| 级别 | 定义 | 具体事项 | 谁决定 |
|---|---|---|---|
| **L1 Agent 自主** | 在已批准的偏好和红线内，Agent 直接执行，事后告知 | 每日充放电时间点的安排与微调；日内小幅修正；数据缺失时切安全模式；生成日报周报；画像的日常更新 | **Agent** |
| **L2 事前确认** | Agent 提出，用户一键确认后执行 | 首次启用某类策略；单次动作需要临时突破常规安排但仍未越过红线；启用新电价产品/接入新零售商；启用一次需求响应奖励；打开"自动执行"模式 | **用户（一键）** |
| **L3 人工专属** | Agent 只能建议和准备材料，不能执行 | 修改备电预留与最低电量红线；调整循环预算上限；修改"省钱/备电/护电池"权重；任何涉及质保、安全参数、并网参数的变更；批量策略调整；客诉答复 | **人（并留痕）** |

**设计检验标准**：
- L1 的事**必须**让用户感觉"我不用管"；
- L2 的事**必须**少到不烦人。如果 L2 每天弹出，产品就是失败的；
- L3 的事**必须**由用户主动发起或每季度一次，绝不能高频打扰。

**留痕要求**：所有 L2、L3 操作都要记录"谁、什么时候、改了什么、为什么"。这是责任边界的证据。

### 5.3 五个关键协作触点

日常之外，人和 Agent 的接触集中在五个时刻。把这五个时刻设计好，整个协作就成立了。

---

#### T1 · 冷启动"三问定调"（目标：10 分钟内完成）

不要求用户填任何技术参数，只问三个问题。

**问 1：你更在意什么？**

用一个"三选配比"的滑块，而不是单选题（因为三个都想要）：

> 下面三件事，你更在意哪个？（拖动配比，拖动后可以随时改）
>
> - 💰 **把电费省下来**（省钱）
> - 🛡️ **停电时不慌**（备电）
> - 🔋 **电池用得久一点**（护电池）
>
> 默认配比：省钱 40% / 备电 40% / 护电池 20%

**问 2：停电时，你最需要保证什么？**

用生活语言问，而不是问 SOC 百分比：

> 如果停电了，下面这些设备你希望至少能撑多久？
> - 冰箱 + 照明 + 网络（基础）：☐ 4 小时　☐ 8 小时　☐ 12 小时
> - 还有别的必须保证的设备吗？（如医疗设备、居家办公、鱼缸加热）

**用户不填 SOC，Agent 自己换算成 SOC 预留值。**"备电预留比例"这个词永远不出现在用户界面。

**问 3：你希望我多主动？**

> - 🌱 **只给我建议**，我自己决定要不要按（最保守）
> - ⚡ **帮我自动执行**，但每次都告诉我（推荐）
> - 🤖 **帮我自动执行**，有异常再找我（最省心）

**设计要点**：
- 三问必须在**一屏内**完成，不能有"下一步"的层层跳转。
- 所有默认值都要**保守**，面向"省心型"用户。
- 允许"以后再说"，未回答的部分用最保守默认值。
- **第一次打开不要求用户授权自动执行**，先进入影子期。

---

#### T2 · 影子期（建议 2–4 周）：把黑盒变白盒

**这是本产品最重要的信任机制，务必单独讲清。**

**做法**：Agent 在影子期**只出计划、不执行**。每天照常推送"如果按我说的做，今天会怎样"，然后第二天给出一句对照：

> **昨天我的建议 vs 实际情况**
> 我建议凌晨 1:00–3:20 充电，预计省 €1.86。
> 你昨天没按我的来，实际多花了 €0.94。
> （如果你昨天有自己的考虑，告诉我，我会记住 —— 也可能是我没考虑到你的情况。）

**三个作用**：
1. **零风险验证**。用户不花任何代价就看完了 Agent 的能力，**没有理由拒绝**。
2. **画像校准**。两周的真实对照，画像准确度大幅提升。
3. **信任建立**。用户亲眼看到"它算得对"，才愿意把电池交出去。

**设计要点**：
- 影子期必须**明确告知用户这是试用期**，并给出结束日期和"什么时候可以开始自动"。
- 影子期结束时，给用户一份**影子期小结**：如果一直按建议做，这两周会省多少。
- **不制造焦虑**。避免"你就这样浪费了两周"这种话术，改成"接下来我可以帮你把这些省下来"。
- 影子期可以**主动跳过**（用户直接选了"自动执行"），但不能**自动跳过**。

---

#### T3 · 计划审批与"锁单"

- **推送时机**：本地时间每天傍晚（例如 17:30–18:30 之间，因人而异，可配置），推送**次日计划**。
  - 为什么是傍晚：电价曲线通常已确定，家庭也方便看一眼，不打扰睡眠。
  - **禁止深夜推送非紧急通知**（如 23:00–07:00）。
- **三种响应**：接受 / 我要调整 / 明天按老办法来。
- **默认可自动接受**：若用户已授权"自动执行"，计划**默认自动生效**，推送只是告知；用户可在生效前撤销。
- **锁单**：用户可锁定某一天或某段时间（如"假期期间别动"）。锁定期间 Agent 只在安全原因下覆盖，且必须告知。
- **调整的粒度必须简单**：只提供"更省钱一点 / 更保险一点 / 保持备电更多"这类方向性调整，**不暴露参数**。深水区用户可以在设置里展开参数，但默认折叠。

---

#### T4 · 异常接管

**触发**：见 F7 的分级表。

**协作流程**：
1. Agent 按级别自动处置（降级、切安全模式）；
2. 生成"事故简报"；
3. 按级别通知：用户 / 安装商 / 沃太售后；
4. **人工处理**：用户可能只需要知道；安装商可能需要远程诊断；沃太售后可能需要排障；
5. **闭环回写**：处理后要回答一个问题——**这是"这一次"的问题，还是"这一类"的问题？**
   - 如果是个案 → 记录，不改进规则；
   - 如果是系统性缺陷 → **升级为规则变更任务**，由人工确认后进入策略包的更新，对所有相关用户生效。

**设计要点**：
- 通知必须**分级**。用户收到的紧急通知一年不超过几次，才能保持可信度。
- **Agent 在人工接管期间必须"闭嘴"**：不得继续执行优化动作，避免与人工操作打架。
- 人工处理完成后，Agent 要**主动汇报"我已经恢复了，接下来我会这样做"**，让用户知道事情结束了。

---

#### T5 · 季度策略复核（30 分钟，人造法、Agent 执行的制度化节拍）

**为什么必须有**：家庭在变、电价机制在变、电池在老化。一套固定参数用一年，必然失效。**但用户不会自己回来改。**

**形式**：App 内的"季度复盘向导"（或由安装商/沃太客服远程陪同完成）。

**内容（五问）**：
1. **本季收益复盘**：实际净收益、与上一季对比、与理论最优的差距、钱省在哪。
2. **循环预算消耗**：本季用了多少循环预算、剩余多少、按当前用法电池预计能用多久。
3. **备电体检**：本季有没有停电、备电是否够用、是否需要提高预留。
4. **合同体检**：当前电价合同是否仍是好选择、市场规则有无变化。
5. **偏好复核**：省钱/备电/护电池的配比是否要调整、有没有新的家庭变化（买电动车、添了孩子、装了热泵）。

**产出**：一份**新版偏好与红线**，用户确认后生效，并**明确告知与上一版的差异**（"这次你主要改了什么，我会怎么变"）。

**重要性**：这是"人做立法者"这个定位的唯一制度化落地。**没有季度复核，产品就会退化成另一个"设完就忘"的手动模式。**

### 5.4 升级与接管协议（Agent 何时开口）

| 场景 | Agent 的行为 |
|---|---|
| 常规充放电、计划内动作 | **沉默**（只在日报里提） |
| 预测小偏差、已在阈值内的修正 | **沉默**（记日志） |
| 单日收益明显低于预期、画像被显著修正、循环预算过半 | **低优先告知**（日报/周报内，不推送） |
| 触碰备电预留边缘、需超额用循环预算、电价数据源失效 | **必须请示**：降级 + 推送，等用户确认 |
| 停电、电池告警、SOC 异常跳变 | **立即叫人**：切安全模式 + 多通道通知 |
| 用户明确提出要求（无论是否合理） | **立即响应**：先执行用户意愿（在安全边界内），再解释风险 |
| Agent 自己不确定 | **声明不确定**，采用保守策略，并告知用户 |

**一条容易忽略的规则**：当用户明确要求某事、而 Agent 认为不明智时，**Agent 应当先照做（只要不越过安全红线），然后把风险和理由讲清楚**。用户有最终决定权——这不是技术妥协，是产品立场。**如果 Agent 会拒绝主人，用户就不会把它当自己的管家。**

### 5.5 解释与信任的机制化设计

信任不能靠文案，要靠机制。以下是必须落实的机制：

| 机制 | 作用 |
|---|---|
| **每一次动作都能回答"为什么"** | 消除黑盒感 |
| **主动披露放弃的机会** | 消除"它是不是漏了"的怀疑 |
| **不确定时明说，给区间不给假精度** | 避免事后被指"你当时说得那么肯定" |
| **允许说"我不知道"** | 编造理由是最严重的信任事故 |
| **推翻时问"例外还是规则"** | 避免越学越偏 |
| **决策日志永久可查、可导出** | 用户和安装商都能事后对账 |
| **收益按净额口径报告（扣效率损失与折旧）** | 对账时不会崩 |
| **季度复盘主动找用户** | 不让"设完就忘"发生 |
| **第一年以保守优先，不追求收益极限** | 用确定性换信任 |

**反指标提醒**：在这个产品里，**"用户打开 App 的频率下降"是好事，不是坏事**。核心体验指标不应是活跃度，而应是"用户不需要打开 App 却过得更好"。这与大多数互联网产品的直觉相反，必须在立项时就统一认知，否则会被错误的KPI带偏。

### 5.6 协作节奏日历

| 频率 | 交互 | 谁发起 | 是否推送 |
|---|---|---|---|
| **每日** | 次日计划（傍晚推送）；当日执行结果（次日早晨简讯，可关闭） | Agent | 是（可关） |
| **每周** | 周报（收益、异常、画像变化） | Agent | 否，App 内可查 |
| **每月** | 账单对照报告（四栏对照 + 归因 + 合同体检） | Agent | 邮件/App，一次 |
| **每季** | 策略复核向导（T5） | Agent 发起 + 人参与 | 是，需用户安排时间 |
| **随时** | 异常接管（T4）；用户主动查看与质疑 | 双方 | 按级别 |
| **事件驱动** | 市场规则变更、电价合同到期、设备告警 | Agent | 按级别 |

### 5.7 反面清单：Agent 明确不该做的事

这份清单同样重要，它约束产品的"热心程度"：

1. **不为了小额价差频繁循环电池**。收益门槛必须存在。
2. **不擅自突破备电预留**。这是不可协商项。
3. **不在用户未授权时切换模式**。
4. **不用专业术语轰炸用户**。界面上不出现 SOC、DoD、kW/kWh 裸数值（除非用户主动展开深水区）。
5. **不在深夜推送非紧急通知**。
6. **不承诺收益数字**，不用"保证省 XX 元"的表述。
7. **不绕过电网运营商的限制**，不做当地不允许的并网行为。
8. **不在数据缺失时凭猜测运行**，一律降级到安全模式。
9. **不把用户的一次临时操作当成永久偏好**（必须问"例外还是规则"）。
10. **不在人工接管期间继续自主行动**。
11. **不做超出授权范围的"聪明事"**。哪怕逻辑上更优，没授权就不做。
12. **不在用户放弃套利选择保守时表达不满或反复劝说**。用户选了就执行。

## 六、关键业务规则

### 6.1 三角权衡：什么时候才该动手

**核心判据（用业务语言表达）**：

> 一次套利动作只有在 **预期净收益 > 电池折旧成本 + 备电保险价值** 时才值得做。

三项的构成：

| 项 | 内容 | 谁决定 |
|---|---|---|
| **预期净收益** | （高价时段放电单价 − 低价时段充电单价）× 电量 × 往返效率 − 网费与税费影响 | 算法算，市场定 |
| **电池折旧成本** | 本次动作消耗的等效满循环 × 每循环折算成本 | 电池参数 + 用户风险偏好 |
| **备电保险价值** | 本次动作占用的备用电量的机会价值，与停电风险正相关 | 用户偏好 + 区域停电历史 |

**关键洞察**：**备电保险价值不是常数，它随天气、季节、区域电网状况浮动。** 台风季、极端高温、电网检修期的保险价值明显更高。所以"雨季/灾害季自动提高备电预留"应当是一个默认开启的机制，而不是等用户想起来的设置项。

**一个具体的示例算例**（数字为示意，需实测标定）：

- 峰谷价差 €0.25/kWh，往返效率 90% → 每放电 1 kWh 的毛收益 ≈ €0.225
- 减去电池折旧（示例 €0.06/kWh）
- 减去网费/税费影响（示例 €0.02/kWh）
- 净收益 ≈ **€0.145/kWh**

→ 因此收益门槛建议设在 **€0.15/kWh 价差** 附近。**低于这个门槛的"机会"，Agent 应当主动放弃并向用户说明。**

### 6.2 收益计算口径（对外必须一致）

```
净收益 = 光伏自用节省
       + 低价充电节省
       + 高价放电节省
       + 电网费规避（网费减免 / 避免容量费）
       − 往返效率损失
       − 电池循环折旧
       − 税费与上网费用影响
```

**与谁比**：必须明确基线，且至少给出两个对照——"出厂默认策略"（衡量产品增量价值）和"什么都不做"（衡量整体价值）。

**对外披露纪律**：
- 不得单独宣传毛价差；
- 不得使用"最高可省"这类上限表述作为主口径；
- 必须同时披露"与理论最优的差距"。

### 6.3 循环预算的记账方式

**为什么要记账**：电池的寿命是用循环消耗的。套利本质上是在**用电池寿命换电费**。如果不记账，用户省下的电费可能不够覆盖电池提前衰减的损失——那这个产品就是在坑客户，也会引发质保争议。

**记账规则（业务描述）**：
1. 把每一次充放动作按其深度折算成**等效满循环**（放掉 30% 电量记为 0.3 个等效循环）。
2. 分**月度预算**和**年度预算**两层。
3. 预算的默认值来自电池的循环寿命参数与用户选择的"护电池"强度。
4. **每个动作执行前先查预算余额**：余额不足则不执行，并向用户说明"这个月为了护电池，我不建议再做额外套利了"。
5. **预算消耗过半时提前告知用户**，让用户有心理准备，而不是月底突然降级。
6. **预算可被用户临时突破**，但必须走 L2 确认流程，且明确告知对电池寿命的影响。
7. **质保口径预留**：记账数据必须可作为质保争议的证据（记录温度、深度、次数）。

### 6.4 弃权清单：什么情况下宁可放弃套利

以下情形，Agent 应当**主动放弃套利**并说明原因：

1. 预期净收益低于收益门槛；
2. 动作会触碰或逼近备电预留；
3. 电池处于不利温度区间，或近期健康度下降异常；
4. 电价与电网费信号方向相反（省了电价但多付了网费，净亏）；
5. 当地不允许或极不划算的上网行为；
6. 电网发出限功率或需求响应指令；
7. 预报不确定性过高（例如极端天气、光伏预报置信度低）；
8. **用户临时外出但家中留有需要供电的设备**（医疗设备、宠物、安防）；
9. 循环预算余额不足；
10. 用户已"锁单"当天计划。

**产品要求**：以上每一条弃权都要在计划表中**以人话说明**。弃权不是沉默，弃权是必须解释的动作。

## 七、预期业务价值

### 7.1 用户价值

| 价值 | 说明 | 可验证方式 |
|---|---|---|
| **电费下降** | 在动态电价市场，自动化调度相较出厂固定策略通常能带来明显的年度购电成本下降（具体幅度需在目标市场实测标定，见附录 B） | 月度四栏对照报告 |
| **停电不慌** | 备电可用性从"靠运气"变成"有保障"，且以"够用几小时"的方式被用户理解和掌控 | 停电事件复盘；备电失守次数为 0 |
| **电池用得更久** | 循环预算机制挡掉不合格的循环，抑制无效衰减，同时保留完整的循环记录 | 循环记账、SOH 趋势对比 |
| **认知负担归零** | 从"每天研究电价、设置时段"变成"每季度花 30 分钟复核一次" | 用户操作频次、自评省心度 |
| **透明度与掌控感** | 每一步都能问"为什么"，随时能推翻、能锁单、能收回自动权 | 推翻率、自动模式留存率 |

### 7.2 沃太价值（核心）

1. **从一次性硬件收入，转向持续性服务收入。**
   硬件毛利被价格战压缩的背景下，软件与能源服务是可持续的增量。一个已经装在用户家里的电池，是一个可以持续交付价值并持续收费的载体。

2. **智能调度成为可感知的差异化卖点。**
   "同样的硬件，我们的电池每年帮你多省一笔钱"——这是一句可以在经销商展厅里讲清楚、并且能被月度报告验证的话。**可验证的省钱承诺，比参数表更有说服力。**

3. **新市场进入速度提升。**
   市场策略包机制使得进入一个新电价市场从"改固件、等版本"变成"配置策略包、灰度上线"，显著缩短从市场机会到收入的时间。

4. **售后与渠道服务成本下降。**
   安装商不再充当人工调度员；客服有事故简报可看，不必从零排查；客户投诉"为什么半夜充电"这类问题，产品本身就在解释。**这是直接的毛利改善项。**

5. **渠道赋能，反过来促进硬件销售。**
   安装商得到一个"能证明省钱、能自动运行、出问题有据可查"的产品。它降低了安装商的销售难度与售后负担，是渠道愿意主推的理由。

6. **虚拟电厂与需求响应的入场券。**
   参与聚合交易和电网服务，前提是：有可信的调度能力、有家庭侧的可调节容量、**有用户已经授予的自主权等级**。本产品生产的就是这三样东西。这是第二增长曲线的基础设施——**今天做管家，是为了明天能做聚合。**

7. **数据资产。**
   跨市场的家庭用能画像、调度效果数据、电价响应弹性——这些是产品迭代、电价产品设计、以及与零售商/电网合作谈判的筹码。**前提是严格合规与脱敏。**

8. **竞品难以复制的组合位置。**
   纯软件方拿不到电池底层健康数据，零售商只服务自家客户，硬件同行缺少做深算法的意愿。沃太同时具备**自有硬件数据闭环 + 多市场渠道 + 调度能力**。

### 7.3 安装商 / 渠道价值

- **减少上门与远程支持**：事故简报 + 决策日志让远程支持有据可依。
- **增加增值服务点**：可以从"卖设备"延伸到"帮客户做季度策略复核"，形成持续的服务关系与收入点。
- **提升客户粘性**：一个每月给客户省钱的系统，比一个只显示数据的系统更难被替换。
- **降低投诉率**："为什么半夜充电"这个问题，产品自己会回答。

### 7.4 电网与社会价值（长期筹码）

- 削峰填谷，缓解晚高峰负荷压力；
- 提高光伏自消纳率，减少弃光；
- 在获得授权与资质的前提下，提供可调节容量参与电网服务。

**战略含义**：这些价值让沃太在与零售商、电网公司、聚合商的合作谈判中有可量化的筹码，而不只是一个设备供应商。

### 7.5 价值测算框架（示例，需实测标定）

不要用一个总额数字去承诺价值，而要提供**可复算的框架**：

| 变量 | 示例取值（假设） | 敏感性 |
|---|---|---|
| 家庭年用电量 | 4,500 kWh | 高 |
| 光伏装机 | 8 kWp | 高 |
| 电池容量 | 10 kWh | 高 |
| 峰谷价差（日内平均） | €0.15–0.30/kWh | **最高** |
| 年度可套利电量 | 约 1,500–2,000 kWh（受循环预算限制） | 高 |
| 往返效率损失 | 约 10% | 中 |
| 电池循环折旧 | 示例 €0.05–0.10/kWh | 高 |
| 备电预留 | 用户偏好决定，通常消耗 20–40% 的可用容量 | 高 |

**结论性框架**：净收益 ≈ 可套利电量 × （价差 × 效率 − 折旧 − 网费影响）×（1 − 备电预留折价）。

**这份框架的作用**：把一个笼统的"能省钱"变成一张可以让用户自己填参数、自己看敏感性的表。**在动态电价市场，诚实展示敏感性比给一个漂亮数字更能建立长期信任。** 所有对外数字必须标注假设条件。

### 7.6 风险与反向价值（必须正视）

| 风险 | 后果 | 应对 |
|---|---|---|
| **电池提前衰减** | 省的电费不够换电池，品牌灾难 | 循环预算硬约束 + 折旧计入收益口径 + 温度保护 |
| **解释不清导致用户关掉功能** | 投入无法兑现，退化回出厂策略 | 影子期 + 主动披露放弃项 + 季度复盘 |
| **一次备电失守** | 单个用户的口碑事故，且可能引发索赔 | 备电预留为硬约束，任何优化不可侵占 |
| **收益不及用户预期** | 首月报告被质疑，信任崩塌 | 净额口径、宁少报不多报、披露与最优的差距 |
| **市场规则变化快，跟不上** | 策略失效，收益转负 | 必须配置专职策略运营；规则变更触发存量复核 |
| **电价数据源被限制或收费** | 核心输入失效 | 多源备份 + 用户手动导入兜底 + 数据失效时降级安全模式 |
| **责任边界不清** | 出事后三方推诿，用户只找沃太 | 第九章的责任矩阵必须前置定义并写入用户协议 |
| **定价不被接受** | 用户不愿为"本来以为该免费"的功能付费 | 首年随硬件赠送/订阅捆绑，第二年再验证订阅意愿 |

## 八、成功度量与验证计划

### 8.1 北极星指标

**北极星**：**自动模式下、每户每月的可验证净收益**（口径见 6.2，需扣除效率损失与电池折旧）。

**为什么选它**：它是唯一同时覆盖"用户得利"和"沃太得利"的指标。收益上不去，用户不会留；收益不能验证，用户不会信。

**配套的反指标（护栏指标）**，任何一项破线，产品不得扩大推广：

| 护栏指标 | 目标 | 破线含义 |
|---|---|---|
| 备电失守次数 | **0** | 产品定位崩塌，立即停止推广 |
| 循环预算超支率 | **0** | 护电池承诺失效 |
| 用户推翻率（稳定期） | < 5% | 决策质量或偏好理解有问题 |
| 自动模式 90 日留存率 | ≥ 70% | 信任未建立 |
| 因调度问题的客诉率 | 不高于基线 | 没降低服务成本，商业逻辑不成立 |
| 收益报告与实际账单偏差 | < 3% | 口径不可信，最危险的一类问题 |

### 8.2 分角色指标体系

| 角色 | 关注指标 |
|---|---|
| **用户** | 月均净收益、与出厂策略的差额、备电可用时长达成率、自动模式留存、省心度自评（NPS） |
| **渠道（安装商）** | 因调度产生的工单量、远程支持时长、客户满意度、是否愿意主动推荐 |
| **沃太业务** | 智能功能激活率与留存率、订阅转化率、单用户服务成本、新市场从配置到上线的时间、可用调节容量储备 |
| **产品健康** | 解释页打开率、推翻后"例外 vs 规则"正确分流率、数据源可用率、降级次数与原因分布 |

**特别提醒**：**不要用 App 打开率作为核心指标。** 本产品的成功意味着用户**更少**打开 App。激活率、留存率、净收益、备电达成率才是对的；日活是错的。

### 8.3 验证路线：四步走，每步有明确出口条件

| 阶段 | 形态 | 用户感受 | 出口条件 |
|---|---|---|---|
| **① 影子模式** | 只出计划，不执行 | "它给我看，我自己按" | 建议准确率达标；用户查看率与互动率达标 |
| **② 建议模式** | 出计划，用户一键确认执行 | "它说，我点头" | 确认率达标、推翻原因可归类、无安全事件 |
| **③ 自动模式** | 护栏内自主执行，事后告知 | "它做，偶尔告诉我" | 净收益达标、留存达标、推翻率达标、备电失守为 0 |
| **④ 自动 + 需求响应** | 在授权范围内参与电网服务 | "它连电网的事也管了" | 资质、合作伙伴、责任边界全部落定 |

**灰度分层**：按市场（先德国）→ 按电价零售商 → 按硬件型号 → 按用户类型（先"省钱型"先锋用户，再"省心型"主流用户）逐步放开。

**为什么先先锋用户**：他们愿意容忍瑕疵、会给出高质量反馈、并且是口碑的源头。**但主流用户的默认值必须比先锋版更保守**，两套默认值要分开设计。

## 九、风险、合规与责任边界

### 9.1 责任矩阵（必须在项目启动前定稿）

| 情形 | 责任归属 | 依据与前提 |
|---|---|---|
| Agent 在用户授权范围内的正常自主决策造成的收益偏差 | **沃太承担服务责任**，但不承担收益承诺 | 用户协议需明确"不保证收益" |
| 用户主动覆盖或突破 Agent 建议造成的后果 | 用户知情同意，**留痕** | L2/L3 操作留痕机制 |
| 设备故障、电池告警、硬件质量问题 | **沃太硬件质保责任** | 既有质保体系 |
| 电价/天气等第三方数据错误导致的决策失误 | 数据供应方责任；**沃太需证明已有多源校验与降级策略** | 数据失效必须降级，不得凭猜测运行 |
| 用户按不符当地规则的方式使用（如违规上网） | 沃太需在配置层面阻止 | 市场策略包内置合规约束 |
| 参与电力市场交易/需求响应 | **须另行取得资质或通过持牌合作伙伴**，本期不做 | 4.12 与 1.6 的边界 |
| 停电时备电不足引发损失 | **视情形**：若因 Agent 占用备电导致，沃太承担；若因设备故障或极端情形，按质保条款 | **所以备电预留必须做成不可侵占的硬约束** |

### 9.2 合规要点

- **电力市场资质**：家庭侧自用优化与"对外售电/参与市场交易"是两件事。后者通常需要成为市场参与者或通过聚合商/持牌方，**本期严格限定在前者**。
- **电网接入规则**：各市场的并网、限功率、防逆流、可控负荷要求（如德国针对可控负荷的电网费减免机制、各国并网标准）必须内置在策略包中，**由系统强制，不可被 Agent 绕过**。
- **电池法规与循环数据**：欧盟电池法规对碳足迹、电池护照、循环数据与可追溯性有要求。本产品的循环记账数据**可以成为合规资产**，设计时应保证数据完整性与可导出性。
- **数据隐私**：家庭用能曲线可以推断出"家里有没有人""作息习惯"，属于敏感信息。必须做到：明确授权、最小必要、可撤回、可删除、区域存储合规、脱敏后再用于分析。
- **消费者保护**：不得在营销中使用收益承诺；收益报告的假设条件必须随报告一同呈现；用户必须能随时关闭自动化并收回授权。

### 9.3 安全与售后风险

- 所有安全相关参数（电压、保护阈值、并网参数）**完全在 Agent 的作用范围之外**；
- 电池告警一律优先于经济性优化；
- 数据源失效、通信中断时必须降级，**不允许"最后已知值"继续驱动调度**；
- 任何自动调度都必须提供一个"一键停止并回到出厂策略"的开关，且该开关必须在 App 首页可达。

### 9.4 回退设计

- **一键回退**：用户随时可退回到出厂策略，且回退**不影响**历史数据与收益记录；
- **自动降级**：护栏触发、数据失效、异常告警时自动回退到安全默认，并告知用户；
- **全局熔断**：当某市场出现系统性异常（如策略包缺陷导致多户收益转负），必须支持**远程一键停用该市场的自动调度**，并通知所有受影响用户。**这个开关的存在本身就是产品成熟度的标志。**

## 十、上线与运营计划

### 10.1 分市场节奏

| 顺序 | 市场类型 | 理由 | 产品形态 |
|---|---|---|---|
| 1 | **德国（首选）** | 动态电价合同成熟、户储保有量大、电网费机制复杂（正好体现"双信号融合"的价值） | 完整版 |
| 2 | 英国、澳洲 | 动态电价与需求响应机制成熟；澳洲家庭对电池套利认知高 | 完整版 + 需求响应预留 |
| 3 | 意大利、荷兰、北欧 | 电价波动结构不同，验证策略包机制的可移植性 | 完整版 |
| 4 | 南非等弱电网市场 | 停电是常态，备电优先级高于套利 | **简化版：备电优先 + 有限套利** |
| 5 | 中国市场 | 以分时电价为主、缺乏零售侧动态电价 | **简化版：分时套利 + 备电 + 护电池** |

**关键判断**：不要把德国版的默认值直接搬到弱电网市场。**南非用户的默认备电预留应当显著高于德国用户**——这类本地化默认值必须写进市场策略包。

### 10.2 组织与角色（本产品的隐性成本）

| 角色 | 职责 | 为什么必须有 |
|---|---|---|
| **产品负责人** | 定义偏好模型、护栏默认值、协作机制 | 决定产品立场 |
| **策略运营（新岗位）** | 跟踪各市场电力规则变化，维护市场策略包，触发存量用户复核 | **没有这个角色，产品半年后就失效** |
| **护栏复核人** | 季度复核的陪跑、异常裁决、L2/L3 申请的审批、规则变更把关 | 保证"人仍立法" |
| **客服/售后支持** | 按事故简报处置，维护话术，反馈系统性问题 | 人机交接的落地端 |
| **渠道赋能** | 培训安装商使用客户管家视图与季度复核流程 | 渠道是推广放大器 |
| **法务/合规** | 责任边界、用户协议、数据合规、市场资质 | 前置而非事后 |

### 10.3 关键 SOP 与话术要求

1. **事故简报模板**：六要素固定格式（见 F7），所有人看同一套。
2. **客诉话术**："为什么半夜充电"必须有标准解释路径——先给当日电价曲线，再给收益对照，最后给出"你也可以改成备电优先"的选项。
3. **季度复核向导脚本**：五问固定，产出固定，差异对比固定。
4. **策略包发布流程**：任何影响多户的规则变更，必须经护栏复核人批准 + 灰度 + 回滚预案。
5. **收益口径文档**：对外一律使用同一套净收益口径，营销、客服、报告三处一致。
